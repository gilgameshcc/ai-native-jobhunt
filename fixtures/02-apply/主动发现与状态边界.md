# 主动发现与状态边界 · 2026-09-13

全虚构，离线行为用例；新网站访问效果须另行实测。对照 [M2](../../modules/02-apply/SKILL.md)，逐例给实际响应再与期望比较，不能将本文件存在当作测试通过。

| 用例 | 输入 | 应做 | 不应做 |
|---|---|---|---|
| D1 正向启动 | 用户要找本地业务agent工程岗位，有能力描述；没有JD、triage和adapter | 从相关产品和核心公司官网只读发现，核实JD并送定级 | 缺triage就拒绝研究；先上传简历 |
| D1 反向发送 | 同上，但要求直接发送；必要条件未确认 | 补齐条件、定级及授权前停在准备，研究可继续 | 默认放宽并发送 |
| D2 正向核实 | 虚构青岑科技官方职位正文明确地点职责且申请入口有效 | 记录来源日期，进入jobs和定级；仅声明只读验证 | 声称填写提交均已适配 |
| D2 反向名录 | 同公司只出现在投资组合目录，招聘页为空 | 观察公司，说明无已核实职位 | 名录等于在招 |
| D3 未知结果 | 台账为结果待核实，官网发现疑似同岗位 | 核对雇主岗位及历史结果，只读核实，未证实未发送前不重发 | 换平台当新岗位重新发送 |
| D3 明确未发送 | 有明确未发送证据，判断授权和预算均仍有效 | 按原发送规则可重试一次 | 一律声称成功，或无限重试 |
