# 样例 · 用 `interview-strategic-assessment` 评估一家虚构公司

> ⚠️ **本文所有内容均为虚构**。公司、产品、案例、人员构成、材料出处全部是为演示编造的，不对应任何真实公司或个人，也不摘录任何真实素材。
>
> **它演示的是**：[`modules/03-company-analysis/interview-strategic-assessment/SKILL.md`](../modules/03-company-analysis/interview-strategic-assessment/SKILL.md) 从输入到产出的完整一遍。每一节标出了对应 SKILL 的哪一步。
>
> **怎么读**：先看 §0 输入 → §1 到 §3 是过程（四框架 → 五法 → 提问设计）→ §4 是产出的评估报告 → §5 是产出的一页纸。**过程比结论重要**——你换一家公司，结论全变，过程一样。

## 1. 第一步：四框架审视（对应 SKILL §2）

### 1.0 先过红线：投资人版 → 候选人版改写（SKILL §2.0）

**这一步在四个框架之前做，它决定了哪些维度根本不进表。**

| 原始（投资人版） | 处理 | 落地成什么 |
|---|---|---|
| 现金还能撑多久 / 什么时候要下一笔钱 | ❌ **删**，改写 | 观察公开招聘页的岗位数与构成；面试问"未来一年团队规模的计划" |
| 收入规模与增速 | ❌ **删**，改写 | 问"增长主要来自新客户还是老客户扩容" |
| 最大客户占收入多少 | ❌ **删**，改写 | 问"如果最大的那个客户明年不续约，计划是什么" |
| A 轮估值 / 稀释情况 | ❌ **删，不改写** | 与我相关的那部分（行权价、行权期、离职后行权窗口）是 offer 条款，属于 [`05-offer`](../modules/05-offer/)，不在这里问 |
| 毛利率 | ❌ **删**，改写 | 问"每服务一个新客户，交付和调优大概要投入多少人力、多久上线" |
| 联创的真实分量 | ⚠️ **改写方法** | 只看公开的职务与业务变动，不挖个人信息。⚠️ 但 founder-market fit **不进疑点表**——它是观察角度不是判据（SKILL §2.1 A4） |
| 董事会构成 / 投资人是谁 | ❌ **删，不改写** | 公开报道里看到就看到了，但它不产生任何我能问、能验、能据以决策的东西 → **不进疑点表**，也不留"以后想办法查"的空格子（SKILL §2.0） |

⚠️ **这张表是这份评估里最容易被跳过、跳过了后果最严重的一步。** 上面六条如果原样留在清单里，会占掉将近一半的提问预算，而对方一条都答不了。

### 1.1 公开材料盘点（`公开可查`）

| 观察 | 来源 |
|---|---|
| 官网首页主叙事是"企业文档智能中枢" | 官网 |
| 客户案例页有六个 logo，其中三个有详细页；详细页里两个写的是"试点/验证"，一个写"已接入日常流程" | 官网案例页 |
| 招聘页现在挂着十来个岗位：交付/实施顾问占了一半以上，销售两个，研发三个 | 官网招聘页 |
| 产品更新日志最近一次更新是四个月前 | 产品文档站 |
| 公开报道提到已完成 A 轮，服务金融与制造行业客户 | 公开报道 |
| 定价页没有公开价格，写"联系我们"；某个案例页里出现"按处理量计费"的表述 | 官网 |
| 官网写"用得越多越准" | 官网 |
| 创始团队公开背景：一位是文档处理/信息抽取方向的技术背景，另一位是企业软件销售背景 | 公开报道 |
| 案例页里最突出的那个客户，在公开报道里同时出现在另外两家同类公司的案例中 | 公开报道交叉检索 |

### 1.2 框架 A · 真需求

- **A1 真需求还是尝鲜性采购** → ⚠️ 有疑点。三个详细案例里两个停在"试点/验证"，没有一个说得出用了多久、哪个部门每天在用。而首页叙事已经在讲"中枢"。
- **A2 增速与结构** → ⚠️ 有疑点。产品更新日志停更四个月；在招岗位里研发占比很低。⚠️ **招聘构成受 SKILL §2.0.1 约束（观察角度不是判据）**，所以这条**必须交叉才算数**：本次它与"更新日志停更四个月"方向一致（都指向工程投入不强），推论才保留；如果更新日志是每周一更，这条推论就该作废。
- **A3 这门生意的钱从谁口袋里来、什么时候来** → ⚠️ 不明。定价不公开，只有一处提到"按处理量计费"。
- **A4 人和事对不对得上** → ⚠️ **只作观察角度，不进疑点表**（SKILL §2.1 A4）。公开职务看得出是"技术背景 + 企业销售背景"的组合，但 founder-market fit 与公司成败之间没有可靠因果证据，事后总能讲通（光环效应）。**既不据此加分也不据此扣分。** 这里只记一句备查：没有一个人有目标垂直行业的深度背景——如果别的框架（例如 C3 滩头阵地）已经指出疑点，这条可以作为补充说明附在旁边。

### 1.3 框架 B · 可持续性

- **B1 数量级领先？** → 待问。公开材料说不清楚。
- **B2 为什么是现在** → 待问。
- **B5 分销** → **待问**。⛔ 原先写的"在招销售 = 已在建可复制的销售动作"**已删**：招销售既可能说明销售动作可复制，也可能说明创始人卖不动了，**同一观察两解，不构成判据**（SKILL §2.2 B5）。改成问事件：*"最近成的那一单，是怎么找到你们的？"* → 转为 **F7**。
- **B6 三年后别人复制要多久** → 待问（这是个好问题，技术负责人愿意答）。
- **B4 团队 / B7 秘密** → 转为问题。

### 1.4 框架 C · 阶段

- **C1 标杆客户是尝鲜者还是早期主流** → ⚠️ **强疑点**。案例呈现的全是尝鲜者特征（内部有人推动、买的是"未来"、没有 SLA/合规相关表述），而对外叙事已经在讲行业标准。
- **C2 完整产品还缺什么** → 待问。
- **C3 有没有打穿一个滩头阵地** → ⚠️ 有疑点。公开报道同时提金融与制造两个方向，案例也横跨多个行业。

### 1.5 ⭐ 框架 D · AI 时代风险透镜

**先过启用判据**（SKILL §2.4）：这家的产品核心能力（文档解析、字段抽取、摘要）**直接依赖大模型** → **框架 D 必答**。

- **D1 模型上移 / 薄封装** → ⚠️ **强疑点**。官网强调"自研模型 + 行业知识沉淀"，但产品文档里能看到的能力（文档解析、字段抽取、摘要），与通用基座模型现成的文档理解能力高度重叠。**它自己的部分到底是什么，公开材料看不出来。**
- **D2 效果付费** → 🟢 不适用。没有任何材料显示按效果收费，**不硬套**（SKILL §10 L2：不适用就说明理由并跳过）。
- **D3 成本通缩挤压** → ⚠️ 有疑点。"按处理量计费"这条线，单位成本随基座下降时，收入会一起降。
- **D4 数据飞轮真伪** → ⚠️ **强疑点**。官网写"用得越多越准"，但三个必要条件（合同许可 / 回流路径 / 谁在标注）一条都看不到机制。
- **D5 组织形态是否被当成产品** → ⚠️ **有疑点**。在招岗位里交付/实施占一半以上，研发只有三个，**这个构成更像一家在做项目交付的公司**，而 JD 把这个岗位写成产品工程方向。⚠️ **但这是观察角度不是判据**（SKILL §2.0.1）：本次已与"产品更新日志停更四个月"交叉，方向一致所以推论保留；即便如此，**观察标 `公开可查`、推论仍标 `我推测的`**，最终要靠 T2 当面问掉。

### 1.6 疑点合并去重（SKILL §2.5）

**合并同源，被多个框架同时指到的排最前。**

| # | 疑点 | 来自框架 | 被几个框架指到 |
|---|---|---|---|
| **Q1** | 案例全是尝鲜者/试点，但对外叙事已经在讲行业标准与"中枢" | A1 + C1 | **2** |
| **Q2** | 招聘构成里交付/实施占一半以上、研发极少，而这个岗位被写成产品工程方向 | C2 + D5 | **2** |
| **Q3** | "自研模型 + 行业沉淀"与通用基座的文档理解能力高度重叠，自己的部分说不清 | D1 | 1（但影响最大） |
| **Q4** | "用得越多越准"没有任何机制支撑 | D4 | 1 |
| **Q5** | 同时讲金融与制造两个方向，看不出滩头阵地 | C3 | 1 |
| **Q6** | 中间人说岗位"新设"，JD 写"接手并优化现有系统"——口径不一致 | 业务澄清 | 1 |
| **Q7** | 按处理量计费遇上成本通缩 | D3 | 1 |
| **Q8** | 最突出的那个客户同时出现在两家同类公司的案例里（赛马） | A1 反向压力测试 | 1 |
| **Q9** | 产品更新日志停更四个月 | A2 | 1 |

⚠️ **到这里为止，一个问题都还没写。这是对的。**（SKILL §2.5）

## 2. 第二步：业务澄清五法（对应 SKILL §3）

| 法 | 这次怎么用的 | 结果 |
|---|---|---|
| **交叉核查 + 可信度分级** | Q6 的两个说法：`中间人转述`（新设岗位）vs `公司自述`（JD 写接手现有系统）。两者可信度都不高，且互相矛盾 | **标"待核实"**，升级为 T6 与 H1 两条问题，分别向技术负责人和 HR 问，看两边说法是否一致 |
| **反证优先于自证** | 中间人说"技术负责人很强"——这是自述性质的转述，不作为判据 | 改用公开信息：这条业务线现在归谁管、还在不在招研发。**结论：研发只在招三个，与"很强的技术负责人正在扩张"这个印象对不上**，记入 Q2 |
| **查不到 → 升级为必问项** | 真实的交付人力占比、单客户上线周期、数据回流机制——公开渠道全查不到 | ✅ **全部升级为必问项，且提到最前**（T2 / T3）。⚠️ 注意区别：这几条改写后**对方答得了**，所以是升级；而现金储备改写后仍然拿不到，所以是**删掉**（见 §1.0） |
| **反向压力测试（赛马假设）** | 官网最强调的那个客户 → 交叉检索发现它同时出现在另外两家同类公司的案例里 | 记为 Q8。⚠️ **不当面戳穿**——改成主动抛观点 V2（见 §4.4），用"客户在这个阶段还在比较不同做法"的措辞 |
| **边界：研究不是审讯** | Q6 的口径矛盾、Q8 的赛马，都不用陈述句问 | 全部改成"我看到……我理解的是……是这样吗" |

## 3. 第三步：提问设计（对应 SKILL §4）

**提问预算**：面试安排未知 → 按一场 60 分钟、能问透六到八个准备（`默认建议值`，不是实测常数）。所以做**通用序 + 三份分身序**（SKILL §5）。

⚠️ **三份分身序的条数加起来超过六到八，是因为到场只会用其中一栏。** 如果一轮里技术负责人和 HR 一起进来，**仍按单场六到八个砍**，从两栏里合并挑，不叠加（SKILL §4.2）。

**收敛前先划出两栏不可砍的**（SKILL §5 第 2 条）：🔪 Kill Switch 判"公司成不成"，🔒 必要条件验证题判"我要不要去"，**两栏并列，砍问题时都不参与**。

**🔪 Kill Switch 挑选**（三条，对应能直接判生死的二元命题）：

1. **T2**（这是产品公司还是项目制公司）→ 直接决定入职后的日常工作
2. **T1**（模型上移之后还剩什么）→ 直接决定这家公司三年后还在不在
3. **F1**（有没有滩头阵地）→ `答不上来本身是信号`，**但只在问创始人 / 高管时成立**；如果这轮只见得到技术负责人，这一条降级进备用区，不占 Kill Switch 名额

**🔒 必要条件验证题挑选**（来自用户 `positioning.md` 的三条必要条件 + 一条硬性排除，见 §4.6）：

| 必要条件 | 配哪条问题 | 问谁 |
|---|---|---|
| ③ 岗位是产品方向不是交付方向 | **T2** —— ⭐ 它同时是 🔪1，**只占一个名额**，两个记号都标 | 技术负责人 / 直属上级 |
| ① 直接向技术一号位汇报 | **H2** | HR / 中间人（见到技术负责人时交叉问一次） |
| 硬性排除：常驻客户现场出差 | **H5**（新增：*"这个岗位过去半年实际出差的频率大概是什么样？最近一次去客户现场是什么事？"*） | 技术负责人 / HR |
| ② 现金部分不依赖期权兜底 | **本场不问** —— 属 offer 条款，交给 [`05-offer`](../modules/05-offer/)，不占名额 | — |

⚠️ **T2 兼了两职，不等于 🔒 这一栏满了**：①、硬性排除各自仍然需要一条。**这一栏的位置是固定的，不参与砍。**

⚠️ **假设这场只见得到技术负责人、提问时间只有十来分钟**：F1 按上面的规则降级进备用，剩下 🔪T1 / 🔪🔒T2 / 🔒H2（改向技术负责人问）/ 🔒H5 四条，**就只问这四条** —— 这是收敛对了，不是没准备好。⛔ **不许**因为"通用序里那几条也挺重要"把 H2 / H5 砍掉：砍掉它们，这场面试结束你会有一份"这家公司还不错"的结论，**却仍然不知道自己去不去**。

# 纬度智能 · AI 产品工程负责人 · 面试前评估

- **评估日期**：2026-08-30
- **面试安排**：未知（只知道这两天一轮）→ 一页纸给通用序 + 三份分身序
- **信息来源盘点**：`你给的` JD + 中间人三条转述 + positioning · `公开可查` 官网 / 产品文档站 / 招聘页 / 公开报道 · 中间人转述 有（可信度：低于公开报道）
- ⚠️ **本次缺什么**：面试对象未知 → 问题清单按三种可能各备一栏；无内部信息 → 全部结论只由 `公开可查` 与 `我推测的` 构成，无一条 `你给的` 属于内部事实

### 4.1 结论速览

| | |
|---|---|
| **匹配度** | **中** —— 技术要求（大模型应用落地、检索与结构化抽取、带人）对得上；但"产品工程方向"这一条与 §1.5 D5 的观察冲突，**是否真的是产品岗待验证** |
| **级别** | **探路** —— 不是不投，是"必须靠这一场面试把两条关键疑点问掉才能定" |
| **上游定级 / 本次是否修正** | 上游判的是 `无上游 — 本次从零判级`（这次没走 [`jd-triage`](../modules/03-company-analysis/jd-triage/)）→ 本次定为 **探路**。⚠️ 如果接了上游：这一行要写"上游判 X → 本次维持 / 修正为 Y，理由 Z"，且上游标出的「待确认的必要条件」要逐条落到 §4.3 的 🔒 那一栏，**不能靠人工搬运** |

### 4.6 决策分离

#### 公司成不成

- **必要条件有没有硬伤**：未见明确硬伤。
- **四框架信号**：负面 Q1 / Q2 / Q3 / Q4 / Q5（其中 **Q2 的观察最硬，但推论仍是 `我推测的`**）· 正面 **暂无**——原先写的"在招销售 = 已在建可复制的销售动作"**已按 SKILL §2.2 B5 删除**（同一观察两解，不构成判据），改为待问 **F7** · 信息不足 Q7 / Q9
