# 本地工作区与可审阅交付

易用性和完成度优先：Agent 负责整理、建目录、写成品、检查和维护策略。用户只需提供已有材料、目标和无法代答的个人选择。完整指本次任务可完成的部分已经落地，不是每个表格都有猜出来的答案。

## 建在哪里

用户已指定本地路径时，直接创建缺失的目录，不要求先手工建空文件夹。未指定且没有既有求职工作区时，一次询问存放位置，同时继续整理已给材料；不能自行选公共仓库放个人资料。文件夹申请只问路径或 Agent 运行环境实际需要的目录访问权限，已有授权不重复申请。

新工作区由工作区模块建立；单独用其它模块时只建本次所需目录，不强迫完成全套初始化。已有工作区先读现有文件，初始化只补缺失项。原始材料和历史审阅保留；策略、申请索引及衍生产物可按本次授权更新并记录变更，冲突保留并报告。写完重新读取实际文件，不能把目录树展示当成建好了。

## 用户策略放在 `policies/`

从 [策略模板](../modules/00-workspace/templates/policies/README.md) 建立本地 `policies/README.md`、`preferences.md`、`changes.md`。每次任务先读有效策略，再读相关模块；只有单份 SKILL 时也须按其中的交付规则创建最小策略文件。

执行偏好、可调参数和适配经验放这里。`positioning.md` 仍唯一维护必要条件、排除条件、可协商区间与披露边界；策略入口引用它。事实仍在 `facts.md`，不能复制到策略里形成第二份真相。

用户说“以后按这个来”时，Agent 直接更新对应策略，记录旧值、新值、理由、日期与影响产物；改前内容留在变更记录中以便恢复。Agent 自己提出的偏好或阈值建议先标待确认，不得变成生效值。重复或冲突项主动合并；涉及用户底线冲突时一次说明并提问，继续不受影响的工作。调整策略不等于获得发送权限，也不能取消事实真实性和已有执行边界。

## 岗位申请文件夹

涉及具体岗位时建立 `applications/YYYY-MM-DD-公司短名-岗位短名/README.md`。有岗位标识时记录在索引；同岗位后续跟进复用原目录，同公司不同岗位分开；名称重名则加序号。具体文件由 Agent 按实际任务写出，索引至少列：

- 公司、岗位、来源、申请状态、最近更新时间。
- JD 原文、定级、简历、接触文本、面试材料及 offer 分析的相对路径；未产生的标“本次未涉及”或“待补”，不得放死链接。
- 本次审阅入口和下一步。

`jobs/`、`triage/`、`resumes/`、`assessments/`、`interviews/` 等继续放正文，`ledger.md` 继续记录接触。申请目录是单岗位导航，不复制事实池或再建一份台账。一次多岗位任务分别建索引，共用报告可指向同一个文件的对应小节。

## 每次任务怎么交付

1. 把用户要求的可做部分写成可读文件：定制简历、岗位判断、面试清单、复盘或 offer 对照。不能只交步骤、空模板或“可以继续”。无事实材料时交缺口明确的骨架并标为部分完成，不冒充成稿。
2. 在 `reviews/YYYY-MM-DD-任务短名.md` 写审阅卡，使用 [审阅模板](../modules/00-workspace/templates/review.md)。包含成品链接、主要结论、事实/来源依据、已用策略、待确认项及其影响、实际检查结果、下一步。文件重名时加序号，不覆盖历史审阅。
3. 逐一打开产物检查：链接存在、内容非空、来源可追溯、未把推测当事实、已完成所需格式检查。对外正文不混入内部审阅批注；PDF 要按简历模块完成相应验证。
交付前核对报告、申请索引、台账、审阅卡的结论与下一步一致；“不投”的下一步是说明排除依据及何种证据或本人条件变化才重评，不使用继续推进的通用句。重排正文后修正“上表/下表”等指代；检查文件数量必须来自实际统计，未统计就列检查对象。历史错误另加勘误并保留原记录。

4. 状态只用“可审阅 / 部分完成 / 阻塞”，审阅状态另记“待本人审阅 / 已审阅”。可审阅不等于获准对外发送；已有明确发送授权的任务继续按投递规则执行，不凭这张卡新增审批。
5. 最后给用户可点击的成品与审阅卡路径，说明尚缺什么。若运行 Agent 的工具环境不能写文件，明确说未落盘，交完整正文和建议路径；不得称目录已建或本地交付完成。

适用入口：[仓库首页](../README.md)、[工作区模块](../modules/00-workspace/README.md)、[文件契约](module-contracts.md)。各模块 SKILL 的“交付约定”包含独立使用时的最低要求。
