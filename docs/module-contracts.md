# 模块间的文件契约

> **模块之间唯一的耦合点。** 模块不互相调用代码，只读写下面这些文件。
> 改模块内部随便改；只要契约不变，就不会打断下游。

## 怎么读这份文档

每个契约给三件事：

1. **谁写谁读**
2. **最小字段** —— 少于这些，下游就没法用
3. **上游缺失时怎么降级** —— ⚠️ 这一栏是全文最重要的。**任何模块在上游文件不存在时都必须能继续跑**，退化成"需要你手工补这几项"，**不是报错退出**

三条通用纪律：

- **契约文件是 markdown，不是 schema。** 结构化字段只在必须索引时出现，且永远附带文本上下文。你可以用表格、也可以用小标题＋段落，只要那几个字段能被读出来
- **契约里不出现平台专有字段**（某个网站的按钮状态、职位 ID）。这类进各自的适配层私有文件
- **登记类契约不设最小样本门槛**（见 `discoveries.md`）

## 0. ⭐ 五条标注轴：先分清楚，否则它们会互相冒充

整个仓库里有**五套标签**在跑。它们**互不换算、互不覆盖**——同一个东西可以同时挂上其中好几个。

**不先讲清楚会出什么事**：某一处只标了「参数来源等级」，读者以为那就是来源标注，于是**结论本身其实一条标注都没有**；或者上游标了「未验证」，下游读成「你给的」（因为它确实"来自面试复盘"），于是**测过但没测出来的东西被当成事实参与了排序**。这两种都真的发生过。

| 轴 | 枚举 | 贴在**什么**上 | 它管什么 | 谁必须用 |
|---|---|---|---|---|
| **A · 来源标注** | `你给的` / `公开可查` / `我推测的` | ⭐ **每一条结论** | **能不能参与排序 / 能不能当依据**（`我推测的` ⛔ 不参与） | **全部模块** |
| **B · 参数来源等级** | `实践校准` / `默认建议值` / `纯占位待校准` | **阈值与参数**（不是结论） | 这个数字有多可信、要不要做敏感性测试 | 有阈值的模块 |
| **C · 证据等级** | `合同白纸黑字` / `面试口头` / `公开记录` / `自己估算` / `未验证` | **翻转点里的每条假设** | 这条假设有多硬（口头承诺按 0 计的判据） | 05-offer |
| **D · 验证三态** | `证实` / `证伪` / `未验证` | **面试前写下的每条判据** | 这条判据**测出结果了没有** | 04-interview |
| **E · 转录保真度** | `原话` / `我转述的` / `归纳的` | **对方说过的话** | 这句引用有多接近他原本说的 | 04-interview |

### 三条不许违反的换算规则

1. ⭐ **B 不能替 A 出场。** 标了参数的来源等级 ≠ 标了结论的来源。
   > 真实反例：一份报告写着「差 1 家没到门槛，本轮不改」——**这条结论没有任何来源标注**，而它引用的那个门槛数字标着 `纯占位待校准`。**读者会以为标过了。**
2. ⭐ **D 的 `未验证` 在 A 轴里一律是 `我推测的`。** 它**不是** `你给的`——虽然它确实"来自面试复盘"。
   > **测过了但没测出来 ≠ 你告诉我的事实。** 上游花力气把「未验证」和「证伪」分开，就是为了不让它在下游被当成通过。
3. **E 贴在问句上，A 贴在判断上。** 一个格子里同时出现 `原话` 和 `你给的` 是错的——前者说的是"这句话我抄得准不准"，后者说的是"这个判断是谁给的"。

### ⛔ 一条自查，比补标注更重要

> **如果你的一份产出里，来源标注全都是同一个值（比如全是 `你给的`），那它等于没标。**

一个只会给出一种标签的标注系统，和一个根本没在运行的标注系统，**从产出上看长得一模一样**——这就是这个仓库反复讲的那条命题，用在了它自己身上。
**跑完先数一遍**：`我推测的` 一条都没有，多半不是你什么都知道，是你没在标。

## 1. `positioning.md` —— 你在找什么

| | |
|---|---|
| **谁写** | 06-positioning，或你自己手写 |
| **谁读** | 03-company-analysis（jd-triage **与** interview-strategic-assessment 都读）、⭐ **04-interview**（输入表 + §3.3「面试官关注点 vs 你预设的定位」）、⭐ **05-offer**、⭐ **02-apply**（fail closed 的两个必需判断依据之一——必要条件与硬性排除条件，直接读这里，不经过 triage 派生） |
| **最小字段** | 目标形象（一句话）· **必要条件**（不满足就不投/不去）· **加分条件**（满足越多越好，但单条不构成否决）· **硬性排除条件** |
| **可选字段**（2026-09-21 起） | **可协商区间**（对带数值的必要条件：底线 / 可谈到哪 / 换什么才谈；硬性排除条件没有区间）· **披露边界**（主动不说 / 对方问了再说 / 只给本人看） |

**可选字段缺失时怎么降级**：没有「可协商区间」，下游按必要条件字面判，差一点的归「待确认」不放行，并明说"按底线判"；⛔ 不许自己发明一个区间。没有「披露边界」，投递模块按保守默认：当前薪资、离职原因、其他 offer 不主动写，期望薪资只在对方问了之后给区间。

**上游缺失时怎么降级**：没有这个文件，定级模块**不猜**。它会先要你把「必要条件」和「排除条件」各写 2-3 条——这是全仓最短的必填项，写不出来说明你还没决定在找什么，而不是模块坏了。

> ⚠️ **必要条件与加分条件不可互换。** 加分项再多也换不掉一条必要条件。这条纪律在 `03-company-analysis/jd-triage`、`05-offer` 等几个模块里都出现过，**犯的是同一类错**。

> ⚠️ **读它的时候，条件的"写下日期"以文件里记的为准，不是以你问出来的时间为准。** 下游在会话里重问一遍"你的必要条件是什么"，问出来的是同一条内容，但**时点不是今天**。把它记成今天写的，一条真·事前条件就被降级成"事后重构"，于是白白触发一整套本来不需要的额外对照。
> ⭐ 这个区分决定了下游 gate 的性质：**事前写下的条件起约束作用**（不满足就是不满足），**事后重构的条件只起暴露作用**（只能提醒你去看一眼，不能拿来否决）。两者混同，gate 要么过松要么过紧，而你不会知道是哪一种。

## 2. `facts.md` —— 事实池

| | |
|---|---|
| **谁写** | **你自己是唯一的事实权威来源，agent 可以代做机械转录** |
| **谁读** | 01-resume、⭐ **04-interview**（它有一条**每场必查**的硬检查项要读「待核实区」：今天有没有把还没核实的内容当确定的说出去） |
| **最小字段** | 经历条目（时间 / 组织类型 / 做了什么 / 结果）· 可复用指标 · 口径裁定记录（同一件事对外统一怎么说） |

⚠️ **"谁写"这一格容易被误读成"你必须亲手打字写 markdown"，不是这个意思。** 准确的分工是：**事实内容只能来自你本人**（agent不编造或夸大事实；表达可保持事实地优化）；但**把你口述的几段话整理成 `facts.md` 的结构化格式，是 agent 的工作**——[`01-resume/SKILL.md`](../modules/01-resume/SKILL.md)明确要求由agent整理散乱材料。这与全仓其它模块的 I5 三级自救阶梯是同一条纪律（L2"自己把散着贴来的材料整理成契约文件，不要求用户先整理好"），不是 `facts.md` 的特例。真正不可让渡的是**裁定权**：写进去的每一条事实，最终认不认、准不准，只有你自己说了算。

**上游缺失时怎么降级**：简历模块拒绝在没有事实池的情况下生成内容——**它宁可停下要材料，也不编**。这是"单一事实来源"的执行点。

## 3. `jobs/<batch>.md` —— 一批待评估的岗位

| | |
|---|---|
| **谁写** | 02-apply，或你手工贴 |
| **谁读** | 03-company-analysis、⭐ **02-apply**（步骤 2「渠道优先级执行」也会重读自己刚写入的这批候选做门槛过滤，不只是写入方） |
| **最小字段** | 公司 · 岗位 · 城市 · 薪资原文（**原文，不折算**）· 要求 · 职责 · 链接 · ⭐ **这条是怎么进来的**（搜索命中 / 平台推荐 / 对方主动推来 / 中间人转介 / 其他） |

**上游缺失时怎么降级**：定级模块接受**散着贴进来的 JD 原文**，自己整理成这个结构，不要求你先排好版。

> ⭐ **「这条是怎么进来的」是全表唯一一个不来自 JD 正文的字段，也是最像"可以省"的那一栏 —— 恰恰相反。**
> 定级用不到它，但它是下游判断"你的搜索词是不是在漂移"的**唯一输入**。漏填的条目在方向复盘里等于不存在；而且它**事后补不回来**（过两周你想不起来这条是搜出来的还是别人推来的）。

> ⛔ **本文档不涉及 JD 是怎么拿到的。** 采集属于 02-apply 的范围，且受该模块的边界约束。

## 4b. `triage/<date>-定级结果.md` —— 定级判断 ⭐

| | |
|---|---|
| **谁写** | 03-company-analysis / jd-triage |
| **谁读** | 03-company-analysis / interview-strategic-assessment、你、⭐ **02-apply**（fail closed 的第二个必需判断依据——没有定级结果的条目本轮不处理） |
| **最小字段** | 每条岗位：级别（强匹配 / 较匹配 / 探路 / 不投）· ⭐ **能追回到具体条件编号的理由** · 待确认项（含"原文未提及"的必要条件） |

**上游缺失时怎么降级**：面试前评估拿不到它时，从零判一次级，并在报告里标明"无上游定级"。

> ⚠️ **为什么它要单独一个位置，而不是塞进已有的三个文件里**：
> - `jobs/<batch>.md` 放的是**原文**，⛔ 不放判断 —— 混进去会把"原文 vs 判断"的边界从目录级降成文件级，更容易被违反
> - `ledger.md` 的「级别」栏只装得下一个字母，装不下**能追回到条件编号的理由**
> - `assessments/<company>.md` 按定义只放**面试前**评估，而定级发生在投之前
>
> 这三条是实跑中真实撞上的：不给它位置，**每个用户都得自己发明一个文件名**。

## 6. `interviews/<company>-<date>.md` —— 当天复盘 ⭐

| | |
|---|---|
| **谁写** | 04-interview |
| **谁读** | 05-offer、06-positioning |

**最小字段**：

| 字段 | 说明 |
|---|---|
| 被问到的问题 | 原话优先 |
| 答得不好 / 被追问的地方 | 这一栏空着就等于没复盘 |
| 面试官关注点 vs 你预设的定位 | 对不上是最有价值的信号 |
| **红旗绿旗实测结果** | ⭐ **三态：证实 / 证伪 / 未验证**。**"未验证"不等于"证伪"**——没问到、没聊到、对方回避，都是"未验证"。⭐ **每条带它验证的疑点编号 / 必要条件编号** |
| ⭐ **对方说了什么值得记的** | 对方**主动给的、会改变你对这家公司判断**的具体事实。每条带：**落在哪条疑点**（落不上就写 `新疑点：…`）· **追到底了吗**。⚠️ 与下一行的分工见表下 |
| ⭐ **溢出 / 意外收获** | 跑题跑出来的东西：与本岗位无关但你讲得比对方还兴奋的话题、对方无意透露的行业信息、可复用的线索 |

**上游缺失时怎么降级**：offer 模块拿不到复盘时，"发展空间"这一维只能标 `我推测的`，因而**不参与排序**（见 §来源标注）。

⭐ **还有第三态，不要漏**：拿到了复盘，但其中某一条标着 `未验证`。
**上游标 `未验证` 的判据，下游一律按"未测得"处理，⛔ 不得当作"没问题"通过。** 具体到每个下游模块怎么落地（补测 / 降权 / 标为待验证假设）由各模块自己写，但这条口径在契约层。

> ⭐ **为什么这一句必须写在契约层**：上游花力气把「未验证」和「证伪」分开，就是为了不让它在下游被当成通过。契约层不写这一句，**三态纪律会在最后一米作废** —— 每个下游模块都会各自默认"没写问题就是没问题"，而上游做的那份区分谁也用不上。

> ⭐ **「对方说了什么值得记的」与「溢出」的分工，用一句话分**：
> - 拿掉它，**你对这家公司的判断会变** → 前者（去向：**回流面试前评估的疑点表**）
> - 拿掉它，**公司判断不变，但你对自己的判断会变** → 后者（去向：**发散信号**）
>
> ⚠️ **这两栏不是重复设置。** 溢出栏的区分判据（"拿掉它结论会不会变"）会**正确地**把前一类挡在外面 —— 而在补上这一栏之前，**被挡出去的那些就直接丢了**。实测中一场面试里信息量最大的几条原话，全部因此无家可归。

> ⚠️ **三态不能压成两态。** 把"未验证"记成"证伪"，会直接污染定位模块的判据校准——它会以为某条判据被证明是错的，而其实只是没测过。
>
> ⚠️ **每条判据必须带回它验证的是哪一条。** 没有这个指针，下游拿到"未验证"时不知道它有多要紧 —— 一条挂着**必要条件**的"未验证"和一条挂着**次要疑点**的"未验证"，处理方式完全不同：前者回答的是"我到底去不去"，必须补测或显式接受风险；后者可以留到下一轮。
> ⭐ 指针的来源在上游 `assessments/<company>.md` §3 分层问题清单的「验证哪条疑点 / 哪条必要条件」那一列（`Q<n>` / `必要条件<n>`）。⛔ 复盘时把它丢掉，这条链就只能**联合读两个上游文件**才能还原 —— 而下游只读复盘卡。
>
> ⚠️ **「溢出」栏是发散信号的唯一采集点。** 没有这一栏，"投着投着发现新可能性"就没有数据来源。它的成本是一段模板文字，**任何一轮精简都不许删它**。

## 7. `offers.md` —— offer 横向对照

| | |
|---|---|
| **谁写** | 05-offer |
| **谁读** | 你（终点，不再往下游传） |
| **最小字段** | 每个选项一列（含"留在原地"）· 各维度取值 **+ 来源标注** · 假设与证据等级 · **排序** · **翻转点** |

**上游缺失时怎么降级**：这是全仓最独立的模块——没有任何上游文件也能跑，最少只要**三组**"薪资结构 + 通勤时间"：两个 offer **加上你现在这份工作**。

> ⚠️ **第三组不是可选的。** "留在原地"是排序里的基准列，缺了它就没有参照系——一个只在两个新机会之间做的排序，回答不了"到底该不该动"这个真问题。
> 现状数据实在拿不到时，改用其中一个 offer 做基准并**显式声明"本次无法计算机会成本"**，不要静默换基准。

> ⛔ **不输出 0-100 综合分。** 一个数字会把"我们对这几个假设的把握程度完全不同"这件事抹平。

## 8. `ledger.md` —— 台账 ⭐

| | |
|---|---|
| **谁写** | 所有模块（每发生一次接触就登记一次） |
| **谁读** | 06-positioning、⭐ **03-company-analysis / jd-triage**（拿已投过的条目**反推阈值**，见该模块「怎么标定你自己的阈值」）、02-apply（步骤 0 并发锁检查时现读今日记录，重新数真实进度，不信锁文件旧计数） |

**最小字段**：日期 · 公司 · 岗位 · 级别 · 渠道 · 用的简历版本 · 状态 · 下一步 · ⭐ **对方回应原话** · ⭐ **反向吸引标记**（对方主动发起的，打标）

**上游缺失时怎么降级**：定位模块接受 **10-20 条"公司 / 岗位 / 日期 / 对方回了什么"，散着贴进来也行**——由 agent 整理成台账，不要求你先整理好。少于 10 条时它会直接说"这个量级看不出漏斗形态"，而不是硬给结论。

> ⚠️ **「对方回应原话」不要改写成分类标签。** 一旦压成"婉拒/待定/邀约"，就再也分不出"薪资不匹配"和"方向不匹配"了——而这两者指向完全不同的改法。
>
> ⚠️ **「反向吸引」是最容易漏的一栏**：对方主动来找你的那些，往往指向你自己没意识到的定位。

## 9. `discoveries.md` —— 异常登记簿 ⭐

| | |
|---|---|
| **谁写** | 06-positioning 的发散环 |
| **谁读** | 06-positioning、你 |
| **最小字段** | 日期 · 信号类型 · 原始证据（**原话，不概括**）· 累计出现次数 · 是否已升级为分支 |

**上游缺失时怎么降级**：不存在就新建，登记本身零门槛。

> ⭐ **这个契约不设最小样本门槛，且这是刻意的。** 收敛环靠"重复出现 + 样本门槛"防止被一两次拒绝带偏；而"投着投着发现新可能性"的信号**天然是单次的、看起来像噪声的**——同一套门槛会把它当噪声滤掉。
> **所以：登记免费、不设门槛；门槛只加在「登记 → 开分支」这一步。**

## 10. `branches.md` —— 活跃探路分支 ⭐

| | |
|---|---|
| **谁写** | 06-positioning 的发散环 |
| **谁读** | ⭐ **03-company-analysis / jd-triage**（⛔ 只有定级模块读它，interview-strategic-assessment 不读）、你 |
| **最小字段** | 分支描述 · 开启日期 · **配额**（最多投入多少）· **证伪判据**（看到什么就该关掉）· **截止日期** · 状态（活跃 / 已关闭 + 关闭依据） |

**上游缺失时怎么降级**：定级模块读不到分支时，一律按主线阈值判——**探路岗位会被判成"不投"**。这不是 bug，是缺省的保守行为；降级说明必须写明"你如果在试新方向，需要手工告诉我"。

> ⚠️ **这是全仓唯一一条"发散环 → 执行层"的耦合**：定级模块对探路分支下的岗位走**一套更宽的阈值**，否则新方向的岗位永远过不了为老方向标定的门槛，发散环等于白开。
>
> ⚠️ **证伪判据和截止日期是必填，不是可选。** 一条没有关闭条件的探路分支就是一个无限期的资源漏洞。
