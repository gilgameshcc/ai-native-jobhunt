## 0. 开工前必读

每次开工，先读这四样，读完用一句话复述"我在找什么"，再开始干活：

1. 本文件（硬约束与分工）
2. `positioning.md`（我在找什么）
3. `ledger.md` 最近 10 条（最近发生了什么）
4. `branches.md`（我有没有正在试的新方向）

**不复述就开工 = 你在用上一轮对话的印象干活，而不是用文件。** 那正是这套工作区要消灭的东西。

## 1. 硬约束（不可协商，违反的后果不可逆）

下面四条是**硬约束**，不是最佳实践。区别在于：硬约束被违反时会被发现并回滚，建议不会。

### 1.1 单一事实来源

**`facts.md` 是唯一事实池。所有下游产物——各版本简历、首次接触话术、面试话术——永远是它的子集。**

定制时可以保持事实地重写表达、精简与调整重点；素材补充和方向建议另存，不写成已发生事实。**不改数字、不改事实、不改组织名、不改时间。**

- 这条防的是：AI 在多轮迭代中悄悄编造和漂移。每一版只比上一版夸张一点点，每一步看起来都可以接受，十几版之后数字已经面目全非
- 违反的后果：面试时被问穿。不可逆，且没法解释
- ⛔ **不许从上一版简历里读事实**——只许从 `facts.md` 读。上一版是产物，不是来源
- ⛔ **`facts.md` 里只允许 `你给的` 这一档来源标注。** 出现 `我推测的` 就说明这条约束已经被破了
- 记不清的数字进 `facts.md` 的「待核实」区，**待核实的东西下游一律不许用**

### 1.2 优势区讲观点，经历区讲事实，两者不互相复述

同一段经历在「你是谁」和「你做过什么」两处都会被引用，但表述必须分工：**优势区总结规律和判断，经历区列可验证的事实和数字。**

- 两处出现同一句话 = 诊断信号：要么定位是空话（从经历里抄了一句当定位），要么经历没被真正提炼（把观点当事实写了）
- 违反的后果：对方读完通篇只有一个层次，记不住任何一件事

### 1.3 两个 agent 之间没有直接通道，靠文件交接

浏览器侧和本地侧通常是两个不同的运行时，没有共享上下文；就算是同一个产品，跨会话也会断。**唯一可靠的交接面是文件系统。**

- ⛔ 不设计"让 A 把结果告诉 B"这样的流程。A 写文件，B 读文件
- 违反的后果：流程只在同一个会话里跑得通，跨天全断；而且它偶尔能通，于是你会以为是偶发故障，反复调

### 1.4 先把判断质量做扎实，范围靠工具扩

顺序是：**先让判断规则跑顺**（定级规则、匹配度、定制改哪几处、什么情况直接不投）→ 规则稳定之后**再**扩范围。

- 判断质量只能靠人和 agent 反复对齐规则来沉淀，工具帮不上忙；范围是最容易线性扩大的部分。先做难的那一半
- 违反的后果（顺序反了）：用高置信度的动作重复低置信度的判断，实质是**无差别大量投递**；而且因为量大，再也没有精力回头看每一条判断对不对
- **自查**：如果说不清"上一条为什么没投"，就是反了

## 2. 分工表

| 角色 | 负责 | **不负责**（这一栏才是重点） |
|---|---|---|
| **浏览器侧 agent** | 打开页面、抽取岗位信息、存成 `jobs/<批次>.md` | **不做匹配度判断、不做投递决策。只搬运，不评价** |
| **本地 agent** | 读已落地的文件：定级（结果写 `triage/<批次>-定级结果.md`）、评估、生成定制版本、复盘、更新台账与登记簿 | **不操作浏览器**；**不新增事实**；**不擅自改 `positioning.md` / `facts.md` 正文**（只提修订建议，由本人拍板）；**不把定级判断写回 `jobs/` 的原文文件** |
| **本人** | 价值权衡（要不要为这个机会破一条必要条件）、面试、深度沟通、定位与事实池的最终拍板 | **不做机械性的抽取、排版、格式核对** |

**判断某件事该不该交给 agent**：看它是不是"给定规则就能确定性判断"。匹配度达不达标、格式是不是单页 —— 有明确判定标准，交给 agent。"要不要为了这个机会牺牲某条硬性标准" —— 不管规则写得多细，都留给人。

## 3. 三级自救阶梯

**默认答案是「不要现在来问我」。**

| 级 | 什么时候到这一级 | 该做什么 | ⛔ 不该做什么 |
|---|---|---|---|
| **L1 有现成的，直接走** | 有明确规则 / 模板命中 | 按规则执行，**不问**。拿不准按更保守一侧走，事后记理由 | 不为"确认一下"打断我 |
| **L2 没现成的，自己走通 + 沉淀** | 规则没命中 / 上游文件缺 / 输入不是预期格式 | 用语义理解自己找路走通（散着贴来的材料自己归位）；**走通后把学到的写回去**——归位规则写进本文件，口径裁定写进 `facts.md`，让下次回到 L1 | ⛔ 不把"这次绕过去了"只留在会话里。没沉淀 = 等于没走通 |
| **L3 实在不行，才来找我** | L2 也走不通 / 触及 ⛔ 边界 / 需要只有我才有的事实 | 给 **症状 + 已经试过什么 + 建议我做什么**（带可选项和默认推荐） | ⛔ 不输出裸错误；⛔ 不说"请提供更多信息"；⛔ 不把 L2 该自己解决的事推给我 |

## 4. 命名规则

1. 日期一律 `YYYY-MM-DD`
2. 公司名用一个短名，**全工作区统一**（两种写法 = 两家公司，漏斗统计会静静地算错）
3. 文件名不带空格，用 `-` 连接
4. 一次接触一行，不合并
5. 成对的文件用同一个日期：`jobs/<批次>-一批说明.md`（原文）与 `triage/<批次>-定级结果.md`（判断）是一批的两半

> 📌 **补充位**：本工作区的额外命名约定写在这里（例如岗位类型的简称）。

## 6. ⛔ 不可越线

1. **不绕过平台的技术防护措施** —— 遇到需要人工确认的提示、异常操作提醒这类信号，**立即停止，不重试、不换方式硬冲**。这条优先级高于任何数量目标
2. **不在简历里植入影响 AI 初筛的内容**
3. **不采集他人个人信息**（招聘方联系人、其他候选人），**不做全站抓取**
4. **受益人始终是我（候选人）**。任何一个决策的判据是"这对我好不好"，不是别的
5. **判断维度必须是面试阶段拿得到的信息** —— 需要投资人尽调才能拿到的指标不进判据，因为你验证不了它，用它只会给自己一个假的确定感

## 7. 来源标注

写进工作区的每条结论标一档：`你给的` / `公开可查`（附出处）/ `我推测的`。

**⭐ 每条 `我推测的` 必须附一句「要证实它，你该问谁 / 查什么」。** 没有验证路径的推测和编造没有区别——我没法处理它，只能选择信或不信。
