## 必要条件（不满足就不投 / 不去）

| # | 条件 | 怎么判定（看什么就能给出是/否） | 来源 |
|---|---|---|---|
| 1 | <例：必须能接触到真实业务方> | <例：面试时问"这个岗直接对接哪个业务角色"，答不上来即为否> | 你给的 |
| 2 | | | |
| 3 | | | |

**填表规则**

- **至少 2 条，建议不超过 5 条。** 超过 5 条通常意味着你把加分项混进来了
- 每条必须**可判定**：看 JD 或在面试里问一句就能给出是/否。"想去有技术含量的公司"不是条件，是愿望——追问自己"看什么就能判断有没有技术含量"，把答案写进来
- **不写数字阈值**。薪资、通勤时长这类有具体数值的，写进下面的「阈值区」并标来源等级

> **为什么要它**：它是全仓最短的必填项，也是下游所有"投不投 / 去不去"判断的地基。
> **不填会怎样**：⭐ **定级模块读到空的必要条件时不猜、也不用默认值**——它会先回来要你把这一栏和下面的「硬性排除条件」各写 2-3 条。如果你让它硬跑，结果是**所有岗位都会被判成"较匹配"**：没有一条能否决的条件，也就没有任何区分力，一份看起来很专业但每行结论都一样的表。
> ⚠️ **不要把这理解成"它会保守地一律判不投"。** 失效方向恰恰相反——**是全部放行，不是全部拦下**，而全部放行比全部拦下更难被你发现。

## 加分条件（满足越多越好，但**单条不构成否决**）

- <例：团队里有比我资深的同角色的人>
- <例：办公地点在通勤半小时圈内>

> **为什么要它**：把"更好"和"必须"分开，是为了让排序有梯度而不是只有及格线。
> **不填会怎样**：所有条件都变成必要条件，于是你会否掉所有机会；或者反过来，所有条件都变成软的，于是什么都能投。

> ⚠️ **必要条件与加分条件不可互换。加分项再多也换不掉一条必要条件。** 这是全仓复现率最高的错误——它会在定级和 offer 排序时各犯一次，形态完全一样：「这家虽然某条不满足，但别的方面太好了」。**那正是必要条件存在的意义。**

## 硬性排除条件（一票否决，不可被匹配度换）

| # | 排除项 | 为什么它是一票否决 |
|---|---|---|
| 1 | <例：不接受完全不写代码的岗> | <例：三年后我要还能回到技术岗> |
| 2 | | |

**填表规则**

- **至少 2 条。** 写不出排除条件，通常说明你还没真的想过"什么情况下我宁可不去"
- **必须写"为什么"那一栏**。半年后你会遇到一个各方面都很好、只差这一条的机会，那时你唯一的抵抗就是当初写下的这个理由

> **为什么要它**：这是 `positioning.md` 里唯一在你最想妥协的时刻还能拦住你的东西。
> **不填会怎样**：会出现"匹配度很高所以就算破了底线也投吧"——底线被匹配度换掉了。而破底线的代价通常在入职三个月后才显现，那时换回来的成本远高于当初拒掉的成本。

## 可协商区间（可选；只对有数值或范围的必要条件写）

| 条件 | 底线（低于它就是不满足） | 可谈到哪 | 换什么才谈 | 来源 |
|---|---|---|---|---|
| <例：薪资下沿> | <留空或写在阈值区> | <例：低一成以内> | <例：远程天数增加、或明确的晋升时点> | 你给的 |
| <例：远程天数> | <例：每周至少两天> | <例：一天> | <例：通勤时间在半小时以内> | 你给的 |

**填表规则**

- 只写**必要条件里带数值或范围的那几条**（薪资、通勤、到岗时间、远程天数）。硬性排除条件**没有区间**，一票否决不谈
- "可谈到哪"是你**事前**写下的放宽上限，**含端点**（写"可谈到一天"，恰好一天算区间内）。agent 在区间内放宽时**必须记下原因**（哪条岗位、放宽了哪一项、换到了什么）；**超出区间不许自己放，回来问你**
- 没有"换什么才谈"的一行，等于把底线直接改低了。写不出来就不要写区间

> **为什么要它**：没有它，agent 在主动探索和定级时只有两种做法，要么死守数字把差一点的机会全筛掉，要么"这家其他方面很好"就悄悄放宽。区间把"放宽"从一次隐性妥协变成一条有记录的决定。
> **不填会怎样**：合法。agent 按必要条件的字面判，差一点的机会归入「待确认」而不是放行，并在报告里明说"没有可协商区间，按底线判"。

## 披露边界（可选；agent 起草任何对外文本前对照）

| 栏 | 内容 |
|---|---|
| **主动不说** | <例：当前薪资、离职原因、手上其他 offer 的公司名、通知期细节> |
| **对方问了再说** | <例：期望薪资区间、最早可到岗时间、是否在看其他机会（只答是否）> |
| **只给本人看** | <例：底线数字、真实离职原因、对某家公司的负面判断、待核实区里的一切> |

**填表规则**

- 这一栏管的是**投递模块的打招呼语、简历定制稿、任何 agent 代你发出的文字**。它不管你自己在面试里怎么说
- "只给本人看"里的内容，agent 可以用来**替你判断**，⛔ 不能出现在任何对外产物里
- 保守默认**始终生效**：当前薪资、离职原因、其他 offer 的存在与公司名一律不主动写，期望薪资只在对方问了之后给区间。这一栏只能在保守默认之上**再收紧**，或把某项**明确**挪进「对方问了再说」来放开；栏里没提到的项不等于可以说

> **为什么要它**：agent 写得越像你，越容易把你只是告诉它的东西当成可以说出去的东西。事实池管的是"不编造"，这一栏管的是"不该说的别说"，两件事不一样。
> **不填会怎样**：合法，按上面的保守默认跑。真正危险的是你在对话里随口说了底线，而它没有任何地方被标成"只给本人看"。

## 阈值区（一律留空 + 标来源等级）

| 阈值 | 当前取值 | 来源等级 |
|---|---|---|
| 匹配度下限（低于此不投） | <留空> | 纯占位待校准 |
| 薪资区间下沿 | <留空> | 纯占位待校准 |
| 单次通勤时间上限 | <留空> | 纯占位待校准 |
| <你自己的其他阈值> | <留空> | |

**来源等级三档**：`实践校准`（你自己跑出来的）/ `默认建议值`（模块给的起点，还没验证）/ `纯占位待校准`（还没定）。

> **为什么要标来源等级**：一个没标来源的数字看起来和一个校准过的数字一模一样，但它们的可信度差着量级。标注让你在复盘时知道"这条判断是建立在真实数据上，还是建立在我当初随手写的一个数上"。
> **不填会怎样**：不填（留空）本身是合法状态，agent 会按更保守一侧判并明说。**真正危险的是随手填一个数字却不标来源**——那会让你以为自己有标准，其实只是有一个数字。

## 修订记录

| 日期 | 改了什么 | 依据（哪一轮数据 / 哪次面试） |
|---|---|---|
| | | |

> **为什么要它**：定位是会变的，但**每次改动都得有依据**，否则就是被最近一次拒绝带偏。
> **不填会怎样**：三个月后你会发现定位和最初完全不同，但说不清是哪几次数据推动的——于是也无法判断这个变化是校准还是漂移。
>
> ⚠️ **一两次拒绝不构成修订依据。** 改必要条件之前，先确认这个信号重复出现过、且样本量够（判定规则见 `06-positioning`）。**"本轮数据不够，什么都不改"是一个合法且经常正确的结论。**
