# 工作区骨架

> **用法**：照着建目录和空文件。**先建全，再填**——一个存在的空文件会提醒人去填，一个不存在的文件不会。
>
> 契约字段的权威定义在 [`docs/module-contracts.md`](../../../docs/module-contracts.md)；本文件只管"文件放哪、怎么命名"。

## 目录结构

```
求职工作区/                      ← 名字随你，这个文件夹整体是私人的，永不进任何公开仓库
├── AGENTS.md                   写给 agent 的硬约束与分工表（可改名，见下）
│
├── positioning.md              你在找什么：必要 / 加分 / 硬性排除
├── facts.md                    ⭐ 事实池：唯一真相，下游全是它的子集
├── ledger.md                   ⭐ 台账：每发生一次接触登记一次
├── discoveries.md              异常登记簿：登记免费、不设门槛
├── branches.md                 活跃探路分支：必须带证伪判据和截止日期
├── offers.md                   offer 横向对照（拿到 offer 之后才建，见 05-offer）
│
├── jobs/                       待评估的岗位**原文**，一批一个文件
│   └── 2026-01-15-一批说明.md
├── triage/                     ⭐ 定级结果，与 jobs/ 一批一份对应
│   └── 2026-01-15-定级结果.md
├── runs/                       每次执行的 review 卡（v0.1 注定是空的，见下）
│   └── 2026-01-15-review.md
├── assessments/                面试前评估，一家公司一份
│   └── 纬度智能.md
├── interviews/                 面试当天复盘，一场一份
│   └── 纬度智能-2026-01-20.md
│
├── resumes/                    材料各版本与定制成品（v0.1 注定是空的，见下；内容规则见 01-resume，本模块不定义）
└── notes/                      还没归位的原始材料 —— ⭐ 唯一允许乱的地方
```

**根级 5 份契约文件（`positioning` / `facts` / `ledger` / `discoveries` / `branches`）+ 规则文件 `AGENTS.md` + 7 个目录，就是全部。**（`offers.md` 是第 6 份契约文件，但**拿到 offer 之后才建**，见 `05-offer`。）

> ⭐ **空模板从哪来**：`positioning` / `facts` / `ledger` 在本模块 [`templates/`](.) 下；**`discoveries` 与 `branches` 的模板本体在 [`../../06-positioning/templates/`](../../06-positioning/templates/)**——它们是发散环的产出物，**全仓只留一份**，本模块不复制副本（副本存在过，两份沿相反方向漂移了）。位置在工作区根目录这一点不变。

新增任何一个之前先回答："**哪个已有文件承担不了这件事？**"答不上来就别加——文件多了就是负担，而负担会让你停止维护。

> `triage/` 是按这条规则新增的最近一个目录，把它的答案写在这里当范例：**三个候选位置都承担不了。** `jobs/` 按定义只放原文（判断写进去就等于用判断覆盖了原始信号）；`ledger.md` 的「级别」栏只装得下**一个字母**，装不下"能追回到具体条件编号的理由"；`assessments/` 按定义只放**面试前**评估，读者与时机都不同。三个都不行，所以它才存在。

## 每个位置放什么

| 位置 | 放什么 | ⛔ 不放什么 |
|---|---|---|
| `AGENTS.md` | 硬约束条文、分工表、命名规则 | 具体的岗位信息、你的经历——那些是数据不是规则 |
| `positioning.md` | 三类条件 + 阈值（留空占位） | 具体某家公司的评价 |
| `facts.md` | 你说过的经历、数字、口径裁定 | **任何你没说过的事**；未核实的数字（进「待核实」区） |
| `ledger.md` | 一次接触一行；「级别」栏只写**一个字母** | 长篇分析——那属于 `assessments/`；定级理由——那属于 `triage/`（一个字母装不下理由） |
| `discoveries.md` | 不在预期内的信号 + 原话证据 + **出处**（合并计数要靠它） | 已经想明白的结论——那属于 `positioning.md`；对方的负面反馈——那属于 `ledger.md`（拒绝是主线数据，不是异常信号） |
| `branches.md` | 正在试的新方向 + 关闭条件 | 已经关闭很久的分支（关闭后保留一段时间再归档）；"这条分支是从哪条信号来的"——那条指针存在 `discoveries.md` 的「是否已升级为分支」栏，**只存一侧** |
| `jobs/` | 岗位**原文**与结构化抽取表 | 你对岗位的判断——那属于 `triage/` |
| `triage/` | ⭐ 一批一份定级结果：每条岗位的**级别** + **能追回到具体条件编号的理由** + **待确认项**（`原文未提及` / `我推测的`，各带一句"要证实它该问谁、查什么"） | JD 原文的改写版（原文只在 `jobs/`，这里引用原句即可）；面试前的疑点清单——那属于 `assessments/` |
| `runs/` | 每次执行做了什么、要你拍板什么 | 累计统计——那是分析，属于周期性复盘 |
| `assessments/` | 面试前的疑点、问题清单、红旗绿旗判据 | 面试后的实测结果——那属于 `interviews/`；投前定级——那属于 `triage/` |
| `interviews/` | 当天复盘：被问了什么、答得不好的地方、红旗绿旗实测 | 下一步计划——那进 `ledger.md` 的「下一步」栏 |
| `notes/` | 任何还没归位的东西：截图说明、随手记、聊天记录整理 | **长期驻留的东西**。这里的每一条早晚要被归位或删掉 |

> ⚠️ **`notes/` 是唯一允许乱的地方，但它不是垃圾桶。** 允许乱是为了让你随手记录时零摩擦；如果三个月后它还在长大，说明归位这一步从来没发生过——那是 agent 该干的活（L2），提醒它。

## ⭐ v0.1 里注定是空的两个目录

`runs/` 和 `resumes/` 建出来之后**会一直是空的，这是正常的，不是你漏做了什么**：

| 目录 | 谁往里写 | 现在的状态 |
|---|---|---|
| `runs/` | 投递执行模块（每次执行的 review 卡） | **它的生产者模块尚未发布** → 没有任何东西会自动往里写 |
| `resumes/` | 材料版本模块（各版本与定制成品） | **它的生产者模块尚未发布** → 同上 |

**照样先建出来**，理由和"先建全再填"是同一条：位置先占住，等生产者模块到位时不用再改一遍命名和所有引用。

你当然可以自己手工往里放东西——`resumes/` 放你手上现成的那几版材料、`runs/` 放你自己写的执行小结，都不违反任何约定。**⛔ 但不要因为它们空着就把目录删掉**，删了下次得连引用一起改回来。

## 命名规则

**这四条当场立下，写进 `AGENTS.md`，因为改起来的代价随文件数量线性增长。**

1. **日期一律 `YYYY-MM-DD`**。不用 `1月15日`、不用 `20260115`。理由：排序即时间序，肉眼和 agent 都不用解析
2. **公司名用一个短名，全工作区统一**。同一家公司在台账里写两种写法，等于两家公司——漏斗统计会静静地算错，而你不会收到任何报错
3. **文件名不带空格**，用 `-` 连接。多数工具链对空格的处理都有坑，且这个坑通常在你最赶的时候出现
4. **一次接触一行，不合并**。同一家公司的三次沟通是三行，不是一行里塞三句话。合并之后再也拆不开
5. **成对的文件用同一个日期**。`jobs/2026-01-15-一批说明.md`（原文）与 `triage/2026-01-15-定级结果.md`（判断）是一批的两半，日期对齐之后两份文件肉眼就能配上对；不对齐就得靠回忆去配，而回忆在第三批之后就不管用了

## 关于 `AGENTS.md` 的文件名（可移植性）

不同 agent 产品会自动读取的约定文件名不一样。**本模块不绑定任何一家**：

- 你的 agent 读 `CLAUDE.md`？把 `AGENTS.md` 改名成 `CLAUDE.md`，内容一个字不用动
- 读别的名字？同理改名
- **两个都不自动读？** 那就每次开工时把它粘进对话——效果完全一样，只是多一步。这不是降级方案，本模块所有内容都是按"能被粘进对话就能用"设计的

## 隐私边界（不是建议，是硬线）

- **这整个工作区永不进任何公开仓库。** 它装的是你的全部经历、薪资沟通、和别人对你的评价
- 如果你要把某段内容分享出去（提 issue、发帖、请人帮看），**重编一份，不要脱敏一份**——脱敏后的材料仍然携带真实的结构与巧合（时间点、行业组合、比例关系），这些是可反查的
- 平台账号信息、登录态、你自己的搜索参数：**留在本机，不写进工作区的任何 markdown**
