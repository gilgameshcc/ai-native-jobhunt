# 00-workspace · 工作区约定

> **v0.1.3** · 纯 markdown，零可执行依赖。不需要你装任何东西，也不需要你会命令行。

把一个散落着简历文件、聊天截图、公司资料的文件夹，变成一个 agent 能直接接手干活的工作区。

它解决的是一个很具体的疲劳：**每开一次新会话，你都要重讲一遍"我是谁、我在找什么、上次聊到哪"。** 讲到第三次你就会开始偷懒，偷懒之后 agent 给的结论就开始飘——它不是变笨了，是你每次喂给它的背景都不一样。

## 一句话原则

> **工作区即数据库，文件即接口。** 状态不放在对话里，放在文件里。下一个环节——不管是你、是下周的你、还是另一个 agent——只从文件读，不从"上次说过什么"读。

对话记忆会丢、会被压缩、会跨不过会话边界；文件不会。这条不是洁癖，是这套东西能不能连续跑超过一周的分水岭。

## I1 三问

每个模块都要回答这三问，答不出第三问说明耦合太紧、该拆。

### ① 单独用行不行？

**行，且它是逻辑上唯一的上游模块——但不是必须先跑完的模块。** 建工作区不需要读任何其他模块，你现在就可以只拿走这一份，把骨架和几个契约文件建起来，然后停在这里；也可以先跳过它，直接去用别的模块，缺什么它们会告诉你怎么降级（见下一段）。

反过来也成立：**其他模块不强制要求你先跑完 M0**。你可以跳过工作区，直接把一份 JD 粘给评估模块。M0 的价值在第二次、第三次用的时候才显现——它让第二次不用重讲背景。

### ② 依赖哪些模块的输出？

**零。** M0 是全仓唯一没有上游模块的模块。它的上游只有一个：**你本人**。

它读你手上已有的东西（经历材料、已经发生过的接触记录、你对"想找什么"的模糊想法），产出的是别人的输入：`positioning.md` / `facts.md` / `ledger.md` / `discoveries.md` / `branches.md`——这五份是 [文件契约](../../docs/module-contracts.md) 里躺在工作区根目录的那几个。前三份的空模板在本模块 `templates/` 下；⭐ **后两份的模板本体在 [`06-positioning/templates/`](../06-positioning/templates/)**——它们是发散环的产出物，**模板只留一份，本模块不复制副本**（理由见下方「目录里有什么」）。

**M0 是文件契约的物理载体**：契约文档说"这个文件要有哪几个字段"，本模块给出"那个文件长什么样、每个字段为什么要"。

### ③ 缺了上游会退化成什么？

上游是你自己，所以"缺上游"= 你还没想清楚 / 手上材料没整理 / 有些事根本没记过。**这三种情况都不阻断，各有明确的退化行为**：

| 你缺的 | 退化成什么（具体行为，不是"报错退出"） |
|---|---|
| **还没想清楚在找什么** | 骨架照建，`positioning.md` 只留「必要条件」「硬性排除条件」两栏待填。agent **不替你填**，也**不停下来干等**——它建完其余所有文件，最后给你一张「就差这两栏，各写 2-3 条」的清单。这两栏是全仓最短的必填项：写不出来说明你还没决定在找什么，而不是模块坏了 |
| **经历材料散在好几个地方、没排版** | 散着贴进来，**agent 负责归位**——整理是它的活。要求你先整理好再来，等于把它该干的事推给你，这是明确禁止的（见 SKILL.md 的三级自救阶梯 L2） |
| **已经找了一阵子，但没有台账** | 补登 〔10-20〕 条（`默认建议值`）「公司 / 岗位 / 日期 / 对方回了什么」就够开工。低于这个量级，`06-positioning` 会直接告诉你「这个量级看不出漏斗形态」，**而不是硬给一个看起来很专业的结论**。⭐ **但四字段只够起步不够收尾**：缺「渠道 / 用的哪一版 / 级别」这三栏，「哪个渠道有用」「要不要改表述」「定级规则准不准」这三类结论**永久不可判**——而且它们**事后补不回来**（见 [`SKILL.md`](SKILL.md) 的「四字段够起步，不够收尾」） |
| **完全没有可复用的经历数字** | `facts.md` 留空开工，但下游简历模块会**拒绝在没有事实池的情况下生成内容**——它宁可停下来要材料，也不编。这是"单一事实来源"的执行点，不是可以绕过去的严格模式 |

**通用退化纪律：任何一步缺输入，说清楚"少了哪一层、因此哪个结论不可信"，然后继续跑剩下的。** 不假装分析完整，也不整个停摆。

## 四条可抄的设计

这四条都是真跑过、且付过学费的。它们比目录结构重要得多——目录你可以随便改，这四条改了整套东西会垮。

### 1. 单一事实来源

**你的经历、数字、项目细节只在 `facts.md` 一个文件里维护。所有下游产物——各版本简历、首次接触话术、面试话术——永远是它的子集。**

定制时可以保持事实地重写、精简与调整重点，也可另提待确认建议。**不改数字、不改事实、不改组织名、不改时间。**

- **为什么**：这条的价值不在整洁，在**防止 AI 在多轮迭代中悄悄编造和漂移**。没有它，十几个版本迭代下来，简历上的数字会不知不觉"越写越好看"。每一版都只比上一版夸张一点点，每一步你都觉得可以接受。
- **犯了会怎样**：面试时被问穿。数字对不上是信任成本最高的一类错误——不是"这一场没过"，是这一场从被问到的那一刻起就已经结束了。而且**不可逆**：你没法解释"那是 AI 帮我润色的"。
- **怎么落地**：写进 `AGENTS.md` 当硬约束条文（模板里已经写好），不是当"最佳实践"提一嘴。硬约束和建议的区别是：硬约束被违反时你会发现，建议不会。

> 这条是整套方法论里最有传播力的一条，也是唯一一条**建议你原样抄走、一个字都别改**的。

### 2. 优势区讲观点，经历区讲事实，两者不互相复述

同一段经历会在两个地方被引用：「你是谁」（定位、优势提炼）和「你做过什么」（经历、项目描述）。**表述方式必须分工**：

- **优势区**：总结规律、下判断、给出你对这件事的理解
- **经历区**：列可验证的事实和数字，不加形容词

- **为什么**：如果两处写的是同一句话，只可能是两种情况之一——要么你的定位是空话（从经历里抄了一句就当定位），要么你的经历没被真正提炼（把观点当事实写了）。**两处重复本身就是诊断信号**，不用等面试官来告诉你。
- **犯了会怎样**：面试官读你的材料时形成不了任何印象，因为通篇只有一个层次。你会觉得"我写得很充实啊"，但对方读完记不住一件事。

### 3. 分工表：谁干什么，以及谁**不**干什么

| 角色 | 负责 | **不负责**（这一栏才是重点） |
|---|---|---|
| **浏览器侧 agent** | 打开页面、抽取岗位信息、存成文件 | **不做匹配度判断、不做投递决策**。它只搬运，不评价 |
| **本地 agent** | 读已落地的文件：定级、评估、生成定制版本、复盘、更新台账 | **不操作浏览器**、**不新增事实**、**不擅自改 `positioning.md` / `facts.md` 正文**（只提修订建议） |
| **你本人** | 价值权衡（要不要为这个机会破一条必要条件）、面试、深度沟通、修订定位与事实池的最终拍板 | **不做机械性的抽取、排版、格式核对**——那是 agent 的活，你做等于浪费 |

**⭐ 两个 agent 之间没有直接通道，靠文件交接。**

- **为什么**：它们通常是两个不同的运行时（一个在浏览器里、一个在本地），没有共享上下文。就算你用的是同一个产品，跨会话时上下文一样会断。**唯一可靠的交接面是文件系统。**
- **犯了会怎样**：你会写出"让浏览器 agent 把结果告诉分析 agent"这样的流程，然后发现它每次都只能在同一个会话里跑通，一跨天就全断。更糟的是它偶尔能跑通（同一会话内），于是你以为是偶发故障，反复调。
- **判断某件事该不该交给 agent**：看它是不是"给定规则就能确定性判断"。匹配度算不算达标、格式是不是单页——有明确判定标准，交给 agent。"要不要为了这个机会牺牲某条硬性标准"——不管规则写得多细，都留给人。

### 4. 升级路径：先把判断质量做扎实，范围靠工具扩

**"覆盖更多岗位"和"每个岗位都判断到位"是两个独立的能力维度。不要用后者的名义牺牲前者。**

正确顺序：

1. 先把**判断规则**跑顺——定级规则怎么定、匹配度怎么算、定制模板改哪几处、什么情况直接不投
2. 规则稳定之后，**再**谈扩范围（更多城市、更多关键词、更多渠道、定时执行）

- **为什么**：判断质量只能靠人和 agent 反复对齐规则来沉淀，**工具帮不上忙**；而范围是最容易靠增加执行时间和渠道数量线性扩大的东西。先做难的那一半。
- **犯了会怎样（顺序反了）**：等于**用高置信度的动作重复低置信度的判断**——你把一个还没校准的判断标准，用工具放大了一百倍。产出上看是"投了很多"，实质是**无差别大量投递**，且因为量大，你再也没有精力回头看每一条判断对不对。
- **怎么知道自己已经反了**：如果你说不清"上一条为什么不投"，就是反了。

## 目录里有什么

| 文件 | 是什么 |
|---|---|
| `README.md` | 本文件：这个模块解决什么、四条可抄的设计、边界 |
| [`SKILL.md`](SKILL.md) | 交给你的 agent 的那一份：从零把工作区建起来的完整流程 |
| [`templates/工作区骨架.md`](templates/工作区骨架.md) | 目录结构 + 每个目录放什么 + 命名规则 |
| [`templates/AGENTS.md`](templates/AGENTS.md) | 写给 agent 的工作区硬约束与分工表（可改名成你的 agent 认的文件名） |
| [`templates/positioning.md`](templates/positioning.md) | 你在找什么：必要 / 加分 / 硬性排除三类条件 |
| [`templates/facts.md`](templates/facts.md) | 事实池：唯一真相，下游全是它的子集 |
| [`templates/ledger.md`](templates/ledger.md) | 台账：每发生一次接触登记一次 |
| ⭐ [`../06-positioning/templates/discoveries.md`](../06-positioning/templates/discoveries.md) | 异常登记簿：登记免费、不设门槛。**模板本体在 `06-positioning`**，本模块只负责把它复制到工作区根目录 |
| ⭐ [`../06-positioning/templates/branches.md`](../06-positioning/templates/branches.md) | 活跃探路分支：必须带证伪判据和截止日期。**模板本体在 `06-positioning`**，同上 |

每个模板里，**每个字段都写了「为什么要它 / 不填会怎样」**。不认同某个字段就删掉它——但先读完那一栏的理由再删。

> ⭐ **`discoveries.md` 与 `branches.md` 的模板本体只有一份，在 [`06-positioning/templates/`](../06-positioning/templates/) 下。**
> 它们是发散环的产出物，口径（尤其是「登记按行、计数按独立事件」）跟着那个模块走。本模块曾经各留过一份副本，**结果两份沿相反方向漂移了**——照本模块建工作区的人，拿到的是被 `06-positioning` 显式推翻的那一版计数口径。**现在这里只留索引，不留副本。**

**为什么建工作区这一步就要建这两份**：它们是 `06-positioning` 的产出，但位置在工作区根目录，而且 `discoveries.md` 的登记是**零门槛、随时可写**的——建晚了，前几周的信号没有落点，而那恰恰是"投着投着发现新可能性"最容易发生的时候。

## 怎么开始

1. 把 [`SKILL.md`](SKILL.md) **整份**交给你的 agent（复制粘贴进对话，或让它读这个文件）
2. 回答它一次性列出的那几个问题——它会一次问全，不会挤牙膏
3. 它建完骨架后，你只需要亲手填两栏：`positioning.md` 的**必要条件**和**硬性排除条件**

第 3 步**必须你本人回答，不要让 agent 代填**。后面每一步的判断依据都从这两栏来；agent 猜出来的定位，会让下游所有结论都建立在一个你没同意过的前提上，而且你很难发现——因为它写得很像你会说的话。

## 不做什么

写在这里是为了防止后来的贡献者把边界撑爆。**下面每一条被突破时，请先来改这一节，而不是直接加功能。**

- **不规定你用哪个 agent 产品。** `SKILL.md` 只是一个文件名约定，不是某一家的格式。不依赖 slash command 注册、自动加载、特定目录约定这类专有机制
- **不做工具、不做命令、不做自检脚本。** 排查动作的执行者是你手上的 agent，本模块只提供它需要的判据。任何"跑一下某个命令自检"的实现都会当场把不写代码的用户挡在门外
- **不提供任何真实个人数据示例。** 需要举例时一律用虚构公司（纬度智能 / 恒平科技 / 青栈网络），数字一律占位
- **不写死任何阈值。** 匹配度分数线、薪资门槛、每日上限——一律参数化留空，并标来源等级（`实践校准` / `默认建议值` / `纯占位待校准`）。抄来的阈值会让你以为自己有标准，其实只是有一个数字
- **不替你做价值判断。** 要不要为某个机会破一条必要条件，永远是你的事
- **不管岗位是怎么拿到的。** 采集属于 `02-apply`，且受该模块自己的边界约束
- **不定义评分公式、不输出综合分。** 一个数字会把"我们对这几个假设的把握程度完全不同"这件事抹平
- **不把工作区做成一个需要维护的系统。** 文件多了就是负担。本模块只定义 **5 份根级契约文件 + `AGENTS.md` + 7 个目录**（`offers.md` 拿到 offer 之后才建），新增任何一个都要先回答"哪个已有文件承担不了这件事"——`triage/` 的那份答案就写在[骨架](templates/工作区骨架.md)里当范例

### ⛔ 三条不可越线

1. **不教绕过平台的技术防护措施**——不是"我们暂时不做"，是不做
2. **不教在简历里植入影响 AI 初筛的内容**
3. **受益人始终是候选人（你）**。这套东西不为招聘方的筛选效率服务

⭐ **同一轮固件里一条未改的发现，记在这里**：`templates/facts.md` 的「可复用指标」表只要求"**必须写口径**"，**没写"口径本身也不许是编的"** —— 跑 `事实池待核实区.hit.md` 时，产物给一个用户从没说过的数字配了一句编出来的口径（"上线前后对比"），而这**完美满足**了"这一格别空着"这条规则。**这条没有固件，也还没改。**

### v0.1.2（跨文件一致性审计的修复）

来源：**一次独立的一致性审计**——不看单个文件对不对，只看同一件事在不同文件里说得一不一致。本模块改了三处，**每一处都是"本模块说的"和"下游模块说的"互相矛盾**：

- ⭐ **删掉 `templates/discoveries.md` 与 `templates/branches.md` 两份副本，改成指向 [`06-positioning/templates/`](../06-positioning/templates/) 的索引。**
  **为什么**：同一份契约模板在两个模块各存一份，**已经沿相反方向漂移**——本模块那版写"合并会让「累计出现」失真"（暗示累计 = 行数），`06-positioning` 那版写"**登记按行、计数按独立事件**"（一场面试 4 条溢出 = 4 行 / 计 1 次），两者互相推翻。⛔ 而本模块自称"**唯一一个必须先用的模块**"——**照仓库指定入口建工作区的人，拿到的正好是被推翻的那一版。** 模板本体现在全仓只有一份；副本里的「每个字段为什么要它」表已搬进 `06-positioning` 的两个模板，没有丢。
- ⭐ **修正「缺 `positioning.md` 会怎样」的说法**（`templates/positioning.md` + `SKILL.md` 各一处）。
