# SKILL · 简历整理（v0.2.0）

**把本文件整份交给你的 agent 即可**——不依赖特定 agent 产品。目标是帮助用户讲清真实价值，交出可读、事实可靠的一页简历。

## 开跑前

**最小可接受形态**：几段真实经历 + 一句求职方向。素材散着贴来，由 agent 整理成 `facts.md` 草稿；不要要求用户先填表。可选 JD、现有简历、定位与定级结果。缺 JD 时做通用基础稿；缺经历时一次列出最少问题（做了什么、本人责任、结果与口径、时间），先给骨架，不编内容、不报错退出。无版本文件就从事实池生成一份，不要求凑齐多个版本。

已有的明确事实直接整理使用；矛盾、未知责任与指标口径集中问用户，询问同时继续处理不依赖答案的段落。

## 第一步 · 判断投入与主动诊断

读 JD 与用户目标，识别最值得强调的真实证据、表达不清之处、证据缺口。给出少量高价值建议，每条包含「为什么值得改 → 可直接使用的改写/取舍 → 需要补什么证据」。可以提出新叙事、替代角度和目标角色建议，不局限于换关键词。

沿用有效定级；命中仍有效的硬性排除条件时停止默认投递路径并说明冲突。匹配不足不能靠编造解决。用户明确要求仅探索/准备简历时可产出标注用途的草稿，不把准备材料等同于授权投递，也不擅自改其底线。

## 第二步 · 选择和维护版本

从最接近目标的现有稿起步；主版本、转型版、副线版只是常见选择，不是必须建齐的三份文件，也没有固定数量上限。按目标受众与长期复用价值决定是否新建基础版，记录理由与事实池版本；单个岗位定制不必升级为长期基础版。重复覆盖的版本可建议合并/归档，未经授权不删除用户文件。

使用 [版本登记表](templates/版本登记表.md) 留下用途、对应路径与更新时间，避免多个版本事实漂移。

## 第三步 · 保持事实的重写与建议

Agent 可以自主重写句子、合并重复、排序、提炼优势、按相关性删减、调整结构和措辞；保留可恢复底稿即可，不为每处可逆编辑要求确认。

**事实边界**：每个经历性断言必须能回溯 `facts.md` 或用户本次明确提供的事实。不得改变公司、日期、角色、责任、数字精度、结果范围和归因；不能把团队成果说成个人主导。约数可同精度转述，不能变成无依据的精确数字。压缩不能删除使余句成立所必需的限定条件；未标 `[可选]` 不阻止合理精简。新发现的真实事实先确认并更新事实池，再入正式稿。

**建议与成稿隔离**：可以说「这段经历可能支持跨团队协作，建议补充你对接谁、负责什么」，标为待核实并给求证问题；未确认时正式稿仍只用已知内容。把建议、事实映射与审查记录写在独立工作记录中，不塞进对外简历。

使用 [简历骨架](templates/简历骨架.md) 时可按实际价值删改板块，不强制优势条数。优势必须有经历支撑，避免空泛自评和上下重复。

## 第四步 · 最终一页纸验收

参照 [单页校验 checklist](templates/单页校验checklist.md)，验的是最终交付文件，不是 markdown 行数或作者自报。

- 可以使用已有工具：`node tools/md2pdf/md2pdf.js <定制稿.md> <输出.pdf>`。退出码 0 只说明工具报单页，仍须检查渲染与文本；1 表示溢出，2 表示环境/输入问题。
- 也可用现有编辑器打印预览并导出；核对导出后的最终 PDF 实际页数，再看页面渲染/截图。只有预览时写「预览单页，最终 PDF 待核」，不能声称 PDF 已验收。
- 检查正常阅读比例下正文可读、无重叠/裁切/乱码，标题与内容配对。溢出先删冗余和低相关内容、缩短句子；不牺牲字号与关键限定条件。
- 从最终 PDF 抽取或复制文本，与批准的内容稿核对姓名、联系方式、公司日期、数字、段落完整性与阅读顺序。抽取能力不可用时给人工复制核对步骤，并记未验，不以页面看着完整代替。

行数与字符密度仅用于预估。每次修改最终内容或导出设置后重验受影响项目。记录放在工作记录，**不写在简历末尾**。

## 第五步 · 独立审查与交付

有 subagent 能力时，将最终产物交给未参与撰写的独立 subagent。使用 [事实保持与独立审查表](templates/定制白名单自查表.md) 中的任务文本；输入只包含原始事实池、JD（如有）、用户要求、最终内容稿、最终 PDF/渲染、抽取文本与必要版本标识，**不给作者自评分、预期通过结论或引导性解释**。审查者不得代改事实，只返回问题、证据、严重性与具体改法。

检查事实归因、JD 对应证据、建议是否混入正式稿、一页完整可读、阅读顺序和关键遗漏；审查者缺失材料/工具时逐项写未核验。作者修复后对受影响项交同一独立审查者复查，最终记录必须对应实际交付版本。事实失真、缺字或不可读未解决时不得标为交付就绪。

**没有 subagent**：明确记「未独立审查」，作者自查可以继续但不充当独立审查；给用户同一材料包和审查任务，交另一个新会话或真人复查。不能因写了审查 checklist 就称已独立审过。

交付内容稿、具备条件时的最终 PDF、单独工作记录（建议/待确认事实/审查问题与修复/验收状态）、`ledger.md` 登记；说明哪些已验证、哪些待完成。仅准备材料的草稿不登记为已投递。

## 来源标注

来源写在工作记录或事实映射中，对外简历保持干净。

| 标注 | 用法 |
|---|---|
| `你给的` | 经历与指标事实、用户明确确认的补充 |
| `公开可查` | JD 原词、岗位要求；记录出处。不能据此推断用户做过什么 |
| `我推测的` | 仅建议区的潜在优势与补证假设；附「向用户问什么/查哪份材料可证实」，确认前不进正式稿 |

## 不对劲的时候

| 症状 | 最可能原因 | 你下一句该说什么 |
|---|---|---|
| 只换词，不给新建议 | 把事实保护误当表达限制 | 「请提炼更有力的表达和取舍，保持责任与指标口径；未知内容列成补证问题。」 |
| 参与变成主导 | 事实归因漂移 | 「撤回主导说法，指出事实依据；需要的责任细节集中问我。」 |
| 只按页数宣布交付 | 缺最终渲染与文本核对 | 「请检查最终文件可读性和文本完整性，未做到的如实标记。」 |
| 作者自己说独立审过 | 没有独立执行者 | 「请将原始材料与最终稿交新 subagent，不给自评分；没有能力就写未独立审查。」 |
| 每个改写都问我 | 可逆编辑权限过窄 | 「保持事实的改写直接做，只有未知事实或目标冲突才问我。」 |

## 三级自救阶梯

- **L1**：有事实和现成版就自主诊断、改写、检验，不为低风险编辑打断用户。
- **L2**：没有合适版或格式混乱就自行整理、选择结构并试出可行导出路径；走通后把事实映射、版本用途及有效检查方法写回用户工作记录沉淀，不额外建工具系统。
- **L3**：真实事实仍有缺口，或缺少最终渲染/独立审查能力时，报告「症状 + 已试过什么 + 还缺什么 + 建议你做什么」，保留可用草稿与人工退路，不冒充完成。
