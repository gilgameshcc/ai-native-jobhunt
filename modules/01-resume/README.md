# `resume` · 简历整理

> **v0.1.0** · 属于全案 M1，从事实池到一份能投出去的单页 PDF。

一句话：**事实池是唯一真相，定制永远只做「删/排序/替词」这三件事，不做「写」——一份能投出去的单页简历，是从已经写好的事实里挑出来的，不是重新写出来的。**

---

## 它做什么

| | |
|---|---|
| **输入** | [`facts.md`](../00-workspace/templates/facts.md)（事实池，你自己的，不进仓库）+ 目标 JD（可选，没有就只走「维护基础版本」这条路） |
| **输出** | ① 一份定制版简历 markdown ② 一份单页 PDF（工具路径）或一份视觉复核记录（no-code 路径）③ `ledger.md` 里的一行登记 |
| **怎么用** | 把 [`SKILL.md`](SKILL.md) 整份交给你的 agent，连同事实池一起 |

### ⚠️ 全仓唯一带可执行依赖的模块——但依赖是可选的

`tools/md2pdf` 用来把 markdown 定制稿转成 A4 PDF 并报告页数，**零 npm 依赖**（只用 Node 内置模块 + 系统里已装的 Chrome/Chromium 通过 DevTools Protocol 直接打印）。这是[整个仓库唯一值得发的可执行代码](../../docs/workspace-architecture.md)。

**但它不是单页校验的唯一路径。** [`SKILL.md`](SKILL.md) 第四步同时给出一条 **no-code 路径**（按行数与字符密度估算 + 浏览器打印预览人工确认）——两条路径**效力相同**，no-code 那条不是"装不上工具时的将就"，是正式验收方式之一。这是[准入线](../../README.md)明确要求的：仓库不许因为某个模块引入了依赖，就让"没有 agent 能跑这个依赖"的人在这个模块里卡住。

### 两条不许简化的判断纪律

这两条是本模块的全部价值所在——没有它们，这个模块和"把 JD 塞给 LLM 生成一份看起来贴合的简历"没有区别。

1. **单一事实来源：定制阶段只能删，不能改。**
   经历、数字、公司名、时间只在 `facts.md` 里维护一份。本模块生成的每一份定制稿都是它的**子集**，永远不能新增或改写一条事实——哪怕改得"更贴合 JD"、哪怕只是把一个约数换成一个更精确的数字。
   **为什么不能松**：没有这条约束，十几个版本迭代下来，简历上的数字会不知不觉地"越写越好看"，直到面试时被问穿。这不是审美问题，是**信任成本一旦崩塌就再也建不回来**。

2. **定制只允许改四处，改别的都算违规。**
   优势条目**顺序** / 术语**替换成 JD 原词** / 经历条目**排序** / `[可选]` 条目**增删**。**不改数字、不改事实、不改公司名、不改时间。**
   一条改动如果说不清自己属于这四处的哪一处，它就不合法——不管它看起来多合理、多"只是让表达更清楚"。

> 这两条与 [`05-offer`](../05-offer/README.md) 的 gate（"必要条件不可被匹配度换"）、[`jd-triage`](../03-company-analysis/jd-triage/README.md) 的"硬性排除条件不可被匹配度换"是**同一类纪律**——某些约束是不可交易的，不管别的地方多想放宽它。

## I1 三问

**① 单独用行不行**：可以。手上有一份 `facts.md`（哪怕只有几条经历）和一份 JD，就能跑完一次定制。没有 JD 也能跑——退化成"维护/更新一个基础版本"，见下方降级说明。

**② 依赖谁**：上游是 [`00-workspace`](../00-workspace/README.md) 的 `facts.md` 契约（唯一事实来源）；有 [`jd-triage`](../03-company-analysis/jd-triage/README.md) 的定级结果时会先做匹配度自检，没有时退化成"只做基本合理性判断，不拦"。

**③ 缺了上游退化成什么**：
- 缺 `facts.md`：**拒绝生成**。会先要你把经历素材整理成事实池（哪怕是最小形态——散着说的几段经历也行，由 agent 整理成结构化的 `facts.md`），因为没有它，"单一事实来源"这条纪律无从谈起，模块宁可停下要材料，也不编。
- 缺 JD：退化成"维护现有版本，不做定向定制"，明确告知这份产出"没有针对具体岗位优化"。
- 缺 `jd-triage` 的定级结果：**降级**匹配度自检前置——不是跳过，这一步仍然会做，只是从结构化定级降级成常识性判断（比如城市/薪资区间明显不合），并提示"没有结构化定级，这一步只能靠粗判"。

---

## 不做什么

- **不生成经历。** 一条 `facts.md` 里没有的经历，永远不会出现在定制稿里——哪怕它"听起来很合理"
- **不润色成"更好听的说法"。** "参与了"不会被改写成"主导了"，这不是文风问题，是防止事实漂移的执行点
- **不提供简历模板美术设计。** 给的是内容结构（哪个模块放什么），不是字体/配色/排版风格——那是你自己的审美判断，不该被写死
- **不做心理战式的"简历技巧"**（比如刻意留白制造焦虑感、用夸张动词堆砌）。这类技巧本质上是在赌 HR 不会认真读，与本仓库"受益人始终是候选人、不操纵筛选系统"这条红线冲突
