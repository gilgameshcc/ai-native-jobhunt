# 04-interview · 面试执行与当天复盘

> **一句话**：把每场面试从一次性事件变成一条反馈边——当天把"被问到什么、哪里讲不通、面试官在乎的和我预设的对不对得上"落成文字，把面试前定下的红旗绿旗回填成**三态**，并留下两栏专门装判据接不住的东西：**对方主动给的、会改变公司判断的事实**（回流疑点表）和**跑题跑出来的东西**（喂发散）。
>
> **版本**：v0.1.4 · 纯 markdown，零可执行依赖 · 入口文件：[`SKILL.md`](SKILL.md)

## 怎么开始

把 [`SKILL.md`](SKILL.md) 整份交给你的 agent（贴进对话、放进项目目录、当系统提示都行），然后告诉它你刚面完哪家公司，把还记得的事说给它听。**这就是全部前置条件。**

不需要 clone，不需要装任何东西，不需要先读完本仓库其他文档，也不绑定某一个 agent 产品。

⏰ **唯一一条时间要求：当天做。** 隔一夜，留下的就只剩结论不剩细节——而这个模块的价值全在细节里（原话、你卡壳的那半句、对方的表情和停顿）。

## I1 三问（模块独立性验收）

### ① 单独用行不行？

**行。** 最小输入是**一场刚面完的面试 + 你还记得的三五件事**。你不需要接受本仓库的简历方法论、投递方法论或定位方法论，也不需要先用过面试前评估模块。

散着说也行——想到哪说到哪，由 agent 整理成复盘卡，不要求你先列好提纲。

⚠️ **但要把话说全：照这个最小形态给，你会拿到一份完整的复盘卡（三问 + ⭐「对方说了什么值得记的」+ 溢出栏 + 问题积累表 + 高风险清单），⛔ 拿不到红旗绿旗那一节能进下游的三态。**（⭐「对方说了什么值得记的」登记的是**对方主动给的**事实，不需要你面试前写过判据，所以它在最小形态下照样能写满。） 三态回填的对象是面试**前**成对写下的 🔴/🟢 判据；事后补的基准一律标 `事后补的基准，可信度低`，不喂给下游做判据校准。想要后者，唯一的办法是面试前把那对判据写下来（自己手写三条也算，**只要是事前写的**）。

### ② 依赖哪些模块的输出？

| 上游文件 | 来自 | 有它会多出什么 |
|---|---|---|
| `assessments/<company>.md` | [`03-company-analysis/interview-strategic-assessment`](../03-company-analysis/interview-strategic-assessment/) | ⭐ **红旗绿旗的对照基准**——你面试前写下的"什么算危险回答 / 什么算好回答"，面试后才有东西可回填 |
| 面试执行一页纸 | 同上 | 现场勾选过的实测栏可以直接誊进复盘卡，少一轮回忆 |
| `positioning.md` | 06 定位模块，或你手写 | 才能判断"面试官关心的点 vs 我预设的定位"对不对得上——没有它，这一栏只能凭印象写 |
| `facts.md`（事实池） | 你自己 | 「已知高风险问题」清单要从它里面挑强主张；没有它就只能凭记忆列 |

**全部是可选增强，没有一项是必需。**

### ③ 缺了上游会退化成什么？

**退化行为不是报错，是降级继续跑，并明确告诉你少了哪一层。**

| 缺什么 | 退化成 | 你会看到 |
|---|---|---|
| 没有 `assessments/<company>.md` | ⭐ **照跑**（[`SKILL.md` §4.4](SKILL.md) 把"那到底还跑不跑"写死了：**跑**），agent 让你**手工列 3 个当时想验证的点**当临时对照 | ⚠️ **但红旗绿旗实测那一栏会失去对照基准**——事后回忆出来的"我当时想验证的"，会不自觉地被你已经听到的答案带偏，等于用结果去写考题。复盘卡里这一栏会**标注"事后补的基准，可信度低"**，且**不喂给下游做判据校准**。⭐ **减偏动作**：先写"我当时担心什么"、写完停笔，再写"结果是什么"——⛔ 顺序颠倒就是事后合理化。⭐ **这 3 个点的真正用途是下一场一页纸的第一稿**，不是检验这一场 |
| 没有一页纸、现场什么都没记 | 只靠回忆重建，问题原话大概率丢失 | 复盘卡里"被问到的问题"一栏会标出哪些是**原话**、哪些是**你转述的**——两者的价值差很多 |
| 没有 `positioning.md` | "面试官关注点 vs 我预设的定位"这一栏填不了 | 不猜。明确写"你预设的定位我不知道，给我 2-3 条就能补完这一节" |
| 没有 `facts.md` | 「已知高风险问题」清单只能从这一场面试里被追问到的点反推 | 会明说这是"事后补的一部分"，不是从事实池系统性扫出来的 |

### ⭐ 还有一条必须先说清楚：你拿到的是**协议，不是题库**

**这个模块发布的是一套复盘协议 + 三张空表 + 填表规则。它里面没有任何一道面试题，也没有任何"高频问题排行"。**

为什么要把这句话写在这么显眼的地方：

- 作者本人工作区里的问题积累表，**只有表头、零填充**；
- 真实面试只有**两场**，全库跟"面试"相关的记录不到十处，其余上百条都停在"已联系 / 等待回复"；
- 唯一一份面试后写下的东西，写的是**对公司的评价**（面试官水平、对产品与技术路线的质疑），**不是自我答题复盘**。

**两场面试归纳不出"哪类问题反复出现"这种模式级结论。** 所以这里不装作有一个经验库——**表是空的，且它本来就该是空的**：它要装的是**你自己**的问题，不是别人的。

> 这符合本仓库"方法论不是数据"的定位。**诚实声明比伪装成熟更能建立信任**——一个号称有"高频问题库"却只有两场样本的模块，第一次被人对照真实经验就会露馅。

## 不做什么

写死边界，防止后来的贡献者把它撑爆：

- ⛔ **不预测面试题。** 不给"这家公司大概率会问 X"。预测面试题需要跨公司的大样本，而这里连"你自己的样本"都才刚开始攒。
- ⛔ **不提供"标准答案"话术库。** 「应该怎么答」那一列是**你自己**根据事实池写的，不是从模板抄的。抄来的答案在追问第二层就会塌——而追问恰恰是这个模块要你记下来的东西。
- ⛔ **不做面试表现打分。** 不输出"本场 72 分"这类数字。分数不承载判断，会把"这三条我答得很稳、那一条我完全没接住"抹成一个平均值——**与 [`05-offer`](../05-offer/) 不出综合分同源**。
- ⛔ **不记录面试官的个人信息。** 记**角色**（技术负责人 / HR / 创始人），不记姓名、履历、社交账号。对公司的判断靠公开信息与现场可观察的行为，不靠对个人的挖掘。
- ⛔ **不替你判断这场面试成不成。** 复盘只负责把事实和落差摆出来。要不要去、几个选项怎么排，交给 [`05-offer`](../05-offer/)。
- ⛔ **不在这里改简历。** 反哺是**建议**，落地在事实池与定位那一侧——见 [`SKILL.md` §7](SKILL.md)。

## 输出与下游

产出一份 `interviews/<公司>-<日期>.md`（模板：[`templates/当天复盘卡.md`](templates/当天复盘卡.md)），字段以 [`docs/module-contracts.md` §6](../../docs/module-contracts.md) 为准：

**被问到的问题（原话优先）· 答得不好 / 被追问的地方 · 面试官关注点 vs 你预设的定位 · 红旗绿旗实测结果（证实 / 证伪 / 未验证 三态）· ⭐ 溢出 / 意外收获**

⭐ **另加一栏「对方说了什么值得记的」**（模板 §4b）：对方主动透露、**会改变你对这家公司判断**的具体事实——它不对应任何一条事先写下的判据（§4 装不下），又因为"结论会变"而按唯一判据**不算溢出**（§5 挡出去）。⭐ **它回流的是面试前评估的疑点表**，不是方向优化的发散侧。⚠️ 这一栏是 v0.1.4 新增的，**尚未进 [契约](../../docs/module-contracts.md) §6 最小字段**——它当前的读者是**下一轮的你自己**。

⭐ 红旗绿旗那一节每条还要带上**它验证的疑点编号 / 必要条件编号**（有上游就照抄 `Q<n>` / `必要条件<n>`，没有就写 `自定：<一句话>`）。⛔ 缺了它，下游分不出一条「未验证」挂的是**必要条件**（判"我去不去"，要紧）还是次要疑点（可以留到下一轮）。

另外两张长期累积的表放在你的工作区里，不是一场一张：

- [`templates/问题积累表.md`](templates/问题积累表.md) —— `日期 | 公司 | 问题 | 我的回答 | 应该怎么答`
- [`templates/已知高风险问题清单.md`](templates/已知高风险问题清单.md) —— 写进简历的任何强主张都等于主动出题

**下游**：offer 模块拿"面试官关注点"与"答得不好的地方"进"发展空间"那一维；方向优化模块拿**红旗绿旗三态**做判据校准、拿**溢出登记**做发散信号。

完整走通一遍的样例：[`../../examples/sample-interview-debrief.md`](../../examples/sample-interview-debrief.md)。

## CHANGELOG

本模块单独版本化。版本语义与仓库一致：**不动 [契约](../../docs/module-contracts.md) 的改动 = patch，动契约 = minor，契约文件被删或改名 = major。**

### v0.1.4

> **来源：一次合成回溯测试（8 个案例）。** 把 8 个已经发生过的求职情境重新灌进当前这套文件，看哪一条会落空。下面三条都是**真的落空了**的缺口。

- ⭐ **§3.2「讲不通」新增第六种形态：「该追没追」**（＋ [`SKILL.md` §3.2.2](SKILL.md) 说明它的修法 · 复盘卡 §2 加勾选项）。
  **为什么改**：原来的五种形态**全部是"我这边出了什么问题"**（没准备好 / 口径不一致 / 数字答不上来 / 被追问后降调 / 说出了待核实区内容）。回测里那一场**最要紧的失误不在这五种里** —— 对方主动给了一件重要的事，用户"哦"了一声就过去了，**这条在旧表里根本没有格子可填**。
  ⭐ **它的修法也不同**：前五种改的是**面试之间**的准备（改表述 / 裁口径 / 备答案 / 去核实），第六种改的是**面试之内**的追问习惯——落点是下一场一页纸上的现场提醒。⛔ 它**不进「已知高风险问题清单」**（那张表收的是"你写了什么招来的问题"，与这一条无关）。
  ⚠️ 它**不会被用户主动报告**：当时那一刻是顺利的（对方在讲、你在听），它只会以"他还提了一句……"的形式顺口出现在复述里，所以 agent 每场要扫一遍。
- ⭐ **新增 [`SKILL.md` §4.5](SKILL.md) + 复盘卡 §4b 一栏「对方说了什么值得记的」**。
  **为什么改**：回测里**本场信息量最大的五条原话全部无家可归**。它们不对应任何一条事先写下的判据（→ 进不了 §4 三态回填），而 §5.4 那条唯一判据（"拿掉它，对这家公司的评估结论会不会变？**会变 → 不算溢出**"）**正确地**把它们挡在溢出栏外——⭐ **判据没写错，错在挡出来之后没有任何一栏接住**。
  现在写死落点与去向：⭐ **回流面试前评估的疑点表**（`assessments/<公司>.md`，更新那家公司的判断），⛔ **不是**方向优化的发散侧——两栏的分工是「改变你对**这家公司**的判断」vs「改变你对**自己**的判断」。同时在 §5.4 的判据旁加了一句指路：**被这条判据挡出去的，去 §4.5，不要丢掉。**
  ⚠️ 这一栏**尚未写进 [契约](../../docs/module-contracts.md) §6 的最小字段** —— 下游模块暂不会来读它，**它当前的读者是下一轮的你自己**（经由疑点表）。下次动契约时应补进去。
- ⭐ **[`SKILL.md` §4.4](SKILL.md) 的自我否定裁决掉了**。
  **为什么改**：原文一边让用户在缺上游时事后列 3 个"当时想验证的点"，一边又明说这样列出来**会被已经听到的答案带偏**，**却没有回答"那到底还跑不跑"** —— 执行者只能自己猜，等于用结果写考题还没人说这算不算数。
  现在写死：**跑**。理由两条：① 这 3 个点的**真正用途不是检验这一场，是给下一场攒判据**；② 复盘卡其余各栏根本不依赖上游判据，为一栏不完整放弃整场是把能拿到的也扔了。产物**只降级不升级**（仍标 `事后补的基准，可信度低`、仍不喂下游校准）。
  ⭐ 新增一条**可执行的减偏动作**：**先写"我当时担心什么"，写完停笔，再写"结果是什么"，两段分开写**；⛔ 顺序颠倒就是事后合理化——**一条永远不会落空的判据，和一条根本没有的判据，是同一回事**。agent 在用户答完第一问之前⛔ **不许复述对方今天说过的任何话**。
- 同步：`SKILL.md` §0 / §1.1 / §1.4 / §5.4 / §7.1 / §7.3 / §9 / §11 · 复盘卡模板 · [样例](../../examples/sample-interview-debrief.md)。
- 未动 [契约](../../docs/module-contracts.md) → **patch**。

### v0.1.3

> **来源：第二轮端到端实跑测试。** 测试者在空白工作区里、只拿仓库文件，把主链路又跑了一遍。下面两条都是实跑中**真的造成了后果**的跨模块契约缺口。

- ⭐ **红旗绿旗回填表新增一列「验证哪条（疑点编号 / 必要条件编号）」**（[`SKILL.md` §4.1.1](SKILL.md) 新增 · [复盘卡模板](templates/当天复盘卡.md)加列 · §4.4 / §7.3 / §9 / §11 同步）。
  **为什么改**：[契约 §4b](../../docs/module-contracts.md) 早就要求定级理由"能追回到具体条件编号"，而 §6 复盘契约**没有对应字段** —— 复盘卡的列是「判据 / 现场听到的 / 三态 / 凭什么这么判」，那一列在**上游的面试前评估文件里**。于是下游（只读复盘卡）看到「某条判据：未验证」时，**完全不知道它挂着一条必要条件**；实跑里那恰恰是全场最要紧的一条（必要条件判的是"我去不去"，比"公司成不成"对本人更要紧）。⭐ **要还原这条链，原本必须联合读两个上游文件，而契约没要求任何一方保留这个指针。**
  无上游评估时这一列写 `自定：<一句话>`，⛔ **不许空着** —— 没有上游不等于这一格可以省。
- **[`SKILL.md` §7.3](SKILL.md) 写明 `未验证` 在下游的口径**：上游标 `未验证` 的判据，下游一律按**"未测得"**处理，⛔ **不得当作"没问题"通过**（[契约 §6](../../docs/module-contracts.md) 新增的第三态降级口径）。挂着必要条件的"未验证"要么补测，要么显式写下"我接受这条没测出来就做决定"。
  **为什么要在契约层写死**：上游花力气把「未验证」和「证伪」分开，就是为了不让它在下游被当成通过。不写这一句，**三态纪律会在最后一米作废**。
- ⚠️ **动了 [契约](../../docs/module-contracts.md) §6 的最小字段 → minor**（不是 patch）。v0.1.0 尚未发布，**因此不产生迁移说明** —— 见契约文档变更日志里那条规则的生效时点。

### v0.1.2

> **来源：一次端到端实跑测试。** 测试者在一个空白工作区里、只拿仓库文件，把主链路真的跑了一遍（面试前评估 → 面试 → 当天复盘 → 反哺）。下面五条全部是实跑中暴露出来、并且**真的造成了后果**的问题。

- ⭐ **§4.3 补充判据 2 第一支放宽**：从「判据里预先写了**答不上来**这一档」放宽为「判据里**预先枚举过的任何一种回应形态**被观测到 → 判 `证实`」（含：答不上来 / **一句具体的回避话术** / 某种特定说法）。同时在 §4.3 开头写死判断顺序：**先查判据枚举，再用一句话判据**。
  **为什么改**：实跑中上游面试前评估模块把两句**具体的回避话术**逐字写进了 🔴，面试官**逐字说出了其中一句**，而 §4.3 的两条判据给出**相反结果**（一句话判据 → `未验证`；补充判据 2 只覆盖"答不上来"，仍落 `未验证`）。**一条真的被测出来的红旗被归成"没测过"**——它既不参与下游校准，也不进下一轮优先项，**这个信号永久消失，而表面上只是多了一格"未验证"**。
  ⚠️ **这是 v0.1.1 那次修复的同一失败类的第二次发生**：上一次修好了「答不上来」一种形态，**漏了「用标准话术挡回来」这一种，而后者才是上游实际写进 🔴 的东西**。
  新增固件：`fixtures/04-interview/三态-回避话术构成证实.{hit,miss}.md`（首跑 hit / miss **同时判 `未验证`**，无区分力；改判据后 hit → `证实` · miss → `未验证`）。
- **§3.2 新增第五种「讲不通」形态**：⛔ **把 `facts.md`「待核实区」的内容当确定的说了出去**。前四种都是"没准备好"（修法是改表述），这一种是**硬约束被破**（修法是回去核实，核不出来就把这句话删掉）。并新增**每场必查的固定检查项**——这一条不能靠用户主动想起来，说的时候通常没意识到。
- **§5.4 的区分判据定为唯一判据**（拿掉它，对**这家公司**的评估结论会不会变），§5.1 的「与本岗位无关」从**必要条件降为典型例子**。
