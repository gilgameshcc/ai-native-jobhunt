# `jd-triage` · JD 结构化与定级

> **v0.1.2** · 属于 `03-company-analysis`，与同目录的 [`interview-strategic-assessment`](../interview-strategic-assessment/README.md)（面试前策略性评估）分工不同、可分别使用。
>
> 一句话：**在投出去之前，先把一份 JD 原文变成一张能追责的结构化表，再按你自己的条件判出四个级别之一。**

---

## ⚠️ 这一版给的是骨架，不是一套调好的参数

请不要把它当成"拿来就能用的定级引擎"。**v0.1 给三件东西**：

1. **抽取模板** —— JD 原文怎么变成结构化表，每一栏的抽取规则，以及抽错了会怎样
2. **定级规则骨架** —— 强匹配 / 较匹配 / 探路 / 不投 四级的定义与**判定顺序**
3. **"怎么定你自己的阈值"** —— 标定方法：从哪几条已投过的岗位反推、先松还是先紧、多久回头校一次

**仓库不给数字。** 所有阈值（薪资线、匹配度线、加分条件命中数）在模板里都是**留空的参数**，并带一个来源等级标注：`实践校准` / `默认建议值` / `纯占位待校准`。v0.1 里它们**全部是 `纯占位待校准`**。

**完整定级模板排在 v0.3**（届时会补：批量 JD 的横向对照表、趋势分析口径、与 `02-apply` 的闸门对接）。在那之前，这个模块靠你手上的 agent 用语义理解来跑，而不是靠一套写死的评分公式。

> 为什么骨架也要现在就发：它是 v0.1 里**唯一服务"我要开始投了"这个状态**的判断层。没有它，仓库 README 的状态路由表里那一行无处可指。

## 它做什么

| | |
|---|---|
| **输入** | JD 原文（只有线索时先主动检索原文，见SKILL主动补齐流程）+ 你自己的必要条件 / 硬性排除条件 |
| **输出** | ① 一张结构化 JD 表（存 `jobs/<日期>-一批说明.md`）② 一个级别：**强匹配 / 较匹配 / 探路 / 不投** ③ **能追到具体条件编号的定级理由** ④ 待确认项清单。②③④ 一批一份，落在 **`triage/<日期>-定级结果.md`**（位置定义见 [`00-workspace` 工作区骨架](../../00-workspace/templates/工作区骨架.md)）——⛔ 不要就地发明文件名，也不要把判断塞回 JD 原文那份文件 |
| **怎么用** | 把 [`SKILL.md`](SKILL.md) 整份交给你的 agent，连同 JD 原文一起 |

### 两条不许简化的判断纪律

这两条是本模块的全部价值所在，规则骨架里的其它部分都可以按你的情况改，这两条不行：

1. **抽取时不做评价，只做客观抽取，原文措辞保留。**
   抽取阶段就下判断，会把 JD 里的原始信号洗掉——后面的定级实际上是在评价一份**已经被评价过**的材料。
   其中 `核心职责` 这一栏的抽取规则**比薪资更能决定要不要去**：它必须能判出两组区分 —— **从 0 搭体系 vs 接手已有系统**、**对内提效 vs 对外产品**。

2. **硬性排除条件不可被匹配度换。**
   薪资、汇报线、权限这类条件是**不可交易的**，不是"权重很高的加分项"。命中任一条 = 直接判"不投"，**短路，不再计算匹配度**。
   > 这与 [`05-offer`](../../05-offer/README.md) 的 gate 是**同一条纪律**：那边是"加分项再多也换不掉一条必要条件"，这边是"匹配度再高也换不掉一条硬性排除条件"。**这条纪律在几个模块里都出现过，犯的是同一类错**——把不可交易的条件当成了可以加权的项。实践里最贵的一次教训就是拿"匹配度很高"去换薪资底线，误投了一批不该投的岗位。

## I1 三问

**① 它能单独拿走用吗？**
能。只要有 **一份 JD 原文 + 你的必要条件与排除条件各 2-3 条**，就能跑完。不要求你先建工作区、先读方法论、先装任何东西。

> ⭐ **但要知道这个最小形态换来什么、换不来什么**：它够**定级**（拿到级别 + 可追编号的理由 + 待确认清单），**不够标定阈值**（所有阈值停在 `纯占位待校准`；「强匹配」与「较匹配」分不开；"我这条排除条件是不是定错了"没有答案）。定级是"用现有标尺量一次"，标定是"检查标尺准不准"——后者要的是**一批你已经做过的判断**，一份新 JD 里没有。详见 [`SKILL.md`](SKILL.md) 的「最小可接受形态」。

**② 它依赖谁？**

| 上游契约文件 | 谁产出 | 本模块拿它干什么 |
|---|---|---|
| [`positioning.md`](../../00-workspace/templates/positioning.md) | `06-positioning`，或你手写（空模板在 `00-workspace`） | 必要条件 / 加分条件 / 硬性排除条件的来源 |
| `jobs/<batch>.md` | `02-apply`，或你手工贴 | 一批待评估的岗位 |
| `branches.md` | `06-positioning` 的发散环 | ⭐ 活跃探路分支——分支下的岗位走**一套更宽的阈值** |

字段定义以 [`docs/module-contracts.md`](../../../docs/module-contracts.md) 为准，本模块不重复定义。

**③ 上游缺了会退化成什么？（退化行为，不是报错退出）**

| 缺什么 | 退化成 |
|---|---|
| 缺 `positioning.md` | **不猜。** 主动问实际存在的必要条件与排除条件，不凑数量——这是全仓最短的必填项。写不出来说明你还没决定在找什么，而不是模块坏了 |
| 缺 `jobs/<batch>.md` | 接受**散着贴进来的 JD 原文**，由 agent 自己整理成结构化表，**不要求你先排好版** |
| ⭐ 缺 `branches.md` | **一律按主线阈值判，探路岗位会被判成"不投"。** 这不是 bug，是缺省的保守行为——但它必须**明确告诉你**："我没看到任何活跃探路分支，**你如果在试新方向，需要手工告诉我**" |

> ⚠️ **缺 `branches.md` 仍然是常态**——`06-positioning` 就在本仓库里（[`modules/06-positioning/`](../../06-positioning/)），但 `branches.md` 只有在你**真的开过探路分支**之后才存在；没跑过它的发散环，这个文件就是不存在的。所以上面第三行不是边角情况，是**默认路径**。这也是本模块唯一一条来自"发散环"的耦合：不给分支放宽阈值，新方向的岗位永远过不了为老方向标定的门槛。

## 不做什么

- **不建设全站采集器。** 用户只给岗位线索时，可以主动检索官网/官方招聘原文并核实出处；平台交互适配仍复用投递模块与适配层。没有取得原文，不假装完成JD抽取。
- ⛔ **不给任何薪资 / 分数的预设值。** 方法论不依赖任何具体数字成立。给你一个默认阈值，等于替你做了一个你没同意的决定，而且你没有任何依据去判断它对不对。
- ⛔ **不做公司层面的深度评估。** "这家公司是不是一层薄封装""它的需求是不是真需求"属于 [`interview-strategic-assessment`](../interview-strategic-assessment/README.md)。本模块只回答"**这个岗位值不值得投**"，不回答"这家公司行不行"。
- ⛔ **不替你决定阈值**，只给标定方法。
- ⛔ **不做无差别大量投递的过滤器。** 定级的目的是产生**真实的 skip**，不是给"看到就投"补一层形式上的手续。
- v0.1 **不提供**完整定级模板、批量横向对照表、趋势分析——排在 v0.3。

### v0.1.2 — 首轮双向断言固件的修复

来源：[`fixtures/jd-triage/`](../../../fixtures/jd-triage/expected.md) 第一次给本模块建固件（**此前一条都没有**），四对全部有区分力（PASS）。**改的两处都不是区分力失败**，而是跑的时候发现"照文档执行时，该放行的那一侧没有判据可依 / 判定完了没有去向"：

- ⭐ **三级收敛期的「降一档」没有取值**。SKILL 只定义了"强匹配→较匹配 / 较匹配→保留但标注关键项未确认"，而 **SKILL 自己写着"首轮的每个人都在三级收敛期"**（〔B 上沿〕`纯占位待校准`）—— 那时只有「匹配」一档，降无可降。**也就是说最常见的那条路径上，这条规则没有可执行的取值。** 已写死：保留「匹配」+ 标注"关键项未确认" + 批内排到同等命中数之后；⛔ 不许因为降不动就把三态压回两态判「不投」。
- ⭐ **排除条件侧的推测项没有去向（落点不对称）**。必要条件第三态明写"降一档 + 挂待确认 + **升级为面试必问项**"，而 §来源标注「推测项不能单独把一个岗位判成「不投」」只写了前两样。已补齐并写明理由 —— **只挂在待确认里、不给去向的推测项，到面试当天不会变成任何一个你问得出口的问题**（与 `interview-strategic-assessment` §8「证实路径那一格空着 = 这条标注等于没标」是同一个失败形态）。
- 未动 [文件契约](../../../docs/module-contracts.md) → **patch**。

### v0.1.1 — 端到端实跑测试的修复

来源：**一次端到端实跑测试**（测试者在空白工作区里只拿仓库文件把主链路真跑了一遍），改的都是"照着文档做会卡住 / 会被迫自己发明规则"的地方：

- **抽取模板新增「⭐ 这条是怎么进来的」一栏**（搜索命中 / 平台推荐 / 对方主动推来 / 中间人转介 / 其他）。它是下游判断"搜索词在不在漂移"唯一的输入，原来 12 栏里没有它——**再多语料也补不出这个字段**。`SKILL.md` 第一步同步说明它的用途，并写明它事后补不回来
- **定级结果有了落点**：`triage/<日期>-定级结果.md`，并写清它与 `jobs/`（原文）、`ledger.md` 的「级别」栏（一个字母）、`assessments/`（面试前评估）四者的边界。实跑中测试者被迫自己发明了一个文件名
- **必要条件补第三态「原文未提及」**：降一档 + 待确认 + 升级为面试必问项，**⛔ 不据此判「不投」**。与排除条件那侧的"推测项不能单独触发不可逆动作"是同一条不对称推理
- **补「加分条件表非空、但上沿还没校准」这一档**（首轮的每个人都在这个状态）：收敛成三级 + 给批内相对排序，并写明它在什么条件下自动解开
- **「最小可接受形态」写清 X / Y**：照最小形态给，拿得到什么、拿不到什么
