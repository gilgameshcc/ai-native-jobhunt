# 定级规则模板（v0.1.1 · 骨架）

> **仓库不给数字。** 本文件里所有 `〔…〕` 都是留空的参数，由你按 §五 的方法自己标定。
>
> 每个阈值都要带一个**来源等级**：`实践校准`（从已投过的岗位反推出来的）/ `默认建议值`（凭判断定的，还没被数据检验）/ `纯占位待校准`（还没定）。**v0.1 出厂时全部是 `纯占位待校准`。**

---

## 一、填之前先分清三类条件

这三类**不可互换**。搞混它们是本模块唯一一个会导致系统性误投的错误。

| 类 | 定义 | 不满足会怎样 |
|---|---|---|
| **必要条件** `N` | 不满足就不投 | **三态**：原文证实 → 满足；原文证伪 → 除非落在活跃探路分支内，否则判「不投」；⭐ **原文未提及 → 降一档 + 待确认 + 面试必问，⛔ 不据此判「不投」**（见 §三之三态） |
| **硬性排除条件** `X` | **不可交易。** 命中即出局 | 命中 → 判「不投」，**短路，不再计算任何匹配度** |
| **加分条件** `B` | 满足越多越好，但**单条不构成否决** | 不满足 → 只影响「强匹配 / 较匹配」的分档，不影响是否投 |

### ⭐ 两条纪律，一条都不能松

1. **加分条件再多也换不掉一条必要条件。**
2. **匹配度再高也换不掉一条硬性排除条件。**

> 这与 [`05-offer`](../../../05-offer/README.md) 的 gate 是**同一条纪律；这条纪律在几个模块里都出现过，犯的是同一类错**——把不可交易的条件塞进了一个加权式子里。只要它和加分项出现在同一个算式中，它就总有一天会被换掉。
>
> ⛔ 因此**不许**出现这些写法：「排除条件命中一条扣若干分」「虽然薪资不达标但匹配度很高，可以试试」「综合评分超过阈值即可投」。

## 二、三张空表（复制走，自己填）

### N · 必要条件（建议 2-5 条；**最少 2 条**）

| 编号 | 条件（用你自己的话写，越具体越好） | 怎么从抽取表里核实 | 来源等级 |
|---|---|---|---|
| N1 | | | |
| N2 | | | |
| N3 | | | |

> 写法提示：**必要条件要能被抽取表里的某一栏证实或证伪**。写不出"从哪一栏看"的条件，说明它还是一个愿望，不是一个判据。
>
> ⭐ **"能被证实或证伪"意味着还有第三种结局：那一栏原文根本没写。** 这一态**不是未满足**，处理方式见 §三之「三态」。写 N 的时候顺手想一句：如果 JD 对这条只字不提，我打算怎么办？想不出来的那几条，最后一定是被默默当成"满足"或"未满足"处理掉的。

### X · 硬性排除条件（建议 2-4 条；**最少 2 条**）

| 编号 | 条件 | 判据（**参数化留空**） | 怎么从抽取表里核实 | 来源等级 |
|---|---|---|---|---|
| X1 | 薪资低于下沿 | 〔下沿〕 | 「薪资原文」栏，**按原文口径比，不折算** | `纯占位待校准` |
| X2 | 汇报线不可接受 | 〔不可接受的汇报关系〕 | 「汇报线 · 团队构成」栏；原文未提及时**不得据此判「不投」**，改为降一档 + 待确认 | `纯占位待校准` |
| X3 | 权限不足以完成职责 | 〔权限底线〕 | 「权限 · 决策范围」栏 | `纯占位待校准` |
| X4 | | | | |

> ⚠️ **X 这张表要一开始就写紧、写死。** 松的是匹配度那一侧，不是排除这一侧（理由见 §五）。
>
> ⚠️ **推测项不能单独触发 X。** 一条标着 `我推测的` 的信息，最多让级别降一档并挂"待确认"，不能直接判「不投」——用猜测去触发一个不可逆的动作，是这个模块最贵的错误形态。

### B · 加分条件（几条都行，**可以为空**）

| 编号 | 条件 | 怎么从抽取表里核实 | 来源等级 |
|---|---|---|---|
| B1 | | | |
| B2 | | | |
| B3 | | | |

> B 表为空是**合法状态**：级别会收敛成三级（「强匹配」与「较匹配」分不开），定级结论里要**明说少了这一层**，而不是假装分得开。
>
> ⭐ **还有一种状态和"表为空"同样处理，而首轮的每个人都在这个状态里**：B 表写了几条，但〔B 上沿〕〔B 中段〕还都是 `纯占位待校准`——**一个没有数值的上沿分不开强 / 较两档**。此时：
>
> 1. **同样收敛成三级**（合并档就叫「匹配」）。⛔ **不许随手编一个上沿把两档劈开**
> 2. **但给出这一批内部的相对排序**（按 B 命中数从多到少），并明说"这是**批内相对排序，不是绝对档位**，换一批 JD 位置会变"
> 3. 每条结论末尾标注：〔B 上沿〕仍为 `纯占位待校准`
>
> **什么时候自动解开**：按 §五 反推出〔B 上沿〕、来源等级从 `纯占位待校准` 升为 `实践校准`（或至少 `默认建议值`）那一刻，四级恢复。触发条件是样本量不是时间——§5.1 的三类样本每类攒够 〔2-3〕 条（`默认建议值`）即可反推；少于这个量级，反推出来的只是把一两条个例写成了规则。

## 三、四级定义与判定顺序

**顺序即纪律，不许调换：**

```
① 先判 X（硬性排除）      命中任一条 → 「不投」→ 短路，停止计算
② 再判 N（必要条件）      ⭐ 三态，不是两态：
                            ├─ 原文证实满足    → 继续
                            ├─ 原文证伪（不满足）→ 查是否落在活跃探路分支内
                            │                      ├─ 是 → 走该分支的更宽阈值 → 可判「探路」
                            │                      └─ 否 → 「不投」
                            └─ 原文未提及      → 降一档 + 待确认 + 面试必问
                                                  ⛔ 不据此判「不投」
③ 最后判 B（加分条件）    仅在 N 全满足时，用来分「强匹配」/「较匹配」
```

### ⭐ 三态：「原文未提及」不等于「未满足」

**JD 不写关键信息是常态**——汇报线、权限、办公方式，多数 JD 都不写。所以 N 这一侧必须有三态：

| 态 | 判据来自哪 | 处理 |
|---|---|---|
| **满足** | 抽取表里有原文**证实** | 继续往下判 |
| **未满足** | 抽取表里有原文**证伪** | 除非落在活跃探路分支内，否则「不投」 |
| ⭐ **原文未提及** | 抽取表这一栏是 `原文未提及` —— **一个待确认项，不是一个判定** | **降一档 + 挂进待确认 + 升级为面试必问项。⛔ 不据此判「不投」** |

「降一档」= 强匹配降为较匹配；较匹配保留但标注"关键项未确认"。**压低优先级，不关门。**

理由与 §二 X 表下那条"推测项不能单独触发 X"**同源**，是同一条不对称推理的两个落点：

- **「不投」不产生任何反馈**（不投、不接触、没有回应），因此**不可逆**——这条判断永远没有机会被证明是错的
- **一份 JD 没写某件事，最常见的原因只是它写得糙**。用"对方没写"去触发一个不可逆的动作，等于把**对方的写作质量**当成了你的判据

⚠️ **反过来同样禁止：不许把「原文未提及」当成「满足」放过去**——那会让结论看起来完整，实际建立在一批没人检验过的默认假设上。**三态压成两态，往哪边压都是错的。**

| 级别 | 判据 | 阈值参数 | 你该做什么 |
|---|---|---|---|
| **强匹配** | 无 X 命中 + N 全满足 + B 命中数 ≥ 上沿 | 〔B 上沿〕`纯占位待校准` | 优先投，值得单独定制材料 |
| **较匹配** | 无 X 命中 + N 全满足 + B 命中数落在中段 | 〔B 中段〕`纯占位待校准` | 投，用通用版本 |
| **探路** | 无 X 命中 + 有 N 未满足**但在活跃分支内** + 满足该分支的更宽阈值 | 见 §四 | 投，计入该分支配额，到分支截止日一起复盘 |
| **不投** | 命中任一 X（**最高优先级，无条件**）；或**任一 N 未满足**且不落在任何活跃探路分支内 | 无参数（见下方 ⛔） | 不投，**但理由要写进台账**——「不投」也是数据 |

> ⛔ 这里**没有"缺口上限"参数** —— 一旦允许"缺几条还能过"，N 就变成了加权项，正是 §一那条"X 不可交易、不许把它塞进同一个加权式子"要防的那件事。分支豁免哪几条 N，写在 `branches.md` 里，是**显式豁免**，不是缺口预算。

### 定级结论的固定形状

**每条理由必须指向至少一个条件编号。** 指不到就写"指不到"，然后回抽取表看哪一栏是空的。

**写到哪**：一批一份 `triage/<日期>-定级结果.md`（日期与 `jobs/<日期>-一批说明.md` 对齐；位置定义见 [`00-workspace` 的工作区骨架](../../../00-workspace/templates/工作区骨架.md)）。里面每条至少三样：**级别 + 可追编号的理由 + 待确认项**。`ledger.md` 的「级别」栏只留**一个字母**，它装不下理由；理由留在这份文件里。**判成「不投」的也要写进来**——它是 §五 校准里最重要的一类样本。

合格（虚构示例）：

> **青栈网络 / 数据平台负责人 → 不投**
> 命中 **X1**（薪资原文的下沿低于你写的下沿）→ 短路，未继续计算匹配度。
> 补充（不参与判定）：N1 N3 满足；N2 待确认——「汇报线」栏为 `原文未提及`。

> **纬度智能 / 智能文档处理产品负责人 → 强匹配**
> 无 X 命中；N1 N2 N3 全满足；B 命中 B1 B2，达到〔B 上沿〕。
> 核心职责栏指向**从 0 搭体系 + 对外产品**（原句：「牵头建立面向客户的文档解析能力」）。

> **恒平科技 / 内部效率平台负责人 → 探路**
> 无 X 命中；**N2 未满足**（行业方向不在主线内），但落在活跃分支「向企业内部效率方向试探」内，满足该分支的更宽阈值。计入该分支配额。

不合格：

> ~~综合看比较匹配，建议可以投一下。~~ ← 指不回任何条件编号，既无法复核，也无法用来校准阈值。

## 四、探路分支：一套更宽的阈值

上游是 `branches.md`（由 `06-positioning` 的发散环产出）。字段定义以 [`docs/module-contracts.md`](../../../../docs/module-contracts.md) 为准。

**为什么必须有这一层**：不给分支放宽阈值，新方向的岗位**永远过不了为老方向标定的门槛**，发散环等于白开。

| 分支 | 更宽在哪（**参数化留空**） | 不放宽的部分 |
|---|---|---|
| 〔分支描述〕 | 可豁免的必要条件编号：〔N?〕· B 上沿下调到：〔…〕 | ⛔ **X 一条都不放宽。** 探路不是降低底线，是允许"做的事不一样"，不是允许"条件更差" |

### ⭐ 缺 `branches.md` 时的降级行为（默认路径）

`06-positioning` 就在本仓库里（[`modules/06-positioning/`](../../../06-positioning/)），但 `branches.md` 要跑过它的发散环、真的开过一条探路分支才会存在，所以**大多数人跑这个模块时是没有 `branches.md` 的**。此时：

- **一律按主线阈值判** → 探路岗位会被判成「不投」
- **这不是 bug，是缺省的保守行为**
- 但必须**明确告诉用户**一句：
  > "我没有读到任何活跃探路分支，所以全部按主线阈值判。**你如果在试新方向，需要手工告诉我**——描述一句这条分支是什么、可以豁免哪条必要条件、什么时候截止。"
- 用户口头给出的分支，**当场整理成 `branches.md` 存回去**（L2 沉淀），下次直接命中

> ⚠️ 一条没有**证伪判据**和**截止日期**的探路分支，就是一个无限期的资源漏洞。用户只说"我想试试新方向"时，要把这两项问出来再开分支。

## 五、⭐ 怎么标定你自己的阈值

### 5.1 从哪几条已投过的岗位反推

不要凭空想一个数。取三类样本，每类几条即可，按抽取模板抽成表，然后问：**要让我当时的判断成立，阈值得设在哪？**

| 样本 | 它告诉你什么 |
|---|---|
| ① 投了、且对方有回应的 | 你的**实际命中区**在哪 |
| ② 投了、但事后后悔的 | 你**漏写了哪条 X**——后悔的那个理由，逐字就是那条排除条件 |
| ③ ⭐ 犹豫很久、最后没投、但一直惦记的 | **最有价值的一类。** 它标出的是你**真实的下沿**，而不是你以为的下沿。你写下的条件往往比真实底线更严，这类样本是唯一能发现这件事的入口 |

反推出来的填 `实践校准`；凭判断定的填 `默认建议值`；还没定的保持 `纯占位待校准`。**三挡要如实标**——把 `默认建议值` 标成 `实践校准`，等于给自己伪造了一份并不存在的证据。

### 5.2 先松后紧，不是先紧后松

**默认先松。** 代价是不对称的：

- **先紧的代价不可回收**：被判「不投」的岗位不产生任何反馈（不投、不接触、没有回应），阈值从此校不动。这是一个**自我封闭的错误**——越紧，越看不见自己错在哪
- **先松的代价可回收**：无非多读几份 JD、多写几条「不投」的理由，而这些恰好是下一轮校准的样本

**唯一的例外：X 表反过来，一开始就要写紧、写死。**

松的是匹配度那一侧，**不是排除那一侧**。把这两侧搞反是最常见的误用，结果是"什么都投得出去，但底线也守不住"——正好是这个模块要防的那件事。

### 5.3 多久回头校一次

**按新增样本量触发，不按时间。** 时间到了但样本没增加，校准只是在重新解释同一批数据。

三个**强制**校准时机（不等样本量）：

1. **连续多条「强匹配」零回应** —— 要么抽取错了，要么阈值标在了一个与市场无关的位置
2. **一条探路分支开启或关闭时** —— 分支的更宽阈值与主线阈值必须一起看，否则会漂移成两套互不相干的标准
3. **你的必要条件本身变了** —— 旧阈值全部作废，回到 `纯占位待校准`。**不要拿旧数字硬套新条件**

### 5.4 校准记录（每次校准追加一行）

| 日期 | 改了哪个阈值 | 从 → 到 | 依据（哪几条样本） | 新的来源等级 |
|---|---|---|---|---|
| | | | | |

> 没有这张表，你三个月后会记得阈值是多少，但不会记得**为什么是它**——于是也就无法判断它该不该改。
