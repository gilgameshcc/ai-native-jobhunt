# JD 抽取模板（v0.1.1）

> 一份 JD 一张表。**抽取阶段不做评价，只做客观抽取，原文措辞原样保留。**
>
> 用法：整表复制走，逐栏填。填不出来的写 `原文未提及`，**不要推一个像是那么回事的答案填进去**。

---

## 一、空表（复制这一块）

```markdown
### <公司> / <岗位>

| 栏 | 内容 | 来源标注 |
|---|---|---|
| 公司 | | |
| 岗位名称（**原文标题**） | | |
| 城市 / 办公方式 | | |
| 薪资原文（**不折算**） | | |
| 学历 · 年限要求 | | |
| 技术与能力要求 | | |
| ⭐ 核心职责（原文原句 + 指向哪一组区分） | | |
| 汇报线 · 团队构成 | | |
| 权限 · 决策范围 | | |
| 招聘方身份（直招 / 中间人转述） | | |
| ⭐ 这条是怎么进来的（搜索命中 / 平台推荐 / 对方主动推来 / 中间人转介 / 其他） | | |
| 链接 · 抽取时间 | | |
| **原文未提及项清单**（→ 面试必问） | | |
```

来源标注三挡：`你给的` / `公开可查` / `我推测的`。**每条 `我推测的` 都要附一句"要证实它，你该问谁 / 查什么"。**

## 二、逐栏抽取规则 + 抽错了会怎样

### 公司

**抽取规则**：写原文里出现的主体名称。如果 JD 是中间人转述的、没写公司名，写"未披露"并在"招聘方身份"里标明——**不要去猜是哪一家**。

**抽错了会怎样**：同一家公司的多条岗位会被当成不同来源，横向比较（v0.3）时的去重会失效。

---

### 岗位名称（原文标题）

**抽取规则**：**原文标题原样抄**，包括那些看起来多余的后缀和前缀。你觉得"这不就是 XX 岗吗"的时候，正是不许改的时候——招聘方选的那个词，本身就是信息。

**抽错了会怎样**：把原文标题归一化成你熟悉的叫法，会**抹掉招聘方的自我定义**。而"对方怎么称呼这个岗位"和"你怎么称呼自己"之间的差距，正是后续复盘要看的东西。

---

### 城市 / 办公方式

**抽取规则**：城市按原文；办公方式（现场 / 混合 / 远程）只在原文明确写了时才填，写了几天到岗就抄几天。原文没写就是 `原文未提及`。

**抽错了会怎样**：这一栏最常见的错是把"没写"当成"默认现场"。它通常是一条硬性排除条件的判据，**用默认值填等于用猜测触发排除**。

---

### 薪资原文（不折算）

**抽取规则**：**原样抄。** 不折算、不换算周期、不取区间中点、不补"大概"、不把浮动部分并进固定部分。原文怎么写就怎么记，包括"面议""视能力而定"这类非数值表述。

以图片形式渲染的薪资（部分平台如此），抄下你看到的原样文本，并在来源标注里注明它来自图片而非可选中的文本。

**抽错了会怎样**：一旦折算，**你的排除条件就对不上口径了**——排除条件是照着原文口径写的。更糟的是你从此分不清"对方给的是一个区间"和"你自己算出来的一个点"，而这两者在谈的时候是完全不同的处境。

---

### 学历 · 年限要求

**抽取规则**：原文怎么写就怎么记，区分"要求"和"优先"——这两个词在 JD 里是两种不同强度，合并就丢了强度。

**抽错了会怎样**：把"优先"记成"要求"，会让一批本来能投的岗位被自己关在门外，且因为不投就没有反馈，你永远不知道这条阈值定错了。

---

### 技术与能力要求

**抽取规则**：逐条列，保留原文措辞与顺序。**顺序是信息**——排在前面的通常是真正卡人的那几条。不要合并同类项，不要把三条含糊的写成一条清楚的。

**抽错了会怎样**：合并与重排会让"这份 JD 到底最在意什么"变得不可见，加分条件的命中判定随之失真。

---

### ⭐ 核心职责（这一栏比薪资更能决定要不要去）

**抽取规则**：摘出原文里能支撑**两组区分**的句子，贴原句，然后标它指向哪一组。**只贴句子和指向，不下结论。**

| 区分 | 原文里往哪看（看动词，不看名词） |
|---|---|
| **从 0 搭体系 vs 接手已有系统** | 前者：搭建 / 建立 / 从无到有 / 定义流程 / 组建 / 牵头。后者：维护 / 迭代 / 优化现有 / 承接 / 保障稳定 / 支持 |
| **对内提效 vs 对外产品** | 前者：内部效率 / 支持业务团队 / 降本 / 提效 / 赋能。后者：面向客户 / 商业化 / 付费用户 / 对外交付 / 营收 |

两组都判不出时，写 `原文未提及` 并进"待确认"清单。**这本身就是强信号**：一份说不清自己要人干什么的 JD，往往对应一个还没想清楚的岗位。

填法示例（虚构）：

> 原句：「负责数据平台的日常维护与迭代，保障核心链路稳定」→ 指向**接手已有系统**
> 原句：「支撑内部各业务团队的取数与分析需求」→ 指向**对内提效**
> `公开可查`

**抽错了会怎样**：这一栏错了，**后面所有定级都是在对着一份被你自己改写过的 JD 打分**，而且错误不可见——因为原文已经不在表里了。薪资谈得动，做的事换不动；这一栏是整张表里唯一无法在入职后修正的部分。

---

### 汇报线 · 团队构成

**抽取规则**：只填原文明确写了的。JD 极少写清汇报线，所以这一栏**大概率是 `原文未提及`**——那就写它，并自动进"待确认"。

**抽错了会怎样**：汇报线常常是一条硬性排除条件。如果你填的是 `我推测的`，而它又触发了排除，你就用一个猜测把一个岗位不可逆地关掉了（见 SKILL「来源标注」里的那条纪律：**推测项不能单独判「不投」**）。

---

### 权限 · 决策范围

**抽取规则**：原文里关于"能定什么、能调动什么、预算归谁"的句子，原样摘。没有就是 `原文未提及`。

**抽错了会怎样**：与汇报线同类——它是"从 0 搭体系"那一组区分的实际约束条件。职责写着"搭建"但权限一栏空白，这个组合本身要记下来，它是面试里最值得问的一个点。

---

### 招聘方身份（直招 / 中间人转述）

**抽取规则**：只分两类：**直接来自招聘方的原文** / **经中间人转述**。转述的要标明信息可信度等级，并注意转述过程中已经发生过一次改写。

**抽错了会怎样**：把转述当原文抽，等于在"抽取不做评价"这条纪律的**上游**就已经破了一次——你保留的是别人的措辞，不是招聘方的措辞。

**漏填会怎样**：这一栏空着，转述件和原文件在表里**长得一模一样**——下游会拿中间人的措辞去判"必要条件满不满足"，而它已经被改写过一次。而且它**事后补不回来**：过两周你不会记得这条是招聘方自己挂的还是别人转给你的。⚠️ 连带丢的还有 `ledger.md` 的「反向吸引」标记（对方主动来找你的那些正是从这一栏认出来的）。

---

### ⭐ 这条是怎么进来的（搜索命中 / 平台推荐 / 对方主动推来 / 中间人转介 / 其他）

**抽取规则**：五选一，填**实际发生的路径**，不是你事后觉得合理的那个路径。

| 取值 | 什么时候用 | ⭐ 还要一起记什么 |
|---|---|---|
| `搜索命中` | 你自己搜出来的 | **把搜索词原样记下来。** 那个词是后面判断"你的关键词在不在漂移"的比对基准；只写"搜索命中"等于只记了一半 |
| `平台推荐` | 你没搜它，是被推到眼前的 | 它出现在哪一类位置（首页流 / 相似岗位 / 提醒消息），记得住就记 |
| `对方主动推来` | 招聘方或中间人直接找上你 | 对方说他是从哪找到你的（如果说了）。这一条同时要在 `ledger.md` 的「反向吸引」栏打标记——两处记的是同一件事的两个侧面 |
| `中间人转介` | 熟人 / 前同事转过来的 | 转介人那句"我觉得这个适合你"的原话。别人凭什么把它和你联系起来，本身就是信号 |
| `其他` | 不属于上面四类，或你确实想不起来了 | 把你记得的那半句写上。**`其他` 是合法取值；猜一个具体来源填进去不是** |

分不清 `搜索命中` 和 `平台推荐` 时（比如搜完之后在结果页下面刷到的），按**"这个词不是我主动搜的"**那一侧填 `平台推荐`——后面要看的正是那些不是你自己找来的条目。

来源标注写 `你给的`。**这是全表唯一一栏记的不是 JD 内容、而是"你和这条 JD 之间发生了什么"的栏**，所以它不受 §三 那条自查（"表里有没有 JD 原文里找不到的词"）约束。

**抽错了会怎样**：**这一栏是下游判断"你的搜索词是不是在漂移"唯一的输入。** 漏填的那些条目，在后面的方向复盘里**等于不存在**——不是权重低，是根本不进样本。所以它不是一个可有可无的来路登记：**攒够再多条语料，只要这一栏是空的，"市场把我的画像投到了哪个邻接方向"这个问题就永远不可判。那不是量的问题，是字段就没记。**

它还有一个不可补救的性质：**事后补不回来。** 一周之后你不会记得某一条是自己搜出来的还是被推到眼前的——而这两者指向完全相反的解读：前者反映的是**你的关键词**，后者反映的是**别人眼里的你**。

---

### 链接 · 抽取时间

**抽取规则**：来源链接 + 抽取当天日期。JD 会被改、会下架，抽取时间是你唯一能证明"当时看到的是这样"的东西。

**抽错了会怎样**：复盘时无法区分"我判错了"和"这份 JD 后来改了"。

**漏填会怎样**：这条 JD 从此**不可复核**——面试前想再看一眼原文没有入口（JD 常被改、被下架），复盘时也说不出"我当时看到的是哪一版"。于是每一次"判错了还是它改了"的争议都只能按**"我判错了"**结案，而那正是会让你去改一条本来没错的阈值的那种错。

---

### 原文未提及项清单（→ 面试必问）

**抽取规则**：把上面所有填了 `原文未提及` 的栏汇总到这里。**这一栏空着才可疑**——JD 从来不写全。

凡是你想知道而原文没写的，**升级为面试必问项**，交给 [`interview-strategic-assessment`](../../interview-strategic-assessment/README.md)，而不是当作"应该没问题"放过去。

**抽错了会怎样**：这一栏被跳过时，那些"没写"的地方会被沉默地当成"满足"处理。定级结论看起来很完整，实际上是建立在一批未经检验的默认假设上。

---

## 三、一条自查

抽完之后问自己一句：**这张表里有没有一个词，是 JD 原文里找不到的？**

有 → 回去重抽那一栏。没有 → 可以进第二步定级了。

> **唯一的例外是「这条是怎么进来的」那一栏**：它记的不是 JD 的内容，而是你和这条 JD 之间发生了什么，来源标注是 `你给的`。自查时跳过它——但**不许因此漏填它**，理由见上面那一栏的"抽错了会怎样"。
