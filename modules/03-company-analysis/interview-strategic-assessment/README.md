# interview-strategic-assessment · 面试前策略性评估

> **一句话**：面试之前，用四个框架把这家公司过一遍，把"说不通的地方"变成一份你当场问得出口、也真拿得到答案的问题清单。
>
> **版本**：v0.1.4 · 纯 markdown，零可执行依赖 · 入口文件：[`SKILL.md`](SKILL.md)

## 怎么开始

把 [`SKILL.md`](SKILL.md) 整份交给你的 agent（贴进对话、放进项目目录、当系统提示都行），然后告诉它公司名和岗位 JD。**这就是全部前置条件。**

不需要 clone，不需要装任何东西，不需要先读完本仓库其他文档，也不绑定某一个 agent 产品。

## I1 三问（模块独立性验收）

### ① 单独用行不行？

**行。** 这是全仓最容易独立起跑的模块之一——最小输入是**公司名 + 岗位 JD**，两样都是你已经有的东西（不然你也约不到这场面试）。

你**不需要**接受本仓库的简历方法论、投递方法论或定位方法论。只用这一块，产出也是完整的：一份评估报告 + 一页纸问题清单。

⭐ **但要说破这一栏的落差**（v0.1.2 起写进 [`SKILL.md` §1](SKILL.md)）：

- **照最小形态给，你拿得到**：完整的四框架疑点表、分层问题清单（每条带可答性标注与提问对象）、红旗 / 绿旗成对判据、"公司成不成"的初判 + 一页纸
- **拿不到**：① "我要不要去"的结论（缺你的必要条件）② 下游 [`04-interview`](../../04-interview/) 能逐条回填三态的判据 —— 只凭 JD，绿旗容易写成"回答清晰"这种形容词，复盘时两边都打不了勾
- **补上这两样就能拿到**（不到五分钟）：2-3 条必要条件 / 硬性排除条件 + 这场面试见谁

⭐ **v0.1.1 起：`SKILL.md` 零硬依赖。** 最终报告的字段规格已内联进 [`SKILL.md` §11.1](SKILL.md)，[`docs/module-contracts.md`](../../../docs/module-contracts.md) 降为**补充读物**（只有你要接下游模块时才需要看）。此前它是全文唯一一处"必须读另一个文件才能确定交付物"的地方。

### ② 依赖哪些模块的输出？

全部是**可选增强**，没有一项是必需：

| 上游文件 | 来自 | 有它会多出什么 |
|---|---|---|
| `positioning.md` | 06-positioning，或你手写 | 让评估从"这公司怎么样"变成"这公司对**你**怎么样"——必要条件 / 加分条件 / 硬性排除条件可直接接进决策分离那一步 |
| `jobs/<batch>.md` | 定级那一步整理好的岗位原文，或你手工贴 | 省掉一轮整理（**只省整理，不带判断**——判断走「上游定级结果」）。已进 SKILL 的开跑前输入表 |
| 定级结果文件（见 [`jd-triage`](../jd-triage/) 模块的产出说明） | 03-company-analysis/jd-triage | 上游判出的**级别**与它标出的**待确认的必要条件**直接进本模块的输入表，不用你手工搬；报告里还会记一行"上游判的是什么、本次改没改、为什么" |

### ③ 缺了上游会退化成什么？

**退化行为不是报错，是降级继续跑，并明确告诉你少了哪一层。** 逐项：

| 缺什么 | 退化成 | 你会看到 |
|---|---|---|
| 没有 `positioning.md` | 只做"公司成不成"这一半，**"我要不要去"那一半停在结论边上** | 报告末尾明确写："你的必要条件与排除条件我不知道，去留判断我不替你下。给我 2-3 条我就能补完这一节" |
| 没有 JD 原文，只有公司名 | 问题清单**只到公司层，到不了岗位层**（问不出"这个岗位是新增还是替补""汇报给谁"这类） | 报告标注"岗位层判断缺失"，并把这几条升级成 HR / 中间人必问项 |
| 没有中间人转述、没有任何内部信息 | 全部结论只由**公开可查**与**我推测的**两级构成，没有一条是"你给的" | 每条推测项后面附"要证实它，你该问谁 / 查什么"——**这正是问题清单的主要来源之一**，不是缺陷 |
| 没有上游定级结果 | 从零判一次级，不参照任何上游结论；上游标"待确认"的必要条件不会自动进清单 | 报告「上游定级」一行写 `无上游 / 本次从零判级`。⚠️ 这一栏空着不影响跑通，但接了上游就别再手工搬运 |
| **agent 没有联网 / 检索能力** | 业务澄清五法从"查 + 问"退化成"全靠问"；公开材料层为空 | 报告顶部一行 `本次无公开检索能力`；本该查的**全部升级为面试必问项**；相应条目标 `我推测的` 并在证实路径里注明"因无法检索而未核实"；可信度分级只剩 `你给的` / `中间人转述` 两档。**不报错，降级跑**（[`SKILL.md` §1](SKILL.md)） |
| 什么公开信息都查不到（早期公司、无媒体报道） | 四框架仍然跑，只是每个框架下的疑点从"材料对不上"变成"这一层完全空白" | **空白本身进疑点表**，并升级为必问项。⚠️ 查不到 ≠ 没法准备，恰恰相反：查不到的东西是"只有当面才拿得到"的东西，优先级要提到最前 |

> **答不出第 3 问 = 耦合太紧。** 这张表是本模块对 I1 的交代，也是它敢说"单独拿走就能用"的依据。

## 生态位：为什么这一块要单独存在

围绕"面试"这件事，开源生态里已经有三类做得不错的东西，**它们和本模块相邻但不重叠**：

| 相邻的一类 | 它们解决什么 | 它们不解决什么 |
|---|---|---|
| **静态"反问清单"** 类项目（众包积累的通用问题列表，长期维护、多语言） | 给你一份可以套在任何公司身上的通用问题池 | **不针对具体这家公司做研究**——问题不和这家公司的具体宣称绑定，不区分该问谁，不标注某条对应验证哪一层判断，也没有"什么算危险回答"的判据 |
| **候选人故事库 / 素材沉淀**（如行为面试 STAR 素材库） | 把**你自己的经历**整理成能应对各类行为问题的素材 | 焦点在候选人自身，不涉及**对目标公司商业模式做策略性研究** |
| **模拟面试 / 面试准备包**（用简历生成准备包、跑模拟问答） | 帮你**更好地回答对方会问的问题** | 不覆盖"你该主动问什么、如何验证对方的商业模式"这一层 |

另外两个方向的现成材料也只到"读物"层：

- **创业评估框架迁移到求职场景**（"要不要加入一家创业公司"）目前普遍停在**单篇博客文章**级别——读完之后，套用到具体公司仍然全靠你自己手动做，没有沉淀成可复用的方法论资产。
- **AI 时代特有风险透镜**（薄封装、模型上移、效果付费能不能成立）在创投圈讨论很活跃，但检索到的应用场景几乎全是"要不要投资"或"要不要以这个方向创业"，**没有被显式迁移到候选人视角**。

**本模块补的就是这个组合的空白**：

> 对目标公司做证据驱动的策略性研究 → 反推出分层问题清单（带可答性标注）→ 红旗绿旗成对判据 → Kill Switch → "公司成不成 vs 我要不要去"决策分离。

四个框架里前三个是搬运（真需求 / 可持续性 / 阶段），**第四个 AI 时代风险透镜是这里最硬的差异化**——它是前三个框架在 2025 年之前根本没有的维度，而你要面的如果是一家 AI 应用公司，它往往是决定去留的那一层。

## 不做什么

写死边界，防止后来的贡献者把它撑爆：

- ⛔ **不做投资人尽调。** 所有判断维度必须是**你在面试阶段或公开渠道拿得到**的信息。任何需要经营数据细节、内部财务、现金储备这类只有投资人和内部人才拿得到的指标，一律删除或改写成可观察的行为化问题。**这条是本模块的生死线**——见 [`SKILL.md` §2.0 改写对照表](SKILL.md)。一份问出来对方答不了、或者你根本无从核实的清单，比没有清单更糟：它消耗掉你本来就很稀缺的提问预算。
- ⛔ **不做人的背景调查。** 不采集、不整理、不推断面试官或其他候选人的个人信息。核实一个职位的分量靠**公开的职务变动**，不靠对个人的挖掘。
- ⛔ **不管职位是怎么找到的。** 采集属于 02-apply 的范围，且受该模块自己的边界约束。本模块从"你手上已经有一份 JD"开始。
- ⛔ **不做审讯。** 所有基于外部检索得出的疑点，当面都用可回旋的措辞去求证，不用陈述句下判断。材料之间对不上的地方，除非直接影响判断，否则不主动当面戳穿。**这不是礼貌问题，是有效性问题**——一旦对方进入防御状态，你这场面试后面的信息密度就归零了。
- ⛔ **不给分数。** 不输出 0-100 的公司综合分。一个数字会把"我们对这几个判断的把握程度完全不同"这件事抹平。
- ⛔ **不替你做去留决定。** 本模块只负责把"公司成不成"这一半做扎实，并把"我要不要去"的判断条件摆出来；多个选项之间的最终排序交给 [`05-offer`](../../05-offer/)。

## 输出与下游

产出一份 `assessments/<公司>.md`（模板：[`templates/assessments-模板.md`](templates/assessments-模板.md)），字段以 [`docs/module-contracts.md` §5](../../../docs/module-contracts.md) 为准：

**匹配度 · 级别（含上游定级 / 是否修正）· 四框架疑点表（含「证实路径」必填格）· 分层问题清单（每条带可答性标注，🔪 / 🔒 显式标出）· 红旗/绿旗成对判据**

⭐ **一条结构要求贯穿整份产出**：**凡是可能出现 `我推测的` 的表，必须有「证实路径」列**（判据纯字面 —— 这张表的枚举里有没有 `我推测的`）。本模块共三张：四框架疑点表 · 框架 D 表 · 「我要不要去」条件表，外加两处非表形态写在同一格里。见 [`SKILL.md` §8.1](SKILL.md)。

外加一份现场用的 [`templates/面试执行一页纸.md`](templates/面试执行一页纸.md)。

下游：`04-interview` 拿红旗绿旗判据做实测对照（三态：证实 / 证伪 / 未验证）；`05-offer` 拿决策分离结论进排序。

完整走通一遍的样例：[`examples/sample-company-assessment.md`](../../../examples/sample-company-assessment.md)。
