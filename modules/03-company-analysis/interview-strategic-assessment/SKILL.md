## 0. 这个 skill 在干什么

**一条链，五步，顺序不可换：**

```
四框架审视（找"哪里说不通"）
   ↓ 疑点合并去重
业务澄清五法（能查的查掉，查不到的升级为必问项）
   ↓
提问设计（分层 + 可答性标注 + 五个模式）
   ↓ 按提问预算收敛
一页纸（现场用）
   ↓ 面试后回填
决策分离（公司成不成 ≠ 我要不要去）
```

### ⚠️ 全文最重要的一条纪律

**问题是评估的副产品，不是起点。**

不要一上来就想"我该问什么问题"。先想"这家公司在每个框架下站不站得住"，问题会从疑点里自己长出来。

**犯了会怎样**：跳过评估直接列问题，你会得到一份和网上任何一份通用反问清单没有区别的东西——问题不和这家公司的具体宣称绑定，对方给一个标准答案你也听不出好坏，因为你事先没想过"什么算好答案"。这场面试你等于没准备。

## 1. 开跑前

### 你要给我什么

| 输入 | 必需？ | 缺了会退化成什么 |
|---|---|---|
| **公司名** | ✅ 必需 | 缺了没法开始——这是唯一一个真的缺不得的 |
| **岗位 JD 原文** | ✅ 必需（可以散着贴，不用排版） | 只有公司名时先主动检索官方岗位原文；补查后仍没有原文，问题清单才只到公司层，到不了岗位层（问不出"新增还是替补""汇报给谁""这个岗位存在多久了"）。我会把这几条升级成对 HR / 中间人的必问项，并在报告里标"岗位层判断缺失" |
| **`jobs/<batch>.md`**（岗位原文已经结构化过的那份） | 可选 | ⭐ 有它就**不用你再贴一遍 JD**——它是上一步定级时整理好的同一份原文。缺了就按上面那行走：你散着贴，我来整理。⚠️ 它**只省你一轮整理，不带任何判断**——判断在「上游定级结果」那一行 |
| **面试安排**（几轮、见谁、多长时间） | 可选 | 缺了我按最常见的情况假设（一场 60 分钟、面试官身份不明），并在一页纸上按"不确定见谁"给你一份**通用序 + 三份分身序**，你到场再挑 |
| **中间人 / 猎头转述的信息** | 可选 | 缺了少一路交叉核查的信源，可信度分级里"中间人转述"这一档为空。不影响跑通 |
| **你已经查到的公开材料**（官网、产品文档、公开报道、招聘页） | 可选 | 缺了我自己查。你给的和我查的会分别标 `你给的` / `公开可查`，不混在一起 |
| **`positioning.md`**（你的必要条件 / 加分条件 / 硬性排除条件） | 可选，但**强烈建议** | 缺了先集中问你的目标与关键条件，等回答时先做公开分析；补问后仍缺才只做"公司成不成"这一半，"我要不要去"那一半会停在结论边上等你补。见 §7。⚠️ 它同时决定 §5 那一栏不可砍的问题填不填得出来 |
| **上游定级结果**（`jd-triage` 判出的**级别** + 它标出的**待确认的必要条件**；文件位置见 [`jd-triage`](../jd-triage/) 模块的产出说明） | 可选 | 缺了我从零判一次级，不参照任何上游结论；更要紧的是**上游已经标"待确认"的那几条必要条件我看不到**，它们不会自动进问题清单，你会到面试结束才发现漏问。缺它时报告的「上游定级」一行写 `无上游 / 本次从零判级` |
| **我能不能联网检索**（⚠️ 这一条不是给我材料，是开跑前要先确认的**能力**） | ✅ 必需先确认 | §3 业务澄清五法整节依赖公开检索。不能联网时**不报错、降级跑**，退化规则见下面一节 |

**以上缺失项先走下文主动补齐流程**：能查的先查，私人目标先问；只有补查后仍无资料或无检索能力，才采用上述降级。岗位摘要同理，先尝试找原文再把未解决项转为具体提问。

### ⚠️ 不能联网时退化成什么

§3 业务澄清五法**整节依赖公开检索**：交叉核查要找两个独立信源、反证优先于自证要看公开的职务与业务变动、赛马假设要交叉检索客户。上面输入表里那句"缺了我自己查"，前提是**你确实有得查**。

所以开跑前先自查一句：**我这次有没有联网 / 检索能力？** 没有就照下面四条退化，⛔ **不许假装查过**。

1. **所有本该查的，全部升级为面试必问项** —— 这和 §3.3「查不到 → 升级为必问项」是同一条纪律，只是这次缺的不是信息而是**能力**
2. **疑点表里相应条目标 `我推测的`，并在同一行的「证实路径」格里注明"因无法检索而未核实"** —— ⛔ 不许标 `公开可查`：没查过就不是查到的
3. **报告顶部写一行**：`本次无公开检索能力 —— 公开材料层为空，全部结论仅由你提供的材料与我的推测构成`
4. **可信度分级（§3.1）降级**：只剩 `你给的` 与 `中间人转述` 两档能填，`官方公告` / `公开报道` 两档空着。**空着就写空着**，不要用推测把它填上

⚠️ **这不是报错，是降级继续跑。** 一份"全靠当面问"的清单仍然有用，只是每一条都必须靠面试当场拿到答案，**提问预算因此更紧** —— 收敛时按 §5 砍得更狠，也就更依赖 §5 那两栏不可砍的问题。

### ⭐ 最小可接受形态

**公司名 + 岗位 JD。就这两样。**

拿到这两样我就开跑。JD 你直接从招聘页面复制粘贴过来就行，格式乱、有多余的排版符号、职责和要求混在一起——**都不用你管，我自己整理**。

⚠️ **如果你给的是一句话概括，而不是 JD 原文**：视同"岗位 JD"这一条**部分满足**——照常开跑，不报错，但：

- 报告里额外标注一行：**"仅有摘要，任职要求 / 团队信息缺失"**
- 本该从任职要求里读出来的东西（这个岗位要什么能力、汇报给谁、多大的组、新增还是替补），**升级成对 HR / 中间人的必问项**
- ⛔ **不许照着一句话概括自己脑补出一份 JD 原文**

⭐ **照最小形态给，你会拿到什么、拿不到什么**（这一栏以前没说破，结果是"能起步，起不了终点"）：

- **拿得到（X）**：一份完整的评估报告 —— 四框架疑点表、分层问题清单（每条带可答性标注与提问对象）、红旗 / 绿旗成对判据、"公司成不成"的初判，外加一份现场用的一页纸。**这份东西本身是完整可用的，不是半成品。**
- **拿不到（Y）**：① **"我要不要去"的结论** —— 没有你的必要条件，这一节只能停在等你补（§7），而 §5 那一栏不可砍的必要条件验证题也填不出来；② **下游 [`04-interview`](../../04-interview/) 能逐条回填三态的判据** —— 只凭 JD，红绿旗很容易写成形容词（🔴"回答含糊" / 🟢"回答清晰"），复盘时你没法判断这算证实还是证伪，那一栏最后会整列填「未验证」。

**要把 Y 也拿到，再给两样**（加起来不到五分钟）：2-3 条必要条件 / 硬性排除条件 + 这场面试见谁。

⭐ **绿旗必须具体到句子**：*"说得出交付与产品的人数比例，并能讲清楚正在把哪一部分交付工作产品化"* 是判据；*"回答得比较扎实"* 不是 —— 后者到复盘时你只会两边都打不了勾。

### ⛔ 四条禁止（写给 agent 自己）

1. **不许报错退出。** 上游文件缺失是常态不是异常。缺什么就降级跑什么，并在报告里明写少了哪一层。
2. **不许静默自己编。** 查不到的东西标 `我推测的` 并附"要证实它你该问谁 / 查什么"，绝不写成像是查到的。
3. **不许一次只问一个问题挤牙膏。** 要什么一次性列全。用户一次回答完，就该开跑。
4. **不许把该自己解决的整理工作推给用户。** 材料散着贴来 → 自己整理成结构；JD 里职责和要求混在一起 → 自己拆开；公开信息要查 → 自己查。**不要让用户先整理好再给你。**

## 主动补齐信息（进入分析前及遇到关键缺口时）

先读已有材料与定位，不重复问已经给过的事实。把缺口按“会不会改变本次判断”排序，优先处理关键项，不能以一张信息不足清单结束服务。

1. **公开可查的，agent直接查。** 公司官网、产品说明、官方招聘原文及公开公告优先；记录具体URL、材料日期和检索日期。只有公司/职位名或链接时，先尝试找到对应JD；同名不清楚再问，不自行挑一家。补查所得放在独立来源段，不改写原JD的“原文未提及”。
2. **用户才知道的，主动集中问。** 例如希望做什么、不可接受的条件、当前面试阶段、已收到的沟通。可用一句：“我先核实官网与岗位内容；还需要你补充最影响判断的这几项：……”。问题按实际缺口生成，不为填满固定数量追问，不要求用户重排材料。
3. **边问边做独立工作。** 等用户时整理公开事实、列条件性分析和最值得验证的问题；没有回答就保持未知，不把沉默当确认，不以猜测生成硬条件。
4. **查不到时给具体交接。** 写已查入口、失败/冲突和仍需谁回答；网络不可用时明确未查，允许用户提供页面文本。需要岗位内部信息可准备给招聘方的问题，但不代发消息。连续补查没有新增证据时停止泛搜，说明哪条信息才能改变结论。
5. **补齐后重算。** 更新受新证据影响的条件、来源与结论；新事实推翻旧判断要注明原因。无关键缺口就直接分析，不额外设问卷。

本流程主动寻找分析所需材料；新公司机会探索由方向模块承接，不以“必须先提供完整JD”阻断检索。无法找到原文时可做公司层初步分析，但不能虚构JD抽取结果或宣称已完成岗位定级。

## 2. 第一步：四框架审视

### ⚠️ 为什么是四个，不是一个

不同框架抓的问题不同。单一框架单打必然有盲区，而**盲区恰恰是你事后才发现"这我当时怎么没想到"的地方**。

四个框架各自过一遍，每遍只输出一件事：**哪里说不通**。不要在这一步写问题，不要下结论。

> **关于下面各表最后一列「默认可答性（锚点）」**：它给 A / B / C 每一问预设一个档位锚点，目的是让不同 agent 跑出来的标注**大致一致**，而不是各标各的（框架 D 的五条自带标注）。它**是锚点不是结论**——最终标注按 §4.4 三档重新判定；且标 `答不上来本身是信号` 的，**必须同时写清楚问谁**（见 §4.4）。

### 2.0 ⭐ 红线：投资人版 → 候选人版改写对照表

**先读这张表，再读后面四个框架。**

四个框架的原始形态是给投资人用的。投资人拿得到的东西（内部经营数据、现金储备、股东信息、客户合同细节），**你拿不到**。照搬过来只会得到一份你问不出口、对方答不了、你也无从核实的清单。

所以每个框架的每一问，进本 skill 之前都必须过一次改写：

| ❌ 投资人版（拿不到，删或改写） | ✅ 候选人版（面试阶段/公开渠道可得） | 为什么这样改还能用 |
|---|---|---|
| 现金还能撑多久 / 什么时候需要下一笔钱 | **公开招聘页面现在挂着多少个岗位、更新频率如何**；面试时问"未来一年团队规模的计划是什么、这个岗位之后还会再招人吗" | 招聘节奏是少数几个不用问就能看到的观察项，**但它是一个观察角度，不是判据**——三条已知混淆与证伪方式见表下 §2.0.1。答"就招你这一个，看效果再说"和答"这条线今年要搭起来"确实是不同的两件事，但那是**提问的理由**，不是下结论的理由 |
| ⭐ **公司撑不住时，这件事会怎么落到我头上**（欠薪 / 突然收摊 / 没人提前告诉我） | ⭐ **直接问 —— 问的是「你会怎么对我」，不是「你有多少钱」**：<br>*"如果这条线做不起来，你打算怎么处理？会提前多久告诉我？"*<br>*"过去一年发薪有没有延迟过？"*<br>*"社保和公积金是按实际工资缴的吗？"*<br>可答性 = **`答不上来本身是信号`** | ⭐ **判据不是那个数字，是对方愿不愿意主动说出自己的下行。**<br>一个会说"账上还能撑到年中，撑不住我提前一个月告诉你、不拖你工资"的人，和一个把这个问题绕过去的人，**是两种雇主** —— 而这个区分**候选人当场就拿得到**，不需要任何内部数据。<br>⛔ 但**不要**顺着追问具体金额、轮次或投资人细节：你要的是**他的处理方式**，不是他的财务。 |
| 收入规模是多少、增速多少 | **"最大的增长现在来自新客户还是老客户扩容"** / "最近一个季度签的客户里，哪一个是你们自己最意外的" | 问趋势和结构，不问数字。对方可以答，也愿意答；而结构本身比绝对值更能说明问题 |
| 客户集中度占比多少 | **"如果最大的那个客户明年不续约，团队的计划是什么"** | 把数字问题转成情景问题。答不上来本身是信号 |
| 毛利率多少 | **"每服务一个新客户，交付和调优大概要投入多少人力、多久上线"** | 这是团队日常工作，面试官答得出，且直接回答"这门生意是产品还是项目制" |
| 估值多少、上一轮稀释了多少 | **不问。** 与你相关的那部分（行权价、行权期、离职后行权窗口、有没有加速条款）是 offer 条款，属于 [`05-offer`](../../05-offer/)，是你有权知道的 | 混淆这两者是最典型的越界。前者不关你事，后者写在合同里 |
| 董事会构成 / 投资人是谁 | **不进疑点表。** 公开报道里看到就看到了，但它不产生任何你能问、能验、能据以决策的东西 | ⛔ 不要为它留一个"以后想办法查"的空格子——照本表最后那句"改写不成立的直接删"办 |
| 团队履历的真实分量 | **看谁接任了这个位置**（公开职务变动），而不是挖个人信息 | 见 §3.2 反证优先于自证 |

**改写不成立的，直接删掉这一维**，不要保留一个"等我以后想办法查"的空格子。

⚠️ **犯了会怎样**：这是本模块唯一一条会让整个产出作废的错误。一份混进了投资人指标的清单会造成三重损失——① 你用掉了本来就只够问几个问题的预算 ② 对方会觉得你搞错了自己的身份，面试印象直接受损 ③ 你以为自己评估过了，实际上那几条永远填不上。**评估维度拿不到答案 = 这个维度不存在。**

### 2.0.0 ⭐ 一条容易被上面这张表带偏的读法（2026-08-31 补）

**这张表的左列写的是"你拿不到的**取值**"，不是"不许碰的**话题**"。**

一次回溯测试里，框架把「公司会不会撑不住」这个**话题**整个按左列删掉了 —— 而那一次真正起决定作用的信号，恰恰是**创始人主动说出了自己的下行**（还剩多久、撑不住会怎么通知你、不会拖工资）。**红线把候选人最该关心的那一类判断，连同话题一起删掉了。**

**区分方式：**

| | 要什么 | 判定 |
|---|---|---|
| ❌ | 一个**你拿不到的数字**（跑道还剩几个月、ARR 多少、最大客户占比） | **删** —— 你问不出，问出来也无从验证 |
| ✅ | 一个**他对你的处理方式**（撑不住会怎么对我、发薪延迟过没有、按什么基数缴社保） | ⭐ **留，而且常常是最硬的一条** |

后者之所以成立，靠的是本文已有的机制：**它的可答性档位是 `答不上来本身是信号`** —— 你要的不是答案的内容，**是他肯不肯答**。

⛔ **别把红线① 用成"凡是听起来像财务的都不问"** —— **下行风险恰恰是最该属于候选人的那一类判断**，把它删掉就是在替雇主省事。

### 2.0.1 ⚠️ 「招聘节奏 / 招聘构成」这个观察项的边界（§2.0 · A2 · D5 共用）

招聘节奏是少数几个不用问就能看到的观察项，**但它是一个观察角度，不是判据**。三条已知的混淆：

1. **研发与资深岗常走内推 / 猎头，不挂公开页** —— 公开页看到的构成，可能只是"愿意公开招的那部分"的构成
2. **招聘页上的岗位可能几个月不下架** —— 挂着不等于在招，数量与新鲜度都不可靠
3. **扩张性招聘与现金紧张并不互斥** —— 大量在招既可能是钱多，也可能是钱快没了所以赌一把

**要证伪它**：把招聘构成的推论与**产品更新日志节奏**、**案例发布时间分布**交叉；三者不一致时，**招聘构成的结论作废**。

⭐ **三者一致时怎么办**：推论**可用**，进疑点表 —— **但它仍然只是推论**：照样拆两行标注（观察 `公开可查` / 推论 `我推测的`）、照样带证实路径、照样要在面试里当面问。⛔ **不许因为"三源都对上了"就把它升级成硬证据，或直接当成结论用。**
⚠️ 这一支必须写出来，理由和本文件其他地方一样：**一条只写了「什么时候作废」、没写「什么时候可用」的规则，与一条"永远作废"的坏规则，在文本上无法区分。**

⚠️ 凡是用到招聘页的地方（§2.0 那一行、A2、D5），写进疑点表时都要拆成两行来源标注：**观察标 `公开可查`，由它得出的推论标 `我推测的`**。不要把两者合并成一条"硬证据"。

### 2.1 框架 A · 真需求（判断"这是不是一门真生意"）

四问：

| # | 问什么 | 你在公开渠道能看到什么 | "说不通"长什么样 | 默认可答性（锚点） |
|---|---|---|---|---|
| A1 | 客户是**真需求**还是**尝鲜性采购** | 客户案例写的是"我们做了个试点/POC"还是"已经接进日常流程、谁在天天用"；产品文档里有没有权限、审计、导入导出这类**只有真正用起来才会被要求**的功能 | 所有案例都停在试点，没有一个说得出"用了多久""哪个部门每天在用" | 视对象而定，默认 `大概率能答`（问的是具体客户与使用情况，属日常事实） |
| A2 | 看**增速与结构**，不看绝对值 | 产品更新日志的节奏、公开的客户案例发布时间分布；招聘页在招的岗位构成（销售多还是交付多还是研发多）——⚠️ 招聘构成受 **§2.0.1** 约束，是观察角度不是判据 | 案例集中在一年前，之后再无更新。⚠️ "在招的全是交付/实施、研发几乎不招"**不单独成立**：必须与更新日志节奏、案例发布分布交叉，三者不一致时这条推论作废 | 视对象而定，默认 `可能回避`（问到增长结构时对方可能不细说；公开观察那半不消耗提问预算） |
| A3 | **这门生意的钱从谁口袋里来、什么时候来** | 定价页、商业模式（订阅 / 按量 / 项目制 / 效果付费）、有没有公开的合作伙伴与渠道 | 说不清收费方式；或者"现在还免费，先做规模"而团队已经不小 | **问创始人 / 高管**：`答不上来本身是信号`（这是他们本该已经想清楚的）· 问技术负责人：`大概率能答`，但答的是转述，可信度打折 |
| A4 | **人和事对不对得上**（founder-market fit） | 创始团队的**公开职务与业务变动**（⛔ 不挖个人信息） | ⚠️ 这是**一个观察角度，不是判据** —— founder-market fit 与公司成败之间没有可靠的因果证据，事后总能讲通（光环效应：公司成了，什么背景都会被讲成"天生适合"）。**它不单独进疑点表**，只在别的框架已经指出疑点时作为补充说明 | 不单独成题（不进疑点表，也就不产生问题） |

⚠️ **A1 是最容易被叙事掩盖的一条**。"我们有个头部客户"这句话本身不包含任何信息量——它可能是深度绑定，也可能是对方在同时试四家。见 §3.4 赛马假设。

### 2.2 框架 B · 可持续性（判断"这门生意能不能守住"）

七问，逐条改写成候选人可观察的形态：

| # | 问什么 | 面试阶段怎么看 | 默认可答性（锚点） |
|---|---|---|---|
| B1 | 技术是**数量级领先**还是小幅改进 | 让对方讲一个具体场景：同样一件事，用你们和不用你们分别是什么样。**如果差别要靠形容词才说得清楚，通常就不是数量级**。<br>⚠️ **混淆项：说不清楚也可能只是这个人不擅长举例。** 换个人问一遍再下结论，一个人的表述不构成判据 | 视对象而定，默认 `大概率能答` |
| B2 | **时机**对不对（为什么是现在） | 直接问"为什么这件事是现在才能做，两年前不行"。这是个好问题：答得好的公司会很兴奋，答不出的公司会绕 | 问创始人 / 高管，默认 `大概率能答` |
| B3 | 能不能**先在一个小市场里做到最强** | 见框架 C（滩头阵地），两者问的是同一件事的两面 | 同 C3：问创始人 / 高管，`答不上来本身是信号` |
| B4 | **团队**（不是履历，是能不能一起把事做成） | 问协作机制而非评价：产品和研发对需求有分歧时怎么定；上一个大的方向调整是怎么发生的 | 视对象而定，默认 `大概率能答`（问的是机制与发生过的事） |
| B5 | **分销**（东西怎么卖出去） | **问事件不问结构** —— *"最近成的那一单，是怎么找到你们的？"*<br>🟢 说得出一条不依赖创始人的路径 🔴 举的例子全是创始人个人关系。<br>⛔ **不用"在不在招销售"下这个判断** —— 招销售既可能说明销售动作可复制，也可能说明创始人卖不动了，**同一观察两解，不构成判据** | 视对象而定，默认 `大概率能答`（问的是发生过的具体事件） |
| B6 | **十年后的护城河**（改写：三年后别人复制你要多久） | 问"如果一个团队明天照着你们做一个，最难追上的是哪一部分"——实践中这条问下来区分度不错（n=1，未验证） | 问技术负责人，默认 `大概率能答` |
| B7 | 有没有一个**别人不认同的洞察** | 就是 §4.3 的收尾"秘密"问题，放最后问 | 问技术负责人 / 创始人，默认 `大概率能答`；⛔ **不问 HR**（问错对象，答案只能标 `我推测的`） |

⚠️ **B4 的坑**：不要问"你们团队氛围怎么样"。见 §4.3 行为化提问。

### 2.3 框架 C · 阶段（判断"公司现在在哪，讲的案例能不能代表规模化"）

三问：

| # | 问什么 | 面试阶段怎么看 | "说不通"长什么样 | 默认可答性（锚点） |
|---|---|---|---|---|
| C1 | 现有标杆客户是**早期尝鲜者**还是**早期主流** | 尝鲜者的特征：内部有个爱折腾的人推动、买的是"未来"、容忍不完善、通常不走标准采购流程。早期主流的特征：走完整采购流程、要 SLA 和合规、买的是"已经被验证的东西" | 全部案例都是尝鲜者，而对外叙事已经在讲"行业标准" | 视对象而定，默认 `大概率能答`（问的是具体客户，属日常事实） |
| C2 | **完整产品还缺什么**（客户真正用起来，除了你们的产品还需要什么） | 问"客户从签约到真正跑起来，中间还需要谁来做什么" | 答"接上就能用"——几乎不可能是真的，说明对方没有真正陪客户上过线 | 视对象而定，默认 `大概率能答`（这是交付日常） |
| C3 | 有没有**打穿一个滩头阵地** | 问"如果只能保留一个客户类型，你们会选哪一类，为什么" | 答"我们各行各业都有客户"——在这个阶段这是坏消息不是好消息 | **问创始人 / 高管**：`答不上来本身是信号` · 问技术负责人或 HR 时这一档**不成立**（他们本来就不该替公司定这个） |

> **「滩头阵地」是什么** = 一个具体到能说出"**这类客户的共同特征是 X**"的细分市场（例：不是"金融行业"，而是"有内部合规审核岗、每天要处理上百份非标合同的中型保险公司"）。
> **反例**：*"各行各业都有客户"* —— 这就是没有滩头阵地。

⚠️ **这一层最容易被"我们有个大客户"这类叙事掩盖**，也是四个框架里最能预测"你入职后会不会天天做定制交付"的一层。**犯了会怎样**：跳过 C，你会在入职三个月后才发现自己进的是一家项目制公司，而 JD 上写的是产品岗。

### 2.4 ⭐ 框架 D · AI 时代特有风险透镜

**这一层传统框架完全没有覆盖。** 如果你面的是一家 AI 应用类公司，它是**必答项，不是可选项**。

**⭐ 什么算"AI 应用类公司"——最简启用判据**：看**产品核心能力是否直接依赖大模型 / 生成式 AI**。

- **是** → 框架 D **必答**
- **纯规则引擎、传统检索、传统机器学习，大模型只是边角功能或完全没有** → 框架 D **跳过**，并在报告里写明"不适用，因为 <理由>"
- **判不准时按"是"走** —— 跑完发现每条都不适用，再逐条写"不适用"跳过。漏跑的代价比多跑一遍大

⭐ **框架 D 在报告里单独过一遍，是一张表**（模板 §2 第二张）。它的每一行都会带来源标注，因而**它必须和四框架疑点表一样带「证实路径」列** —— 见 §8.1。
⛔ 这张表历史上只有「结论 / 证据 / 来源标注」三列，于是标在这里的 `我推测的`（D1 薄封装、D4 数据飞轮、D5 组织形态是三条最常中招的）**物理上没有一格能写"那怎么办"**。缺列不是执行者偷懒，是表设计漏了。

五条，每条都已经改写成面试阶段可问、且对方**大概率愿意答**的形态：

#### D1 · 模型上移与"薄封装"

**核心命题**：如果下一代基座模型顺手做了这家公司的核心功能，它还剩什么。

- **公开渠道先看**：产品里有多少是模型直接给的，多少是它自己的——数据接入与清洗、工作流与审批、人工审核回路、行业规则与合规、交付与实施、和客户既有系统的集成。**后面这些是模型上移吃不掉的部分。**
- **面试问**：*"最近一次基座模型大版本更新之后，你们产品里哪些部分要重做、哪些反而变得更好用了？"*
- 🟢 **好的回答**：能具体说出"某个模块我们直接删了，因为模型自己会做了；省下的人力投到了 X"——说明他们**主动在做这件事，而且不怕承认**。
- 🔴 **危险的回答**：*"我们不依赖某一家模型"* / *"我们做了很多工程优化"* —— 这两句都是在回避问题本身。前者答的是供应商风险，不是能力上移；后者没有说出任何具体的东西。
- **可答性**：`大概率能答`（技术负责人尤其愿意聊）

#### D2 · 效果付费能不能成立

**核心命题**：按效果收费，在没有中立裁决者的情况下，谁来认定效果。

- **面试问**：*"效果是怎么算的？谁来算？如果客户不认这个数怎么办？"*
- 🟢 好的回答：有明确的、双方事前约定的口径，且说得出争议发生时怎么处理。
- 🔴 危险的回答：*"客户都很认可"* / 口径由自己单方面出具。
- ⚠️ **"从没出过争议"有两种解释** —— 规模还小，或者口径确实清楚到没得争。**追问一句区分**：*"上一次客户对这个数提出不同看法是什么时候？后来怎么处理的？"* 答得出具体事件的是后者，完全举不出例子的更可能是前者。
- **可答性**：`大概率能答`（如果他们确实这么收费）· 若对方不是效果付费模式，这一条跳过，不要硬套

#### D3 · 成本通缩对按量计费的挤压

**核心命题**：基座模型的单位成本在持续下降。如果你按调用量收费，你的收入会跟着一起降。

- **面试问**：*"定价是按调用量、按席位，还是按结果？过去一年你们的单位成本降了不少，价格跟着调过吗？"*
- 🟢 好的回答：意识到这件事，并说得出应对（转向席位制 / 转向结果 / 把降本作为竞争手段主动打）。
- 🔴 危险的回答：没想过这个问题；或者收入结构完全绑在调用量上而毫无察觉。
- **可答性**：`可能回避`（涉及定价策略）——⚠️ **神态只记录，不作判据。** 记下他回避的是**哪一类**问题（定价？人数？客户？），**回避的范围有信息量，回避时的表情没有**

#### D4 · 数据飞轮是真积累还是修辞

**核心命题**："我们有数据飞轮"是这两年被说得最滥的一句话。真飞轮有三个必要条件。

- **面试问**：*"客户数据能用来改进给其他客户的效果吗？合同里是怎么约定的？谁在做标注？"*
- 三个必要条件，缺一不可：① **合同层面的许可**（客户同意数据可被用于通用改进）② **回流路径**（数据真的流回训练/评测集，不是躺在客户自己的库里）③ **有人在标注或有自动化的反馈信号**。
- 🟢 好的回答：三条都说得出，哪怕说的是"我们只在第①条上拿到了一部分客户的许可"——**承认边界比宣称飞轮可信得多**。
- 🔴 危险的回答：*"用得越多越准"* 而说不出机制。
- **可答性**：`大概率能答`（这是工程事实，不是商业机密）

#### D5 · 组织形态本身是否被当成产品

**核心命题**：如果交付人力随客户数线性增长，那它更接近一家咨询公司，只是用了 AI 做工具。**这不一定是坏事，但你要知道自己进的是哪一种。**

- **公开渠道先看**：招聘页上交付 / 实施与研发的岗位构成。⚠️ **受 §2.0.1 约束——这是观察角度，不是判据。** 由它得出的推论必须与产品更新日志节奏、案例发布时间分布交叉；三者不一致时这条推论作废。写进疑点表时：**观察标 `公开可查`，推论标 `我推测的`**，不合并成一条"硬证据"。
- **面试问**：*"团队现在大概多少人在做交付、多少人在做产品？一个新客户从签约到上线，通常要几个人、几周？"*
- 🟢 好的回答：说得出比例，并且能讲清楚"我们正在把哪一部分交付工作产品化"。
- 🔴 危险的回答：交付人数明显随客户线性增长，而对方仍然坚持这是产品公司；或者答不出比例。
- **可答性**：`大概率能答`（这是内部日常，不敏感）
- ⚠️ **这一条对你的日常工作影响最直接**：它决定你入职后是在做产品还是在做项目。

### 2.5 疑点合并去重

四个框架各跑一遍之后，你手上会有一堆"哪里说不通"。现在做三件事：

1. **合并同源**：不同框架经常从不同角度指向同一个疑点（例如 A1 的"全是试点"和 C1 的"全是尝鲜者"其实是一件事）。合并，但**记下它被几个框架同时指到**——被多个框架同时指到的疑点，优先级最高。
2. **删掉拿不到的**：对照 §2.0，凡是改写不成立的，删。
3. **标注每条疑点的**：来自哪个框架 · 现有证据与可信度 · 它如果成立会影响什么。

产出一张**四框架疑点表**。这是评估报告的第一张表，也是后面所有问题的原始素材。

⚠️ **到这一步为止，你一个问题都还没写。这是对的。**

## 3. 第二步：业务澄清五法

多来源材料（中间人转述、公司自述、公开报道、产品文档）之间**几乎必然存在口径不一致**。

⚠️ **这是正常现象，不是刻意造假。** 处理原则一句话：**顺带确认，不当场质疑。**

⚠️ **这一整节依赖公开检索。** 如果你没有联网 / 检索能力，先回 §1「⚠️ 不能联网时退化成什么」按那四条走，再往下读 —— 五法不是作废，是**从"查 + 问"退化成"全靠问"**。

### 3.1 交叉核查 + 可信度分级

同一个事实（职位、公司阶段、竞对身份、团队履历）尽量找到**至少两个独立信源**，并标注可信度：

`官方公告` > `公开报道` > `公司自述` > `中间人转述` > `第三方估算`

⚠️ **`公开报道` 这一档要先分辨是采访还是通稿。** 通稿转载的可信度**不高于** `公司自述`——把它当独立信源，会让"两个独立信源交叉验证"变成**同一个信源数了两遍**。判据：同一时间窗内多家媒体措辞高度雷同（段落顺序、形容词、引语都一样）⇒ **按 `公司自述` 计**，不按 `公开报道` 计。

信息不足就明确写"**待核实**"，不要默认采信任何单一来源。

⚠️ **犯了会怎样**：把中间人转述当成事实写进报告，然后基于它设计了三个问题——面试时对方一句"这个说法不太准确"，你三个问题全废，而且当场没有备用方案。

### 3.2 反证优先于自证

核实一个职位的分量，**看"谁接任了这个位置"往往比看头衔本身更可靠**。继任者是不是同级别的人，能反证这个位置的真实分量——这比自述"我曾负责 XX"硬得多。

同理适用于：一条业务线是不是真的重要（看它现在归谁管、还在不在招人），一个客户是不是真的深度绑定（看有没有公开的联合动作，而不是只出现在案例页）。

⚠️ 只用**公开的职务与业务变动**做这件事。不挖个人信息（见 [README 不做什么](README.md)）。

⚠️ **"问"和"检索"要拆清楚，这两件事经常被混为一谈：**

| 动作 | 可以吗 | 为什么 |
|---|---|---|
| 向 HR / 用人方**问**"这个岗位是新增还是替补？上一任现在在做什么？" | ✅ 可以 | 问的是**雇主自己的组织事实**，由雇主自己决定说到哪一层。这也是 §4.3 ⑤ 的标准行为化问题 |
| 去**检索**某个特定前任现在在哪家公司、做什么 | ⛔ 不可以 | 这是对**个人**的背景调查，无论信息是否公开 |

**冲突的是"检索特定个人的去向"，不是"向雇主提问"。** 别因为怕越界，把该问的那一条也删了。

### 3.3 查不到 → 升级为必问项，不是放弃准备

核心经营信息公开渠道查不到，**不代表"没法准备了"**，而是意味着：

> **这是只有当面才能拿到的信息，优先级要提到最前。**

这是本方法论里最反直觉、也最有用的一条转换：**"查不到"是一个把问题排到前面的理由，不是一个把问题划掉的理由。**

⚠️ 但转换时必须过一遍 §2.0：查不到 **且** 改写后仍然拿不到的（现金储备、内部财务），是**删掉**，不是升级。两者的分界线是"对方能不能答"，不是"我想不想知道"。

### 3.4 对正面宣称做反向压力测试（赛马假设）

材料里越是被强调的东西，越值得反向测一下。

例：材料强调"与某头部客户深度绑定"→ 去查这个客户是不是**同时也在和几家同类公司合作**（赛马），有没有独家条款，公开的合作动作是持续的还是只有签约那一次。

⚠️ **犯了会怎样**：不测，你就会把对方最强的叙事直接当成事实，然后整场面试都在这个前提下讨论——你的判断从一开始就被对方的叙事框住了。

### 3.5 边界：这是研究，不是审讯

**所有基于外部检索得出的疑点，当面问出来时都要用可回旋的措辞去求证。**

- ✅ *"我看到材料里提到 X，我理解的是 Y，是这样吗？"*
- ❌ *"你们说的 X 和公开报道对不上。"*

材料之间对不上的地方，**除非直接影响判断，否则不主动当面戳穿**，自己心里有数即可。

⚠️ **犯了会怎样**：这不是礼貌问题，是有效性问题。一旦对方进入防御状态，你后面所有问题拿到的都是标准答案。**你只有一次把气氛聊开的机会，别浪费在一个不影响决策的口径差异上。**

## 4. 第三步：提问设计

### 4.1 按提问对象分层

不同角色只问 Ta **真正能负责任回答、且身份匹配**的问题：

| 对象 | 问什么 | 不要问什么 |
|---|---|---|
| **技术负责人 / 未来的直属上级** | 技术路线、团队协作与决策机制、D1 模型上移、D4 数据飞轮、B6 护城河、C2 完整产品缺什么 | 融资、公司战略层面的取舍（他答的也是转述） |
| **创始人 / 高管** | 战略、竞对定位、B2 时机、B7 秘密问题、C3 滩头阵地、D3 定价 | 具体技术实现细节（浪费这个人身上最稀缺的东西） |
| **HR / 中间人** | 岗位是新增还是替补、上一任为什么走、团队近期变动、汇报线、面试流程、**其他不方便当面问的敏感项** | 商业模式判断（他们不掌握，答案不可信） |

⚠️ **问错对象，答案的可信度要打折。** 向 HR 问"你们的护城河是什么"，得到的答案只能标 `我推测的`，不能标 `你给的`。

### 4.2 ⭐ 认清真实的提问预算

**一场 60 分钟的面试，留给你提问的时间往往只有 15 到 20 分钟。真正能问透的是六到八个问题。**

⚠️ **上面这几个数字是 `默认建议值`，不是实测常数**，也不是从统计里来的。你自己的面试如果明显更长或更短（例如只有 30 分钟，或者是连续两小时的多轮），**按同样的比例调，并在报告里写明你调成了多少**——不要把它当成一个不可动的阈值，也不要假装它有数据支撑。

"问透"的意思是：问出来 + 听懂回答 + **追问一句** + 心里给它归类。走完这四步才算一个。

所以：

- 问题库要有**明确的优先级排序**
- 最终收敛成**一页纸**（见 §5）
- **不是准备几十个问题指望全问完**

⭐ **两个"六到八"是同一个预算，不要按对象数量叠加。**

§5 写的是"每个对象留六到八条"——那指的是**该对象单独占用一整轮**时的预算。如果一轮里同时见多个对象（技术负责人和 HR 一起进来、创始人中途加入），**仍然按"单场六到八个"来砍**，先按对象分栏，再从各栏里挑出总共六到八条，**不是每栏各六到八条加起来**。

⚠️ **犯了会怎样**：带三十个问题进场，实际结果是你会按顺序问前面几个（而不是最重要的几个），且每个都来不及追问。**一份没有排过序的长清单，等于让"问什么"这件事由时间顺序随机决定。**

### 4.3 六个可复用的设计模式

#### ① Kill Switch 问题

从整个问题池里挑出 **3 到 5 个"答不好就该重新考虑"的问题**。

- 特征：通常对应一个**能直接判生死的二元命题**（这门生意的钱从谁口袋里来 / 这个岗位到底有没有决策权 / 这是产品公司还是项目制公司）
- 分量高于常规问题：**优先问、优先记**
- 如果你时间只够问三个问题，就问这三个

⚠️ **必须事先挑好。** 现场是挑不出来的——现场你只会按纸上的顺序念。

⛔ **Kill Switch 只覆盖"公司成不成"这一半。** 验证你自己必要条件的那几条问题**不在这个池子里**，也**不和 Kill Switch 抢名额** —— 两类并列不可砍，见 §5 收敛顺序第 2 条。只挑 Kill Switch，你会带回一份"这家公司还不错"的结论，却仍然不知道自己去不去。

#### ② 红旗 / 绿旗成对设计

**每个关键问题提前想清楚两件事：危险的回答长什么样，好的回答长什么样。**

写成成对的判据，放进一页纸。

⚠️ **犯了会怎样**：不写，你会在面试中**实时地被说服**——对方给一个流畅、自信、听起来很有道理的答案，你当场点头，回家路上才反应过来"他其实没回答我的问题"。**成对判据的作用是把判断力前置到你还清醒的时候。**

> 🔗 这份判据的下游是 [`04-interview`](../../04-interview/) 的实测对照，三态：**证实 / 证伪 / 未验证**。"没问到""对方回避"都算**未验证**，不算证伪。

#### ③ 收尾"秘密"问题

留一个开放的大问题**放在最后、气氛聊开之后**再问：

> *"你自己觉得，这件事里有什么是行业里大多数人还没意识到的？"*

- 这类问题对技术背景 / 创始人背景的面试官通常比较好接（n=1，未验证）
- 实践中这一段的信息密度不错（n=1，未验证）——但它是**加分项不是必答项**，时间不够就砍，不要为它挤掉 Kill Switch
- 它同时是框架 B7

⚠️ **不要放在开头。** 开头问，对方还在评估你，会给一个安全的、准备好的答案。

#### ④ 主动抛出观点，不只是提问

把研究中形成的判断包装成"**观察 + 求证**"的陈述句主动说出来，而不是只用疑问句。

> *"我看你们的客户案例里，跑得最久的那一类都是有内部推动人的。我猜下一步的难点是怎么卖给没有这种人的组织——是这样吗？"*

这是把"候选人被单向考察"变成"**两个专业人士在讨论问题**"，**本身就是面试表现的一部分**。

⚠️ **前提是你的观察得站得住。** 抛一个基于错误前提的观点，损失比不抛大。所以这一条依赖前面的评估做扎实，不是一个可以单独使用的技巧。

#### ⑤ 行为化提问代替标签化提问

**不要问是非题，问具体发生过的事件。**

| ❌ 标签化（答案永远是"是"，或只会是 JD 的复述） | ✅ 行为化 |
|---|---|
| 你们是不是很扁平 / 很重视沟通？ | 最近一次比较大的意见分歧是怎么解决的？最后谁拍的板？ |
| 你们重视技术投入吗？ | 上一次为了技术债专门排开发时间是什么时候？ |
| 你们的产品迭代快吗？ | 最近一个功能从提出到上线用了多久？中间卡在哪一步？ |
| 这个岗位有成长空间吗？ | 上一个坐这个位置的人现在在做什么？ |
| 你们想要什么样的人？ | 你们心里有没有一个"来了肯定会聊"的人？他做过什么？（见 ⑥） |

⚠️ 最后一行是**向雇主提问**，不是去检索这位前任现在在哪——两者的分界见 §3.2。

⚠️ **犯了会怎样**：标签化问题的答案信息量为零——**没有任何一家公司会说自己不重视沟通**。你消耗了一次提问预算，什么也没换到。

#### ⑥ 问出对方的内部标准（你看到的 JD 不是他们筛人的标准）

**JD 是对外的说明，不是对内的筛选标准。** 用人方手里通常另有一套没写出来的东西：心里那个"来了肯定会聊"的参考人选、哪几条是硬的哪几条进来学也行、JD 里省略掉的地点薪酬工作方式、这个岗位从开始招到现在改过几次。这四样决定你会不会被筛掉，而 JD 上一样都看不到。

四个问法，各自带可答性标注和对象：

| 问法 | 问谁 | 可答性 | 它替你读出什么 |
|---|---|---|---|
| "你们心里有没有一个'来了肯定会聊'的人？他做过什么？" | 技术负责人 / 用人方 | `答不上来本身是信号（问用人方）` | 真实的筛选标准。答不上来说明标准还没想清楚，那就不是你的问题 |
| "JD 上这几条，哪几条是硬的，哪几条进来学也行？" | 技术负责人 / 用人方 | `大概率能答` | 你缺的那一条到底是不是硬伤；也顺便验证 §2 里你自己标的必要条件 |
| "地点 / 薪酬范围 / 远程这几样 JD 没写，是还没定，还是不方便写？" | HR / 中间人 | `可能回避` | 哪些实质条件被有意省略了。回避的**范围**有信息量 |
| "这个岗位从开始招到现在改过几次？改了什么？" | HR / 用人方 | `大概率能答` | 需求稳不稳；改过三次的岗位，你入职后大概率还会改 |

⚠️ **这一条和 ⑤ 的分工**：⑤ 管"别问是非题"，⑥ 管"别把 JD 当标准"。四个问法本身已经是行为化的，不要再套一层。

**一条问法算不算 ⑥，只看一件事**：它的答案能不能读出 JD 上没有的信息。"你们想要什么样的人"字面上也在问人选，但答案只会是 JD 的复述，**不算**；改写成参考人选、硬条件 vs 可培养、省略的实质条件、改过几次这四类之一才算。

⚠️ **犯了会怎样**：你按 JD 上的条件准备了一整套，进场才发现对方真正卡的是 JD 没写的那一条；或者你以为自己差一项硬条件而放弃，其实那一项是"进来学也行"。**两种错都是把 Pitch 当成了 Brief。**

⛔ **不要反过来用**：这四个问法是候选人读雇主的标准，不是替雇主写标准。本仓库不做雇主侧的任何东西。

### 4.4 ⭐ 每条问题必须带「可答性标注」

**这是本模块最重要的一个字段。** 每一条问题都要标注三档之一：

| 标注 | 含义 | 怎么判定 | 怎么用 |
|---|---|---|---|
| `大概率能答` | 这是对方日常工作的一部分，不敏感，问了就会答 | 问的是**机制、流程、发生过的事件、技术事实** | 放前面。这些是你的信息主粮 |
| `可能回避` | 涉及定价策略、内部矛盾、未公开的计划 | 问的是**策略、判断、还没发生的事** | 仍然值得问，但**要为回避准备好接话**（"理解，那换个角度……"）。⚠️ **神态只记录，不作判据**：记下他回避的是**哪一类**问题（定价？人数？客户？），**回避的范围有信息量，回避时的表情没有** |
| `答不上来本身是信号` | 这是他们**应该**知道、但可能真的没想过的事 | 问的是**他们本该已经想清楚的核心命题**（D1 模型上移、C3 滩头阵地、A3 钱从谁口袋来） | 这类问题的价值**不在答案，在反应**。愣住、绕开、把问题还给你——都是数据 |

⭐ **标 `答不上来本身是信号` 的问题，必须同时指定提问对象。**

对错人问，答不上来什么也说明不了——向 HR 问"你们有没有打穿一个滩头阵地"，答不上来是**正常的**，那不是关于这家公司的信号，只是关于你问错了人。

- 写清楚：`答不上来本身是信号（问创始人 / 高管）`
- ⛔ **没写清楚问谁的，这一档不成立**：降级成另外两档，或者删掉
- 同一条问题换个对象，档位就会变（A3 问创始人是 `答不上来本身是信号`，问技术负责人只是 `大概率能答` 而且答的是转述）

#### 为什么必须有这一列

**因为"判断维度必须面试阶段可验证"这条纪律，只有变成这一列，你才看得见、也才能自己确认。**

在此之前它只是一个维护者发布前的自查动作——你拿到清单，无从知道其中哪几条是我替你验过的、哪几条是我拍脑袋加的。**有了这一列，你自己就能判断"这条问题是不是在问我根本拿不到的东西"。**

⛔ **如果一条问题你标不出这三档中的任何一档，说明它根本不该在清单里。删掉。**

⚠️ **犯了会怎样**：没有这一列，清单里会混进"看起来很专业但对方压根不可能回答"的问题（现金储备、具体收入、股权结构）。你会带着它进场，用掉宝贵的提问预算，换回一句"这个不方便透露"，而且**给对方留下"这人搞错了自己的身份"的印象**。

## 5. 第四步：收敛成一页纸

把问题池按下面的顺序收敛（模板：[`templates/面试执行一页纸.md`](templates/面试执行一页纸.md)）：

1. **先分对象**（见 §4.1）——每个对象一栏
2. ⭐ **每栏内按优先级排序：🔪 Kill Switch 问题 与 🔒 验证必要条件的问题「并列」排在最前**，两类同属**不可砍区**（理由见下一节，这是本节最容易被砍错的一条）
3. **每条带**：可答性标注 · 它验证的是哪个框架的哪条疑点（🔒 那几条则写它验证的是哪条必要条件）· 🔴 危险回答 / 🟢 好回答
4. **每栏留一个收尾"秘密"问题**在最后
5. **砍到能问透的量**：每个对象留六到八条（`默认建议值`），再多的进"备用"区，不进主清单。⚠️ 这里的"每个对象六到八条"指**该对象单独占用一整轮**时的预算；一轮里同时见多个对象时，仍按 §4.2 的"单场六到八个"砍，**不按对象数量叠加**。⛔ **砍的时候从不可砍区之外砍起** —— 🔪 与 🔒 两栏不参与砍

⭐ **一页纸的验收标准：你在面试开始前扫一眼就能记住前三条。** 做不到就是还没收敛完。

### ⭐ 为什么"验证必要条件"必须与 Kill Switch 并列，而不是排进通用序

> **Kill Switch 回答的是"公司成不成"，验证必要条件回答的是"我要不要去" —— 这是两个并列的问题（见 §7 决策分离），提问预算必须两边都保。**

⛔ **只保 Kill Switch 的后果**：你会带着一份"这家公司还不错"的结论回家，**却仍然不知道自己去不去** —— 而那条没问的必要条件，加分项再多也换不掉（§7）。

⚠️ **这条是被实跑打出来的，不是推演出来的**：一场只见到技术负责人、提问时间只有十二分钟的面试，按旧规则砍到五条，**恰好砍掉的就是验证必要条件的那一条**（这个岗位平时有多少时间在写代码），而那场面试的去留判断完全压在它上面。旧规则把 Kill Switch 排最前、把必要条件验证题混在通用序里，**与本模块自己的决策分离原则是矛盾的**。

怎么落地，五条：

- **必要条件从哪来**：来自 §1 的输入（你的 `positioning.md`，或你口头给的 2-3 条），**不是 §7 的产出** —— 所以在这一步你已经有它了，不用等面试完
- **一条必要条件至少配一条问题，并写清楚问谁**：汇报线问 HR / 中间人，日常工作构成问技术负责人或直属上级
- **一页纸上给它独立一栏**（模板里的「🔒 必要条件验证题」），标 🔒 = 不参与砍
- ⭐ **一条问题可以同时是 🔪 和 🔒**（例："这是产品公司还是项目制公司"既判公司也判这个岗位），这时它**只占一个名额**，标两个记号即可。⚠️ 但**不要因此认为 🔒 那一栏满了** —— 其余必要条件仍然各自需要一条
- ⚠️ **没有 `positioning.md` 也不许跳过这一栏**：先按 §10 L3 向用户要 2-3 条（两分钟的事）。只有当用户明确说"这次先只看公司成不成"，才允许留空，并在一页纸与报告里都写明 **"本场不验证必要条件 —— 去留判断这场拿不到证据"**，⛔ 不要默默空着

⚠️ **🔒 那几条也要有红旗绿旗，同样具体到句子**。例：🔴 *"说不上来这个岗位平时大概有多少时间在写代码"* / 🟢 *"说得出一个具体的近期比例，并说得出它为什么是这个比例"*。

⚠️ **如果 🔪 加 🔒 已经吃掉预算的大半**（例如只有十来分钟提问时间），那就**只问这两栏** —— 这是收敛对了，不是没准备好。

⚠️ 如果面试安排不明（不知道会见谁），准备一份**通用序**（不管见谁都能问的）+ 三份**分身序**（技术 / 创始人 / HR 各一小栏），到场再挑。**不要为"可能见到创始人"这件事把整份清单都写成创始人版。**

## 6. AI Native 考量：用对方的框架给自己定位

### 6.1 用对方的语言重述自己的经历

如果对方（尤其是技术 / 创始人背景的面试官）在材料或谈话中透露出一套自己总结的概念框架——哪怕只是一句话式的——**主动用对方的语言重述自己的相关经历**，而不是套用你原有的话术。

> **面试不是背履历，是用对方认同的语言框架，重新包装同一组事实。**

⚠️ 这比自说自话地罗列优势更容易建立"这个人懂我们在做什么"的信任，也**证明你真的读过材料**。

### 6.2 你自己的第一手体感就是最好的提问素材

如果你面的是 AI 应用类公司（尤其早期），你**自己在原公司做 AI 相关转型/建设的经历，本身就是含金量最高的提问与观点素材来源**——不需要额外查资料，只需要有意识地把它转译成对目标公司的追问依据。

例：你在自己公司推广 AI 工具时踩过的采纳阻力（同事不愿意改工作习惯、领导要看数字才批预算），**直接对应到目标公司的产品要说服的终端用户是谁、卡在哪一层**。

⚠️ 这是本节最容易被忽略的一条：候选人往往觉得"我那点经验不值一提"，但对早期公司来说，**一个真的推动过内部采纳的人，比一个能背出行业报告的人有用得多**。

## 7. 第五步：决策分离

### ⚠️ 公司成不成 ≠ 我要不要去

前面所有框架和问题的产出，回答的都是**第一个问题**（这门生意站不站得住）。但你真正要做的决策是**第二个问题**（这份经历对我有没有价值）。

**这两者不是同一件事，必须显式拆开。**

| | 公司成不成 | 我要不要去 |
|---|---|---|
| **看什么** | 必要条件有没有硬伤（业务地基）· 四个框架给出的信号是正面还是负面 | **你自己的阶段性目标**：想积累哪类经验、想验证哪个方向 |
| **依据** | 本模块的四框架疑点表 + 红旗绿旗实测 | 你的 `positioning.md`（必要条件 / 加分条件 / 硬性排除条件） |
| **谁来判** | 这个 skill | **你**。我只把条件摆出来 |

⚠️ **这个分离必须在提问预算上也成立，不只在报告结构上成立。** 两列并列 = **两类问题都要占到不可砍的名额**（§5 收敛顺序第 2 条）。只保了左边那一列的提问预算，右边这一列面试完照样是空的 —— 报告结构再对也没用。

### 两个方向都成立的交叉情况

- **公司大概率不成，但仍可能该去**：只要能拿到你要的目标经验，**且下行可控**——现金部分不依赖期权兜底、投入的时间不构成不可挽回的沉没成本。
- **公司看着大概率能成，但可能不该去**：授权不到位、拿不到你想要的经验、这个岗位是替补且上一任因为同样的结构性问题走的。

### 落地成一条简单的决策规则

> **区分必要条件与加分条件。**
>
> - **必要条件**：不满足就不去。通常对应硬伤或底线（薪资结构、汇报线、决策权限）。
> - **加分条件**：满足越多越该去，但**单条不构成否决**。

⛔ **必要条件与加分条件不可互换。加分项再多也换不掉一条必要条件。**

⭐ **「我要不要去」在报告里也是一张表**（模板 §6.2：类型 / 条件 / 这家满足吗 / 依据 / 来源标注）。**它的「来源标注」列同样会出现 `我推测的`，所以它同样必须有「证实路径」列** —— 见 §8.1。
⛔ **不要把证实路径挤进「来源标注」那一格**（写成 `我推测的 → T2` 这样）。挤进去有两个后果：① 那一格同时装着两个轴的东西，扫的时候只会读到前半截 ② 下一条推测写的时候没有一个明显的空格提醒你"这里还欠一句"，规则就静默失效了。**依据列指回问题编号（这条这场会不会被验证），证实路径列说的是要证实这条推论该问谁 / 查什么 —— 两件事，两列。**

⚠️ **犯了会怎样**：这是全仓库出现频率最高的一类错——拿"匹配度很高"去换掉一条底线。这条纪律在 [`jd-triage`](../jd-triage/)、[`05-offer`](../../05-offer/) 与工作区的 `positioning.md` 里都有落点，**犯的是同一类错：把不可交易的条件塞进了同一个加权式子**。

### 交给下游

**多个选项之间的最终排序不在这里做**，交给 [`05-offer`](../../05-offer/)——它会把"留在原地"也作为一列摆上桌，并输出排序 + 翻转点（哪个假设变了排序会翻）。

本模块只输出：**"公司成不成"的结论 + "我要不要去"的判断条件清单**。

⚠️ 如果没有 `positioning.md`，第二列就填不了。这时**不要猜**：明确写出"你的必要条件与排除条件我不知道，给我 2-3 条我就补完这一节"，然后停在这里。

## 8. 来源标注

**报告里每一条结论都必须带一个标注**，三选一：

| 标注 | 含义 | 附加义务 |
|---|---|---|
| `你给的` | 用户提供的事实、中间人转述、面试中听到的原话 | 标明来自哪一路，中间人转述要单独标（它的可信度低于官方公告） |
| `公开可查` | 官网、产品文档、公开报道、招聘页、公开的职务变动 | **必须附来源**。说不出来源的，降级成 `我推测的` |
| `我推测的` | 由证据推导、类比、经验判断得出 | ⭐ **必须附一句"要证实它，你该问谁 / 查什么"**。⚠️ 在**任何**列出结论的表里，它是**同一行里独立的一格**（「证实路径」列），不是另起一段的说明 —— 见 §8.1 与 §11.1 |

> ⚠️ **这三档是「A · 来源标注」轴，贴在结论上。** 本文件里另有一套 `默认建议值` 这样的标签（§4.2 的提问预算数字），那是「B · 参数来源等级」轴，**贴在阈值与参数上，不是贴在结论上**。
> ⛔ **B 不能替 A 出场**：标了"这个数字是建议值"**不等于**标了"这条结论是谁给的"。一条由参数推出的结论（例："所以这次只准备六到八个问题"）如果本身要参与判断，它仍然欠一个 A 轴标注。
> 完整定义见 [`docs/module-contracts.md` §0 五条标注轴](../../../docs/module-contracts.md)——**补充读物，不是前置条件**，上面这两句已经够你在本模块里不出错。

### 8.1 ⭐ 结构要求：凡是可能出现 `我推测的` 的表，必须有 `证实路径` 列

**这不是提醒，是表的结构要求。判据是纯字面的：**

> **这张表的枚举里有没有 `我推测的`** —— 有，就必须有那一列。没有那一列的表，不许往里写 `我推测的`。

⛔ **只在某一张表里有这一列 = 另外几张表里的推测物理上没地方写。** 那时候执行者不是偷懒，是**表设计漏了**：他标了 `我推测的`（标对了），然后发现这一行根本没有一个格子能装"那怎么办"，于是这条推测就永远停在那里。**你不会看到任何空格子，因为那一列压根不存在** —— 这比空格子更难被发现。

本模块里**已知会出现 `我推测的` 的表，共三张 + 两处非表**，全部必须带证实路径：

| 位置 | 形态 | 证实路径写在哪 |
|---|---|---|
| **四框架疑点表**（§11.1 / 模板 §2） | 逐行表 | 独立一列「⭐ 证实路径（问谁 / 查什么）」 |
| ⭐ **框架 D 单独过一遍表**（§2.4 / 模板 §2） | 逐行表 | 独立一列，**与疑点表同名同义** |
| ⭐ **「我要不要去」条件表**（§7 / 模板 §6.2） | 逐行表 | 独立一列，**⛔ 不许挤进「来源标注」那一格** |
| 结论速览的「公司成不成（初判）」格（模板 §1） | 键值对，不是逐行表 | 同一格里紧跟一句 `要证实它：<问谁 / 查什么>` |
| §6.1「公司成不成」的初判那一行（模板 §6.1） | 段落 | 同上，紧跟同一行 |

⭐ **新增任何一张会出现 `我推测的` 的表时，先加列再填内容**，不要先填内容再想"这条写哪儿"。

### 为什么推测项必须附证实路径

因为**这就是问题清单的主要来源之一**。

`我推测的` + "要证实它你该问 X" = 一条候选问题。**§3.3 的"查不到升级为必问项"，本质上就是这条规则的一个特例。**

⭐ **自查一句（写到第五、六条时最容易塌）**：**每一条 `我推测的` 右边那一格空着 = 这条标注等于没标**。标注只说明"这条不硬"，证实路径才说明"那怎么办" —— 少了后者，这一行到面试当天不会变成任何一个你问得出口的问题。

⚠️ **这一条会以两种方式塌，两种都要防**：

1. **随行数衰减**：前几行大家都写得挺全，写到第六行只剩标注、证实路径开始空着。所以它在模板里是**一个必填格，不是一段可选说明**。
2. ⭐ **随表衰减（更隐蔽）**：给一张表加了这一列，就以为规则落地了 —— 而同一份产出里另外两张表根本没有这一列。**只补一张表 = 这条规则在另外两张表里从未存在过。** 收尾自查按 §8.1 那张位置表**逐张点名核对**，不要只看你刚写完的那一张。

⚠️ **犯了会怎样**：不标来源，你会分不清哪些是我查到的、哪些是我猜的，然后**基于我的猜测在面试里说了一句陈述句**。这是最尴尬的翻车方式。

## 9. 不对劲的时候

| 症状 | 最可能的原因 | 你下一句该说什么 |
|---|---|---|
| **问题清单看起来和网上的通用反问清单差不多** | 跳过了 §2 四框架审视，直接开始列问题——问题没有和这家公司的具体宣称绑定 | *"先别给我问题。把四框架疑点表给我看，每条标出证据和可信度。"* |
| **一大半问题标成 `可能回避`** | 疑点集中在策略与未公开计划上，缺了机制层与事件层的问题；也可能是 §2.0 的改写没做干净 | *"把每条疑点改写成'问机制、问流程、问发生过的事'的形态，再重排一遍。"* |
| **报告里全是 `我推测的`，几乎没有 `公开可查`** | 公开检索做得不够；或这家公司确实几乎查不到；**或者你的 agent 根本没有联网能力却没说** | *"先说清楚是哪一种：你有检索能力吗？查过哪些渠道、分别查到了什么？没有检索能力就按 §1 的四条退化写明；确实查不到就把空白升级成必问项，别停在推测。"* |
| **疑点表里一堆 `我推测的`，但「证实路径」那一列后半截是空的** | 这条规则会随行数衰减 —— 前几行写得全，写到第五、六行只剩标注 | *"把每条 `我推测的` 右边那一格补齐：要证实它该问谁、查什么。补不出来的，说明它不该占一行，删掉。"* |
| ⭐ **只有四框架疑点表有「证实路径」列，框架 D 表 / 「我要不要去」表没有这一列** | ⛔ **表设计漏了，不是执行者偷懒** —— 那两张表里标的 `我推测的` **物理上没地方写证实路径**，而且不会留下任何空格子暴露这件事 | *"按 §8.1 那张位置表逐张点名：三张表都要有「证实路径」列。先给缺列的两张加列，再逐条补内容。"* |
| ⭐ **自查节写着"证实路径已修"，但只有一张表带这一列** | 只修了触发这条规则的那一张表，没有反问"还有哪几张表也会出现 `我推测的`" | *"把'已修'改成如实的说法：修的是哪一张、另外几张当时没修。然后按 §8.1 补齐。"* ⚠️ 诚实高于好看 —— 一份宣称已修的自查比没有自查更危险 |
| **一页纸上全是"公司成不成"的问题，没有一条在验证你自己的必要条件** | 收敛时把 Kill Switch 当成了唯一的不可砍区，§5 第 2 条被当成了"Kill Switch 优先" | *"把必要条件验证题单列一栏标 🔒 不可砍，然后重砍一次：从 🔪 和 🔒 之外砍起。"* |
| **红旗绿旗那一栏空着，或者只写了红旗** | 只想了"什么算坏"，没想"什么算好"——**这会让你在听到好答案时也认不出来** | *"每条关键问题补上绿旗：什么样的回答会让你觉得这家公司是靠谱的？具体到句子。"* |
| **清单里出现了现金储备、具体收入、股权结构这类问题** | ⛔ 红线被越过了——投资人指标混进来了 | *"对照 §2.0 逐条过一遍：这条我在面试里问得出口吗？对方答得了吗？答不了就删，能改写成行为化问题就改写。"* |
| **给出了一个 0-100 的公司评分** | 违反 [README 不做什么](README.md) | *"把分数删掉。改成：哪几条判断是有硬证据的，哪几条是推测的，各自的把握程度不同——别用一个数字抹平它。"* |

## 10. 三级自救阶梯（写给 agent）

⛔ **不许一出问题就让人接管。** 顺序是先自救两级，第三级才回报人。

| 级 | 什么时候到这一级 | 该做什么 | ⛔ 不该做什么 |
|---|---|---|---|
| **L1 有现成的，直接走** | 本文件里有明确规则命中（框架某一条、五法某一条、可答性判定） | 按规则执行，**不问** | 不为"确认一下"打断用户。已有规则能裁决的判断，自己裁决 |
| **L2 没现成的，自己走通 + ⭐ 沉淀** | 材料格式意外 / 这家公司不是 AI 应用类（框架 D 部分不适用）/ 某个框架在这个行业里问法要变 / 公开渠道查不到 / **这次根本没有联网检索能力** | 用语义理解自己走通：JD 乱贴 → 自己整理；框架 D 不适用 → 说明理由并跳过，**不硬套**；查不到 → 按 §3.3 升级为必问项；**没有检索能力 → 按 §1「不能联网时退化成什么」的四条走，照样交付**。⭐ **走通之后把学到的写回去**：新的改写方式写进 `assessments/<公司>.md` 的"本次新增判据"一节，下次直接回 L1 | ⛔ **不把"这次绕过去了"只留在会话里。** 没沉淀 = 下次还得再试一遍 = 等于没走通 |
| **L3 实在不行，才回报人** | L2 也走不通 / 触及 ⛔ 边界 / **只有用户本人才有的事实**（他的必要条件、他这次面试的真实目的、中间人具体说了什么） | 输出 **症状 + 已经试过什么 + 建议你做什么（给可选项）** | ⛔ 不输出裸错误 · ⛔ 不说"请提供更多信息"这种没有指向的话 · ⛔ 不把 L2 该自己解决的整理工作推给用户 |

**L3 的标准形态**：

> *症状*：决策分离那一节我填不完——"我要不要去"这一列是空的。
> *已经试过*：从 JD 反推了这个岗位大概能给到什么经验；从你贴的材料里找过你的关注点，没找到。
> *建议你做*：三选一 —— ① 写 2-3 条必要条件和排除条件给我（最快，两分钟）② 如果你有 `positioning.md`，贴给我 ③ 或者告诉我"这次先只看公司成不成"，我就把这一节标成"未评估"收尾。

## 11. 输出去哪

产出一份 `assessments/<公司>.md`，模板见 [`templates/assessments-模板.md`](templates/assessments-模板.md)。

### 11.1 最简字段定义（本模块自带，读到这里就够）

⭐ **不需要读任何其他文件。** 下面五个字段就是这份产出的全部必填项：

| 字段 | 取值 / 形态 | 缺了会怎样 |
|---|---|---|
| **匹配度** | `强` / `中` / `弱` —— 外加一句话说清**哪几条对上了、哪几条没对上** | 只剩一个模糊印象，下游没法用 |
| **级别** | `强匹配` / `较匹配` / `探路` / `不投`。⭐ 另起一行记 **上游定级 / 本次是否修正 / 修正理由**（上游定级来自 [`jd-triage`](../jd-triage/) 的定级结果文件；没接上游就写 `无上游 / 本次从零判级`） | 多个公司之间没法排序；且上游判过的级别与本次结论不一致时，没人知道是修正了还是重算漏了 |
| **四框架疑点表** | 一行一条疑点，每行**八列**（含首列编号）：疑点（哪里说不通）· 来自哪个框架 · 现有证据 · 来源标注（`你给的` / `公开可查` / `我推测的`，见 §8）· ⭐ **证实路径（要证实它该问谁 / 查什么）** · 若成立会影响什么 · 已转为哪条问题。**被多个框架同时指到的排最前**。⭐ 另有**框架 D 单独过一遍表**（结论 · 证据 · 来源标注 · **证实路径**，见 §2.4） | 问题清单失去出处，退化成一份和网上通用反问清单没区别的东西 |
| **分层问题清单** | 按提问对象分栏（技术负责人 / 创始人·高管 / HR·中间人，见 §4.1）。**每条必带可答性标注**（`大概率能答` / `可能回避` / `答不上来本身是信号`，见 §4.4；标第三档的必须同时写清问谁），并标出它验证的是**哪条疑点**。⭐ **🔪 Kill Switch 与 🔒 必要条件验证题要显式标出来**（两类并列不可砍，见 §5） | 会混进对方答不了的问题，白白烧掉本来就只有六到八个的提问预算；🔒 没标出来的，收敛时第一个被砍掉 |
| **红旗 / 绿旗成对判据** | 每条**判断类**问题**同时**写 🔴 危险回答与 🟢 好的回答，**具体到句子**，不是形容词 | 你会在面试现场被一个流畅自信的答案实时说服，回家路上才反应过来他没回答问题（见 §4.3 ②） |

> ⚠️ **这条只绑定判断类问题，不绑定流程类问题。**
> "面试一共几轮、分别见谁"这种是**流程题**——它挣的是自己的位置（帮你重排分身序、分配提问预算），但给它配红绿旗接近无意义。
> **判据**：这条问题的答案会不会改变你对这家公司的判断？
> - 会 → 判断题，**必须成对**
> - 不会，只改变你怎么安排这场面试 → 流程题，**标一句用途即可，不要为了凑格式硬编红绿旗**
>
> ⛔ 为流程题硬编红绿旗比空着更糟：它会让整张表里"红绿旗"这一列的含义被稀释，你在现场就不再认真看它了。

另外两条硬约束：

- ⛔ **不含 0-100 综合分** —— 一个数字会把"这几条判断的把握程度完全不同"这件事抹平
- ⛔ **每条结论都要带来源标注**（§8），`我推测的` 必须附一句"要证实它，你该问谁 / 查什么" —— 在**每一张**会出现 `我推测的` 的表里它都是**同一行的必填格**（疑点表 / 框架 D 表 / 「我要不要去」条件表，见 **§8.1**），⚠️ **那一格空着 = 这条标注等于没标；那一列不存在 = 这条规则在这张表里从未存在过**
- ⛔ **不要拿「B · 参数来源等级」（`默认建议值` 之类）当来源标注用** —— 它贴在阈值和参数上，不贴在结论上。两者混同的后果是：读者以为标过了，而这条结论其实一条来源标注都没有（见 §8 表下的说明）
