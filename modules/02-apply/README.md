# 02-apply · 判断闸门式自动投递与浏览器治理

> **v0.1.0** · 治理层方法论，**不是投递引擎**。零可执行代码——本模块和仓库其他部分一样是纯 markdown + 参数模板，不含任何真实平台的自动化实现。

---

## ⛔ 先读这一节，再读别的

**本模块交付的是"什么时候该停、什么时候可以继续、失败了算谁的"这套判断层**，不是一套能直接跑起来的浏览器自动化代码。

- **不专门指导/建议绕过任何技术防护措施**——本仓库不发规避平台校验的具体方法或配置。**这条管的是"仓库文档/代码要不要教这个"，不管"你自己用什么执行引擎"**：
  - 判断层（本模块）与执行引擎解耦，你用什么浏览器自动化技术栈是你自己的选择，包括市面上隐蔽性更强的方案（如 Patchright）——本仓库推荐的参考执行引擎 [`boss-agent-cli`](../../docs/ecosystem.md) 本身也用这类工具，这不是本仓库要禁止的东西
  - **唯一需要你自己知情的是风险**：这类工具存在导致账号被平台限制的真实可能，风险自负，本仓库不背书具体效果、不兜底后果
  - 反过来说，"仓库自己写一份具体的反检测配置/教程"仍然不做——那是"教怎么绕过"，跟"你自己选什么引擎"是两件事
- **不采集他人个人信息**（HR、其他候选人的姓名/联系方式/简历）
- **不做全站爬取**——采集范围必须被你实际会投递的量约束，不提供"抓一遍整站职位库"这类功能
- **不提供无上限的投递配置**——本模块给的默认值全部带护栏，且**四层量级上限必须一起给**（缺一层配置视为不合规，见下）
- **不在简历中夹带操纵筛选系统的隐蔽指令**（通过不可见内容干扰招聘方筛选系统）
- **对外定位使用“判断闸门式投递”**，不以免判断、无限覆盖或追求数量作卖点。受判断和授权约束的无人值守执行仍在模块范围内；通用技术语境的多轮任务不因此被禁止。

**底层执行引擎不要自己造。** 需要真实操作某个招聘平台网页时，直接用现成的、专门做这件事的开源实现（如 boss-agent-cli 这类 MCP 原生的浏览器操作工具，见 [`../../docs/ecosystem.md`](../../docs/ecosystem.md)）。本模块要做的是把**判断层**（该不该投、投多少、什么时候该停、出问题算谁的）套在那套执行引擎外面，而不是重新发明一遍浏览器自动化。

**核心主张：判断闸门控制投递质量，不保证平台安全。** 筛选、去重和事实化定制用于减少不合适的投递；上限与风险停止约束执行。不能从个人历史未遇风险推出平台允许或账号不会受限，也不把随机停留当安全证明。模块沿用 [岗位判断](../03-company-analysis/) 和 [录用取舍](../05-offer/) 的候选人判断纪律。

## I1 三问

### ① 单独用行不行？

**可以独立做目标网站探索与岗位整理。** 给出想做的工作、地域和必要条件，agent 就能从核心目标公司的官网和官方招聘入口开始；没有现成 adapter 或 JD，不应阻止只读发现。发送申请则必须先具备判断闸门、可用材料与对应授权。

### ② 依赖哪些模块的输出？

- `positioning.md` 或你口述的目标、必要条件、排除条件：限定发现范围，并作为后续投递判断依据。
- `jobs/<batch>.md`、`triage/`：可以已有，也可先由本轮发现整理，再用岗位定级模块或等价的明确规则定级。
- 简历版本和 `ledger.md`：发送阶段用于材料准备与去重；缺台账先本地建立，不假定从未投过。

### ③ 缺了上游会退化成什么？

| 缺的 | 退化成什么 |
|---|---|
| 目标画像 | 集中问工作方向、地域及不可接受条件；已有核心公司时可先核实公开入口，不猜个人偏好 |
| JD / 定级 / adapter | 主动只读探索，整理 JD 后定级；新网站先记可读性与核实结果，不宣称已适配发送 |
| 投递判断闸门 | 继续研究、补齐条件；**发送阶段 fail closed**，不得把发现结果直接变成投递队列 |
| 简历或打招呼素材 | 可拟建议草稿，事实和占位符未核实前不能发送 |
| `branches.md` | 按主线判断，不隐性放宽；新方向可研究但不自动开投递分支 |

| 文件 | 是什么 |

| [`SKILL.md`](SKILL.md) | 交给 agent 的判断闸门式投递闭环剧本：定时触发 → 锁检查 → 渠道执行 → 门槛过滤 → 去重 → 定制 → 发送 → 登记 → 解锁 → 生成 review 卡 |

| [`templates/目标网站探索卡.md`](templates/目标网站探索卡.md) | 只读探索范围、入口、职位证据、局部适配与交接 |

- [`../../adapters/`](../../adapters/)——平台相关的东西（URL 拼法、按钮判定、字段定位）一律下沉到这里，声明式 JSON recipe，不是可执行代码，本模块只读取它，不定义它的具体内容
- [`../../docs/module-contracts.md`](../../docs/module-contracts.md)——`jobs/<batch>.md` 与 `runs/<date>-review.md` 两份跨模块契约在那里定义最小字段；`apply-lock.json` / `pacing.json` 是运行时状态与配置，不是跨模块契约，不出现在那份文档里

## 不做什么

- **不提供任何真实平台的适配代码**——`adapters/` 下只有一份完全虚构的格式示例，不对应任何真实网站
- **不给出一套可以直接照抄跑的具体阈值**——`pacing.json` 里每个数字都标了来源等级，且大多数是 `纯占位待校准` 或 `默认建议值`，抄来直接用意味着你在用别人单一实践校准出来的节奏，跑在你自己的账号上
- **不做全站爬取**，采集范围由你实际会处理的投递量约束
- **不提供"确认过一次就一直信任"的机制**——发送前文本比对、每日 review、熔断解除都要求显式的、当次的确认
- **不替你点最终确认动作**（如果你的实现里有需要人工点击的环节，本模块的立场是那个点不该被自动化跳过）
