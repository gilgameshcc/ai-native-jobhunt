# 委托代理平台判断卡 · <平台或产品名> · <日期>

> **什么时候用**：你打算把简历、求职意向或整个求职过程交给一个第三方 AI 求职代理、撮合平台或"帮你找工作的 Agent"之前。**先过这张卡，再点授权。**
> **它不做什么**：不评价任何具体平台好不好，不替你决定用不用。它只把你在授权之前该知道的七件事列出来，答不出的标「查不到」，按保守处理。
> **来源标注**：每一格只能是 `公开可查`（对方的服务条款 / 隐私政策 / 帮助文档，附链接）· `问平台`（你或 agent 直接问过，记原话）· `查不到`。⛔ 不许写 `我推测的` 当答案。

---

## 七问

| # | 问题 | 看哪里 / 问谁 | 你的答案（附来源） | 查不到时按什么处理 |
|---|---|---|---|---|
| 1 | **谁付钱？** 我免费用，钱是谁出的，按什么结算（录用成功费 / 订阅 / 广告） | 定价页、服务条款 | | 假定激励在付钱那一方；我的材料会被用来服务它 |
| 2 | **谁能看到我的底线？** 我告诉它的薪资底线、离职原因、不可妥协条件，会不会进入匹配、会不会被雇主一方看到 | 隐私政策、帮助文档"雇主能看到什么" | | 只给它「披露边界」里允许对外的内容；底线不进平台 |
| 3 | **候选人从哪来？** 它的人才库是用户自己加入并授权的，还是从公开档案抓来的；我的公开档案会不会被它拿去 | 帮助文档"人才来源"、隐私政策"数据来源" | | 假定我的公开信息可能已在里面；开档案前先决定公开范围 |
| 4 | **匹配分是什么？** 它给的"匹配度"有没有校准方法和录用结果标签；没有的话它只是排序工具 | 产品文档、技术博客 | | 只当排序看，⛔ 不当成"录用概率" |
| 5 | **介绍之后谁联系谁？** 联系方式在什么时候、经谁同意后交换；是它替我发消息，还是把我的联系方式给对方 | 帮助文档"介绍流程" | | 假定对方会直接联系我；不给它代发权限 |
| 6 | **能不能撤回和删除？** 关掉可见性之后已经发出的材料怎么处理；已被雇主下载的收不收得回；删除账号后派生数据（摘要、向量、日志）还在不在 | 隐私政策"删除"、账号设置 | | 假定发出去的收不回来；只给能接受收不回的版本 |
| 7 | **被排除时能不能知道原因？** 它替我筛掉一个岗位、或替雇主筛掉我，我能不能看到依据 | 帮助文档、问客服 | | 假定看不到；自己另做一遍定级，不把它的沉默当"不合适" |

## 授权前的三行

- **我授权它做什么**：<例：只看我的公开摘要 / 可以替我提交申请 / 可以替我回复消息（逐项写，没写的默认不给）>
- **我不给的**：<例：底线数字、当前薪资、其他 offer 的信息、代发消息权限>
- **什么情况我会关掉**：<例：连续两次推荐明显不满足必要条件 / 联系方式未经我同意被交换 / 撤回后仍收到基于旧材料的邀约>

---

## 一句写死的话

**平台推荐 ≠ 介绍 ≠ 面试 ≠ 录用。** 台账里这四层分开记（状态栏写清是哪一层），不把"被推荐了很多"当成"有机会"。它推荐的每条岗位，仍然要过你自己的定级（[`jd-triage`](../../03-company-analysis/jd-triage/)），必要条件与硬性排除条件不因为是平台推的就放宽。

---

## 用法

1. 复制到工作区 `runs/` 或任意你顺手的位置，一个平台一份
2. 让 agent 先按「看哪里」去查公开文档，查到的附链接；查不到的**不要猜**，标「查不到」并按最后一列处理
3. 七问都有答案或标注之后，你自己填「授权前的三行」。⛔ 这三行 agent 不代填
4. 三行填完、本次动作落在「我授权它做什么」范围内，agent 可以替你执行（上传按披露边界过滤后的材料、打开你写明的那几项开关）；平台侧若弹出要本人确认的最终动作，不代点，与本模块 README「不做什么」一致
5. 之后每次它推荐岗位，走正常的定级与投递流程；它不是判断闸门的替代品
