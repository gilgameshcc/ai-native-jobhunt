# adapters · 平台适配层契约

> **这里没有任何真实平台的实现。** 本目录只定义**格式**——平台相关的东西（URL 拼法、按钮判定、字段定位）应该长成什么样才能被 [`../modules/02-apply/`](../modules/02-apply/) 安全地使用。[`示例-虚构平台/`](示例-虚构平台/) 是唯一的示例，对应一个完全虚构的招聘平台，不指向任何真实网站。

---

## 为什么是声明式 JSON，不是可执行代码

1. **产出可 diff、可回滚、可人工审查**——探索器（agent 在 L2 自救阶梯里发现的新语义线索）产出的是数据，不是脚本，改动一目了然
2. **动作白名单能在运行时强制**——声明一个元素定位符不等于授权对它执行写动作，这条边界只有在"配置是数据、执行是代码"的架构下才能被真正 enforce
3. **公开的是一组语义模式，不是一份精确指纹**——recipe 失效时靠探索器自愈（见 `02-apply/SKILL.md` 三级自救阶梯 L2），而不是给平台侧送一张可以直接拿去做反制规则的特征表

---

## Recipe 格式

```json
{
  "platform": "平台的内部标识名，不含真实域名或品牌名细节",
  "version": "该 recipe 的版本号",
  "上次验证时间": "YYYY-MM-DD",
  "候选链": {
    "<语义动作名>": {
      "候选定位符": ["按优先级排列的多个定位方式，任一命中即可"],
      "断言": "命中后如何确认这确实是预期的元素/页面状态，不是碰巧匹配到别的东西",
      "允许的动作": ["read"] 
    }
  },
  "去重键": "平台特有的、用来判断'这条是否已经联系过'的信号是什么",
  "已知失效记录": [
    { "日期": "YYYY-MM-DD", "现象": "...", "处理方式": "..." }
  ]
}
```

## ⛔ 动作白名单：声明定位符 ≠ 授权动作

**每个候选链条目的 `允许的动作` 字段必须显式列出，且默认只有 `read`。** 任何写动作（`click` / `submit` / `type`）必须由 `02-apply/SKILL.md` 在对应步骤显式声明它在使用哪个语义动作、且已经过 L1/L2 定位可靠性判断，不能因为 recipe 里存在这个候选定位符就默认它可以被点。

**这是防止"探索器发现了一个元素能被点到，就顺手点了"这类隐性授权扩张的唯一机制**——recipe 描述"这里有什么"，不等于"可以对它做什么"，两者必须分开声明。

## 沉淀纪律

L2 自救阶梯里，agent 用语义候选链/结构探查/a11y 模式走通了一次原本 recipe 没覆盖的场景后，**必须把新发现的候选定位符写回对应平台的 recipe 文件**，下次直接回到 L1。不沉淀 = 下次还得再走一遍 L2 = 等于没走通。

## 社区维护声明

`adapters/<platform>/` 下的内容**可能随时失效**——平台页面结构变化是静默的，不会有报错提示，只会开始返回空结果或断言失败。这一层依赖社区持续维护；单个 recipe 的可信度以「上次验证时间」和「已知失效记录」为准，不是永久有效的。
