# AI Native 求职全案

**一套写给 agent 读的求职方法论。不是投递脚本，是每个决策点上的判断纪律。**

> 你需要的唯一东西：**一个能读写本地文件的 agent**（Claude Code / Codex / Cursor 之类）。
> 不需要会写代码、不需要装任何东西、不需要先读完整套方法论、不需要用某个特定的 agent 产品。

> ⚠️ 本仓库里的 **offer 指「录用通知」**（公司发给你的那份），不是招聘启事——有些语境里 "job offer" 指后者。

## 你现在卡在哪一步？

**不用先理解模块划分，对号入座就行。**

| 你会说的那句话 | 用哪一块 | 跑完你会拿到什么 |
|---|---|---|
| **"我什么都还没准备好，也不知道该从哪开始"** | [`modules/00-workspace/`](modules/00-workspace/) | 一个 agent 能直接干活的工作区骨架——**不需要先想清楚方向**，骨架会带着你把想法慢慢填进去 |
| "我用过一次了，但 agent 每次都要我重讲一遍我是谁" | [`modules/00-workspace/`](modules/00-workspace/) | 同上——这是它真正要解决的问题：**建一次，之后不用每次重讲** |
| "我要 AI 帮我改简历，但绝不能让它编造或美化我的经历" | [`modules/01-resume/`](modules/01-resume/) | 从事实池摘录（只删不改）的定制版简历 + 单页 PDF（或 no-code 校验记录）——**改动只允许四处：顺序 / 术语替词 / 排序 / 可选项增删** |
| "投之前我想先知道这个岗位值不值得投" | [`modules/03-company-analysis/jd-triage/`](modules/03-company-analysis/jd-triage/) | 结构化的岗位表 + 四级定级，**理由能追到你自己写的哪一条条件** |
| "我想让投递能定时无人值守地跑，但它必须仍然在做判断，不能退化成海投" | [`modules/02-apply/`](modules/02-apply/) | 一条判断闸门式投递闭环——**缺判断条件就直接拒绝运行**（不是降级瞎跑，叫 *fail closed*），节奏引擎 + 熔断（命中风控信号后自动停手，直到你手动解除）+ 每日 review 卡 |
| "明天要面试，这家公司到底靠不靠谱、我该问什么" | [`modules/03-company-analysis/interview-strategic-assessment/`](modules/03-company-analysis/interview-strategic-assessment/) | 四框架疑点表 + **一页纸问题清单（每条带可答性标注）** + 红旗绿旗判据 |
| "手上有两个 offer（还有留在原地），到底去哪个" | [`modules/05-offer/`](modules/05-offer/) | 横向对照表 + **排序 + 翻转点**（哪个假设变了排序会翻），**不给你一个假装精确的综合分** |
| ⭐ "我没在找工作，可现在这份越待越不对劲——到底还要不要待下去" | [`modules/05-offer/`](modules/05-offer/) | 一次单列体检：**你现在这份工作过不过得了你自己写下的线** + **什么变了你就该开始看外面**（不出名次，出的是一条过 / 不过的结论） |
| "只有一个 offer（或只有这一个机会），不知道该不该接" | [`modules/05-offer/`](modules/05-offer/) | **接 / 不接 / 先补一条信息再定** —— 只剩一列时问的不是"哪个更好"，是"**它过不过得了你自己写下的线**" |
| "刚面完，感觉答得不好但说不清哪不好" | [`modules/04-interview/`](modules/04-interview/) | 当天复盘卡：被问了什么 / 哪里答不好 / 红旗绿旗**三态**回填 / 跑题聊嗨的那部分也留下来 |
| "投了一批没什么回音，是不是该换个方向" | [`modules/06-positioning/`](modules/06-positioning/) | 一份周期报告：**归因到表述 / 阈值 / 方向哪一层**，样本不够时明确告诉你"本轮不改"；外加一条带证伪判据的探路分支 |

> **要不要先跑 `00-workspace`？** 逻辑上它是唯一的上游——其他模块读写的文件（`positioning.md` / `facts.md` / `ledger.md` …）都是它建出来的。但**没有任何模块会强制你先跑完它**：你可以直接把一份 JD 粘给定级模块、把刚面完的事说给复盘模块，缺什么它会告诉你怎么降级。一句话：**第一次用可以跳过；用到第二次、第三次，你会自己回来建工作区**。

**最快见效的一个**：手上正好有两个 offer 的人，可以**直接用** [`modules/05-offer/`](modules/05-offer/)，不需要接受这里的任何其他东西。不想让 agent 替你算、只想自己想清楚？看 [`modules/05-offer/透镜库.md`](modules/05-offer/透镜库.md)——八个角度，每个在纸上十分钟做完，不出结论也不排序，单独拿走一张也成立。

## 快速开始（60 秒）

1. 挑上面路由表里最贴近你现在处境的那一行
2. 打开那一行链接指向的目录，入口就是里面的 `SKILL.md`
   > ⚠️ 路由表里指的是**具体模块目录**。`modules/03-company-analysis/` 这一层没有 `SKILL.md`——它下面是**两个各自独立的子模块**（`jd-triage/` 投之前用、`interview-strategic-assessment/` 面试之前用），要打开的是子模块目录。
3. **把整个文件贴给你的 agent**，然后说你手上有什么

就这样。每个 `SKILL.md` 顶部都有一节「开跑前」，会告诉你**它要什么、你缺了会退化成什么、以及最少给到什么程度就能开始**。

> **缺东西不是错误。** 这里没有一个模块会因为你少给了一份文件就停下来报错——它会告诉你缺什么、能不能降级跑、降级之后哪一部分结论会变弱。

## 这个仓库和已有的求职开源项目有什么不一样

这条赛道已经有几个数万 star 的全链路项目（career-ops、ai-job-search、Resume-Matcher）。**它们把流程跑起来这件事已经做得很好，不要重新发明。**

这个仓库补的是**判断层**：

| | 已有全链路项目 | 这里 |
|---|---|---|
| 简历 | 给 LLM 素材，按规则生成 | 事实池是唯一真相，**定制只能删不能改** |
| 岗位 | 匹配度打分 | 匹配度 **+ 硬性排除条件不可被匹配度换** |
| 面试 | 帮你准备怎么答 | **先判断这家公司站不站得住**，问题是评估的副产品 |
| offer | 条款整理 / 加权总分 | **排序 + 翻转点**，不出综合分 |
| 投递 | 生成材料辅助人工提交，或全自动无判断执行（后者已有账号被封的真实先例） | **判断闸门式投递**——缺判断条件就拒绝运行；命中风控信号后自动停手（不是靠人盯着），直到你手动解除 |
| 输出 | 一个分数 | 一个**能追到具体条件**的结论，以及它建立在哪些假设上 |

逐项对照与调研出处：[`docs/ecosystem.md`](docs/ecosystem.md)

## 如果你打算跑不止一个模块：先后关系

> **多数情况下用不上这一节——各模块可以独立跑，顺序随你，看完上面「快速开始」就够了。** 只有当你确定要连着跑两个以上模块时，下面这张表才用得上；否则直接跳到「可移植性」一节。

每个模块 README 开头那三问（单独用行不行 / 依赖谁 / 缺了退化成什么）是设计约束，不是客套：任何模块在上游文件不存在时都必须能继续跑，退化成"需要你手工补这几项"，不是报错退出。**所以下面这张表不是流程图**，它只在"这两个我都打算跑"的时候才成立。

| 如果这两个你都想跑 | 建议的顺序 | 为什么是这个顺序 |
|---|---|---|
| 手上有 offer，**但同时在怀疑整个方向对不对** | **先 [`06-positioning`](modules/06-positioning/)，再 [`05-offer`](modules/05-offer/)** | offer 模块做的是**在一组给定的候选里排序**——它默认"这个方向本身没问题，问题只是选哪个"。方向如果不成立，你会在一个可能根本不该走的方向里，认认真真选出一个最优解；而排得越仔细、理由写得越足，越难回头 |
| 面试前评估（[`03-.../interview-strategic-assessment`](modules/03-company-analysis/interview-strategic-assessment/)）+ 当天复盘（[`04-interview`](modules/04-interview/)） | **评估必须在面试前跑** | 这两个是同一条链的两端：复盘要回填的三态，对象是**面试前**成对写下的红旗绿旗。面试完再补，一律降级成 `事后补的基准，可信度低`，**不喂给下游做判据校准**（见 [`04-interview/SKILL.md` §4.4](modules/04-interview/SKILL.md)）。这一条不是偏好，是**时间上不可逆** |
| 岗位定级（[`jd-triage`](modules/03-company-analysis/jd-triage/)）+ 面试前评估 | **先定级** | 评估里的疑点会直接引用定级时写下的条件编号。反过来跑也跑得通，代价是**要重新发明一次编号**，之后两份文件对不上 |
| 简历定制（[`01-resume`](modules/01-resume/)）+ 判断闸门式投递（[`02-apply`](modules/02-apply/)） | **先出简历再投递** | `02-apply` 步骤 4「定制打招呼语」优先用 `01-resume` 的素材生成具体观察句；没有的话退化成通用模板，明说"文本同质化风险"。不阻断，但顺序反了效果打折 |
| 岗位定级（[`jd-triage`](modules/03-company-analysis/jd-triage/)）+ 判断闸门式投递（[`02-apply`](modules/02-apply/)） | **先定级** | `02-apply` 的硬门槛过滤读的是定级结果；没有定级结果，判断闸门缺一环，按第一条规则拒绝运行，不会退化成无判断投递 |

> 还有一条已经在上面说过了：[`00-workspace`](modules/00-workspace/) 在逻辑上是所有模块的上游，**但第一次用可以跳过**。

## 可移植性：换个 agent 还能不能用

**能。** 这里全部是 markdown，没有一行可执行代码，也不依赖任何 agent 产品的专有机制：

- ❌ 不需要注册斜杠命令
- ❌ 不需要自动加载 / 特定目录约定
- ❌ 不需要装 runtime、依赖或 CLI
- ❌ 不需要 git

`SKILL.md` 只是**一个文件名约定**，不是某一家的格式。把文件整份交给你的 agent 即可。
工作区里给 agent 看的那份约束文件，模板叫 `AGENTS.md`；**如果你的 agent 读的是别的名字，改个名就行**，内容不用动。

## 每个 `SKILL.md` 都长同一个形状

这不是排版偏好，是**发布门禁**——缺任一段不许发：

| 段 | 它保证的事 |
|---|---|
| **开跑前** | 你知道要准备什么，以及**最少给到什么程度就能开始** |
| **来源标注** | 每条结论标 `你给的` / `公开可查` / `我推测的`；**推测项必须附"要证实它，你该问谁 / 查什么"** |
| **不对劲的时候** | 跑歪了在对话里就能排查：`症状 → 最可能原因 → 你下一句该说什么` |
| **三级自救阶梯** | agent 卡住时先自己找路（并把学到的沉淀回文件），**实在不行才回来问你，且必须带上"我已经试过什么、建议你做什么"** |

> ⛔ 这四段是 markdown，**不是某个 `doctor` 命令**。排查的执行者是你手上的 agent，仓库只负责给它判据。

## 不做什么

写在这里是为了防止以后被"用户有需求"撑爆边界。

**技术与合规边界（⛔ 没有讨论余地）**

- ⛔ **不专门指导/建议绕过平台的技术防护措施**（不发验证码破解方法、指纹伪装配置、代理池搭建方案、设备伪造教程）——但这管的是"仓库建议什么"，不管"你自己用什么执行引擎"；见 [`modules/02-apply/README.md`](modules/02-apply/README.md) 的完整说明
- ⛔ **不教在简历里植入影响 AI 初筛的内容** —— 那是操纵，不是判断力
- ⛔ **不采集他人个人信息**（HR、其他候选人），**不做全站数据抓取**
- ⛔ **不提供无上限的投递配置** —— 无差别大量投递不是这套方法论要解决的问题，恰恰是它要避免的失败模式

**产品边界**

- **不做执行层** —— 底层投递引擎建议直接用现成的开源实现，见 [`docs/ecosystem.md`](docs/ecosystem.md)
- **不预测面试题，不给标准答案话术**
- **不给 offer 打综合分**，不替你设定权重
- **不告诉你该不该转行** —— 只把可能性摆上台面，并给出证伪它的方式
- **受益人始终是候选人。** 这里不做"帮公司筛人"的任何东西

## 已知局限（不是免责套话）

1. **样本 n=1。** 这套方法论来自**一次真实求职实践**，尚未在多人身上验证
2. **所有阈值都是编的。** 文中每个数字都标了来源等级（`实践校准` / `默认建议值` / `纯占位待校准`）——**不要照抄，按你自己的情况重新标定**
3. **有几件事没有人测过**，我们直接写出来而不是给一个听起来确定的答案。清单见 [`docs/workspace-architecture.md`](docs/workspace-architecture.md) 的局限一节
4. **自测覆盖了全部八个模块，50 对「该触发 / 不该触发」样本，其中 4 对首跑就失败过**（均已改判据后通过）——这不是加分项，只说明还没被更刁钻的样本推翻过。测的是规则的区分力，测不了阈值的标定值。明细见 [`fixtures/README.md`](fixtures/README.md)
5. **offer 模块的必要条件门槛，挡不住一个铁了心的人**——你说"这条底线是我现在才想的"，它不会直接放行，而是把含它 / 不含它两套排序都跑一遍，然后明说"你的结论取决于一条你事后才想起来的条件"；但它不会替你裁决，你说"这条不算"，它就得接受。**这道门槛的作用是让你看见自己在做什么，不是拦住你。**

**欢迎提 issue 讲你的反例。** 这个仓库最缺的就是第二个人的数据。
